## 1. 인수인계 목적

이 문서는 다른 검토 창에서 현재 코드 변경과 시험 결과를 처음부터 다시 추적할 수 있도록 작성했다.
검토자는 다음 세 가지를 우선 확인한다.

1. schema 2.0 입력·출력 계약과 위험도 계산이 의도한 의미를 유지하는가.
2. open 고속화가 결과를 바꾸지 않으면서 실제로 TAT를 줄였는가.
3. 저장된 합성 시험 결과의 범위와 실제 제품 적용 전에 남은 작업이 정확히 구분됐는가.

현재 PDF와 HTML은 최종 첨삭 전 버전이다. 원고와 생성 코드만 갱신했으며
`docs/report/report.html`과 PDF는 재생성하지 않았다.

## 2. 사용자와 합의한 계산 의미

- 기존 현장 sim도 전극 높이를 반영한 2.5D 계산이다.
- 이번 개선의 핵심은 기존 계산 대상이 아니던 전극 조합과 xy 거리·높이 차를 결합한 대각 CA다.
- 보고서에서는 `lateral short`, `vertical short`, `open`, `hotspot` 용어를 그대로 사용한다.
- hotspot은 이물 중심 후보 위치다. 산포 계산에서는 각 위치가 hotspot이 된 조건의 비율을 저장한다.
- open은 배선 사이의 접촉이 아니라 이물이 한 배선을 가려 두 단자 영역의 연결을 끊는 조건이다.
- `contact_margin_um`은 현재 0이다. 전도성·비전도성 이물에 따른 전기 접촉 거리 차이는 후속 항목이다.
- 현재 이물은 원형/구형이다. 타원형·길쭉한 형상·불규칙 형상과 방향각 분포는 후속 항목이다.
- 한 layer에는 여러 전극이 있고 다른 layer 전극과 복잡하게 겹칠 수 있다. 전극별 독립 mask를 사용한다.
- 전극 mask 합집합은 layer mask의 부분집합일 수 있다. 남는 영역은 TR 또는 기타 미평가 영역으로 기록한다.
- TR의 신호 분리 기능과 TR 손상은 현재 불량 계산에 포함하지 않는다.
- `union:any`는 layer 전극 mask의 합집합이 아니다. 같은 이물 유입 공정·크기에서 선언된 모든
  lateral short, vertical short, open hotspot을 OR한 결과다.
- 첫 판단은 동일 이물 조건에서 구조의 상대 비교다. 실제 Fab 이물 분포는 크기별 시뮬레이션 후 적용한다.
- Fab 자료는 layer별·이물 크기별 평균 이물 개수와 검사면적이다.
- 실제 첫 산포 적용에는 mask별 실측 overlay x/y와 CD를 사용한다. 이 값들은 서로 독립으로 취급한다.
- 근거가 없는 두께·이물 크기·중심 이동 산포는 첫 적용에서 0으로 고정한다.
- 기존 sim 결과가 없는 대각 전극 조합은 0이 아니라 `N/A` 또는 `new_pair`로 비교한다.

## 3. 구현한 주요 변경

### 3.1 입력과 schema

- schema 2.0을 추가하고 전극 mask가 layer mask의 부분집합인 입력을 허용했다.
- 동일 layer 전극 간 중첩과 layer 밖 전극 픽셀은 오류로 유지했다.
- layer에서 전극에 할당되지 않은 픽셀 수·면적·비율을 기록한다.
- 전극 조합의 선언·제외·미결정 상태를 전수 검사한다.
- open 입력은 두 점 좌표 외에 두 단자 영역 mask를 지원한다.
- open 경로마다 적용 가능한 이물 유입 공정을 지정한다.
- 산포 YAML은 mask layer별 overlay x/y와 CD 항목 및 근거 메타데이터를 지원한다.
- Fab 입력은 평균 이물 개수와 sample당 검사면적을 사용한다.

주요 파일:

- `src/particle_sim/schema.py`
- `src/particle_sim/config.py`
- `src/particle_sim/io/masks.py`
- `src/particle_sim/io/fab.py`
- `configs/scenarios/fab-overlay-cd.example.yaml`
- `configs/fab-mean-particles.example.csv`

### 3.2 계산과 위험도 출력

- 명목 CA와 산포 평균·분위 CA를 다른 열로 분리했다.
- 전극 조합별 raw CA, 중복 위치를 `1/k`로 나눈 배분 CA, 해당 조합만 만드는 고유 CA를 저장한다.
- layer별 union, 전극 조합별, open 경로별, 개별 전극별, layer×전극별 Fab 가중 위험도를 생성한다.
- short의 배분 기여도는 두 전극에 절반씩 나누고, open은 대상 전극에 전부 배분한다.
- 결과에 실제 전극 ID, 전극 layer, net, failure mode와 입력·출력 hash를 남긴다.
- 대형 산포 실행에서는 변형 mask를 모두 bool 배열로 보관하지 않고 임계 크기 이상에서 packbits 임시
  파일로 순차 재사용한다.

주요 파일:

- `src/particle_sim/aggregation/risk_allocation.py`
- `src/particle_sim/aggregation/risk_tables.py`
- `src/particle_sim/aggregation/fab_weighting.py`
- `src/particle_sim/io/outputs.py`
- `src/particle_sim/pipeline.py`
- `src/particle_sim/uncertainty/sampler.py`

### 3.3 기존 sim 비교 엔진

- 외부 기존 sim 결과를 공통 축으로 읽고 hotspot XOR, 교집합, 합집합, CA 차이를 계산하는 비교 엔진을
  추가했다.
- 좌표축·단위·shape·공통 전극 조합을 검증한다.
- 기존 계산 대상이 아닌 신규 대각 전극 조합은 비교 실패가 아니라 별도 분류한다.
- 예제 계약은 `configs/legacy-sim-reference.example.yaml`에 있다.

주요 파일:

- `src/particle_sim/comparison/`
- `tests/unit/test_legacy_sim_compare.py`

실제 기존 sim 산출물이 저장소에 없으므로 엔진의 합성 round-trip만 검증했다. 현장 sim 대체 판정은
아직 완료되지 않았다.

### 3.4 open 정확성 및 성능 보완

open은 다음 두 단계로 최적화했다.

1. 같은 명목 형상·단자·이물 크기·접촉 여유에서 계산한 binary open 결과를 적용 공정 사이에서 재사용한다.
2. 이물 중심과 footprint는 전체 좌표계를 유지하고, 손상 후 연결 성분 판정만 대상 전극의 최소
   bounding box에서 수행한다.

cache는 명목 실행에만 적용한다. 산포 조건 전체를 메모리에 누적하는 무제한 open cache는 사용하지
않는다. 산포용 bounded 또는 disk cache는 후속 검토 항목이다.

주요 파일:

- `src/particle_sim/failure/open_failure.py`
- `src/particle_sim/units.py`
- `src/particle_sim/pipeline.py`
- `tests/unit/test_open_failure.py`

## 4. 코드 검토 시 특히 볼 항목

1. `OpenResultCache`의 전제는 한 cache를 공유하는 동안 manifest와 masks가 동일하다는 것이다.
   현재 명목 실행과 probability 실행의 명목 기준 계산에서만 공유한다.
2. 산포별 변형 mask에서는 open 결과를 서로 재사용하지 않는다.
3. bounding box 밖 전극 픽셀은 존재하지 않으므로 연결성 결과에 영향을 주지 않아야 한다.
   후보 위치와 결과 배열의 좌표는 계속 전역 좌표다.
4. 단자 영역 일부가 이물에 가려져도 살아남은 단자 픽셀끼리 같은 연결 성분이면 open이 아니다.
5. 한 위치에서 여러 failure unit이 겹치면 배분 CA 합이 `union:any` CA와 일치해야 한다.
6. Fab 위험도에서 raw 조합 합은 중복을 포함할 수 있다. 구조 전체 위험은 union 기반 값을 사용한다.
7. `pair_margin_um`은 float32 전체 ROI 지도여서 큰 입력의 저장 공간을 지배한다.
8. 신규 파일은 `git diff`만으로 보이지 않으므로 `git status --short`와 함께 검토해야 한다.

## 5. 합성 파일럿 시험 구성

`complex_multilayer` 합성 형상은 200×200 px, 0.5 µm/px이며 다음을 포함한다.

- mask1 전극 3개, mask2 전극 4개, mask3 전극 3개
- lateral short 전극 조합 6개
- vertical short 전극 조합 10개
- G1, D1, D2의 굴곡·분기 open 경로 3개
- 이물 유입 공정 3개
- 이물 직경 2, 4, 6, 8, 10 µm
- L/T 형상, 좁은 간격, 분리된 섬, 정렬·부분 중첩·대각 교차

측정은 동일 장비에서 각 조건을 한 번 워밍업한 뒤 실행 순서를 회전하며 5회 수행했다. TAT는 wall
time 중앙값, 메모리는 5회 중 최대 RSS다.

재실행 도구:

```sh
uv run python docs/report/benchmark_failure_modes.py \
  --work-root docs/report/work/failure-mode-pilot-200 \
  --output-json docs/report/evidence/benchmark-failure-modes-200-after-open-crop.json \
  --output-csv docs/report/evidence/benchmark-failure-modes-200-after-open-crop.csv \
  --repeats 5 --canvas-size 200
```

`--reset`은 해당 전용 work-root를 지우고 다시 생성한다. 보존 결과를 덮어쓸 수 있으므로 검토 목적이면
새 work-root와 새 evidence 파일명을 사용하는 편이 안전하다.

## 8. padded 1000×1000 확장성 시험

200×200 복합 형상 자체는 바꾸지 않고 1000×1000 canvas 중앙에 배치했다. 전극과 단자 좌표를 함께
이동했으므로 절대 CA와 union CA는 200×200 결과와 같다. 이 시험은 큰 빈 ROI와 결과 배열 저장
비용을 확인하는 시험이며 긴 배선 또는 실제 제품 layout의 대표 시험이 아니다.

| 실행 | TAT 중앙값 | 200² 대비 | 최대 RSS | 출력 | 단독 TAT 합 비율 |
|---|---:|---:|---:|---:|---:|
| lateral short | 5.678초 | 3.92배 | 534.1 MB | 243.7 MB | 30.09% |
| vertical short | 8.522초 | 4.84배 | 650.3 MB | 377.8 MB | 45.16% |
| open | 4.669초 | 1.49배 | 333.4 MB | 0.07 MB | 24.74% |
| 통합 | 16.385초 | 3.70배 | 843.6 MB | 621.4 MB | — |

open은 전극 bounding box 안에서 연결성을 계산하므로 ROI 빈 공간 증가의 영향이 제한됐다. 통합 출력
621.4MB 중 `pair_margin_um` 디렉터리가 621.3MB, 즉 약 592.5MiB를 차지했다.

Zarr 공간 chunk를 512에서 1024로 키운 단일 탐색 실행은 출력이 502.1MB로 줄었지만 통합 TAT가
17.673초로 늘고 최대 RSS가 920.0MB로 증가했다. 이 변경은 기각했고 현재 코드는 512 chunk를 유지한다.

- `docs/report/evidence/benchmark-failure-modes-padded-1000.csv`
- `docs/report/evidence/padded-1000-analysis.json`

생성 산출물보다 위 Markdown 원고와 `build_report.py`를 기준으로 본다.

## 11. 작업 트리와 대용량 산출물 주의

- 현재 변경은 커밋하지 않았다.
- 수정 파일과 신규 파일이 함께 존재한다. `git diff`는 untracked 파일을 보여주지 않는다.
- `docs/report/` 전체가 현재 Git 관점에서 신규 디렉터리로 표시될 수 있다.
- `docs/report/work/failure-mode-pilot-padded-1000/combined-result`에는 약 621MB의 결과가 있다.

- `docs/report/work/pdf-tools`는 PDF 생성 도구 환경이며 제품 코드 검토 대상이 아니다.
- 기존 파일을 정리하거나 커밋하기 전에 `git status --short`로 범위를 확인한다.

## 12. 남은 작업과 권장 순서

1. 기존 현장 `sim`의 대표 입력·출력과 실행 조건을 확보한다.
2. 동일 mask, 픽셀 크기, 이물 크기, 이물 유입 공정, 공통 전극 조합으로 `compare-sim`을 실행한다.
3. 공통 조합의 hotspot XOR와 CA 차이를 모두 분류한다. 신규 대각 조합은 `N/A/new_pair`로 분리한다.
4. 미분류 차이가 없고 TAT/RSS가 허용 범위일 때 기존 sim 대체 후보로 판정한다.
5. 실제 제품형 1000×1000 이상 mask에서 긴 배선과 큰 전극 bounding box를 포함한 TAT를 측정한다.
6. mask별 실측 overlay x/y와 CD를 적용해 Sobol 64→128→256조건의 CA 수렴과 TAT를 확인한다.
7. 크기별 시뮬레이션 완료 후 Fab 평균 이물 개수와 검사면적을 적용한다.
8. 결과 계약이 확정된 뒤 `particle-sim-compare`와 연결한다.
9. 전체 첨삭이 끝나면 HTML/PDF를 한 번 재생성하고 페이지 넘침과 11·12페이지 표를 확인한다.

## 13. 현재 별도 판단이 필요한 항목

- TR의 신호 분리 기능과 TR 자체 손상을 이물 해석에 포함할지
- 전도성·비전도성 이물별 short/open 판정과 접촉 거리
- 비원형 이물 형상과 방향각 분포
- `pair_margin_um`을 항상 저장할지, 선택 출력으로 만들지, 정밀도나 압축 방식을 바꿀지
- 산포 open 계산에 bounded cache 또는 disk cache를 사용할지
- Fab 이물 크기 분포에서 크기 간 상관이나 경험분포를 어떤 방식으로 적용할지

이 항목들은 현재 합성 결과의 의미를 바꿀 수 있으므로 구현 전에 물리·출력 계약을 먼저 확정한다.
