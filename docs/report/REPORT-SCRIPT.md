# particle-sim 보고서 설명 스크립트

이 문서는 `docs/report/report.html`과 `docs/report/particle-sim-report.pdf`의 **25쪽 판(2026-09-20 생성)** 을
말로 설명하기 위한 원고다. 페이지마다 다음 네 항목을 구분한다.

- **핵심 메시지:** 그 쪽을 덮고 나서도 남아야 하는 한 문장
- **발표 스크립트:** 그림과 표를 차례대로 설명하는 문장
- **사실과 한계:** 저장된 근거로 확인된 범위와 아직 확인하지 않은 범위
- **첨삭 요청:** 내용 책임자가 맞고 틀림, 강조 순서, 용어를 결정할 항목

판정 기준이나 해석이 갈릴 수 있는 쪽에는 **예상 질문**을 덧붙였다.

쪽에 따라 네 항목 뒤에 **해석 절**이 더 붙는다. 수렴 허용 기준이나 p05·p95의 의미처럼 질문받았을 때 한

## 용어 표기 원칙

본문과 발표에서는 한국어를 먼저 사용한다. YAML 필드명이나 결과 열 이름을 확인해야 하는 곳에서만 영문을
괄호 또는 코드로 병기한다.

| 코드·기존 표현 | 보고서 표현 | 처음 설명할 때의 문장 |
|---|---|---|
| `pair` | 전극 조합 | 접촉 여부를 함께 평가하는 두 전극의 조합 |
| `source_step` | 이물 유입 공정 | 이물이 어느 layer 형성 후 들어왔다고 가정하는 공정 시점 |
| M1, M2, M3 | mask1, mask2, mask3 | 본문과 그림에서는 적층 순서를 쉽게 읽도록 단순화하고 실제 ID는 부록에 기록 |
| `particle_size` | 이물 크기 | 계산에 사용하는 이물 직경 |
| `hotspot` | hotspot | 해당 위치에 이물 중심이 오면 불량이 발생하는 후보 위치 |
| nominal | 기준 조건 / 산포 미적용 | 두께·위치 등의 산포를 적용하지 않은 한 가지 기준 조건 |
| probability map | 산포 반영 위험 지도 | 여러 산포 조건에서 위치별로 위험이 발생한 비율 |
| `union`, any-union | 중복 제거 전체 결과 / union CA | 같은 이물 유입 공정·크기에서 선언된 네 유형의 hotspot을 OR해 겹친 위치를 한 번만 센 결과. 전극 형상 mask의 합집합이 아님 |
| lateral short | lateral short | 같은 layer에 있는 두 전극의 이물 매개 접촉 |
| vertical short | vertical short | 서로 다른 layer에 있는 두 전극의 이물 매개 접촉 |
| open | open | 이물이 도체를 가려 원래 이어져 있던 두 단자의 연결을 끊는 조건 |
| CNO (`contact_not_open`) | CNO | 이물이 contact·via hole의 접촉 영역을 덮어 층간 연결이 되지 않는 조건 |
| `failure_unit_id` | 불량 단위 | 전극 조합, open 경로, 자동 단자 전극, contact 연결을 함께 부르는 내부 ID |
| `auto_open:<전극>` | contact 자동 단자 open | 사용자가 단자를 그리지 않고 contact hole과 ROI 경계를 단자로 삼아 판정한 open |
| `baseline_open` | 기준 단선 | 이물이 없어도 이미 끊겨 있던 경로. 이물 기인 CA에서 제외 |
| `terminal_lost`, `contact_lost` | 단자 소실 / contact 소실 | 산포 변형으로 단자나 hole이 전극과 만나지 않게 된 조건. 제외로 기록 |
| `insufficient_terminals` | 단자 부족 | 단자가 2개 미만이라 open을 판정하지 않는 전극 |
| failure mode | 불량 유형 | lateral short · vertical short · open · CNO의 구분 |
| common weighting | 공통 이물 분포 적용 | 모든 구조에 같은 이물 분포를 적용한 상대 비교 |
| actual weighting | 실제 Fab 분포 적용 | 제품·공정에 연결된 Fab 측정 분포를 적용한 계산 |
| `fab_distribution_layer` | Fab 이물 분포 적용 공정 | 시뮬레이션의 이물 유입 공정과 연결할 Fab 측정 공정 또는 layer |

`source_step × particle_size × any-union CA`처럼 코드 축을 그대로 쓰는 문장은 본문에서 다음처럼 풀어 쓴다.
단, `lateral short`, `vertical short`, `open`, `CNO`, `hotspot`은 보고서 용어로 그대로 쓴다.

> 이물 유입 공정별·이물 크기별로 네 불량 유형의 중복을 제거한 전체 CA

## 발표 전 공통 주의

1. 이 자료의 모든 수치는 **합성 형상** 결과다. 실제 제품 mask와 기존 현장 sim 대조는 아직 하지 않았다.
2. CA는 기하 접촉 위험이다. 불량률·수율·예상 불량 개수로 환산해 말하지 않는다.
3. 저장소의 `legacy_failure`는 외부 기존 sim이 아니라 내부 xy kernel 참고값이다. 두 개념을 섞지 않는다.
4. CNO 가림 기준과 병렬 hole 기준은 **잠정**이다. 숫자를 말할 때마다 잠정임을 함께 말한다.
5. 성능 수치는 측정 방법이 서로 다르다. CLI 전체를 잰 값(16·17쪽)과 프로세스 안 계산 시간(10쪽)을
   같은 표에서 비교하지 않는다.

## 1페이지 · 개발내용 요약

### 핵심 메시지

> particle-sim은 이물 중심 후보 위치마다 lateral short, vertical short, open, CNO 가능성을 계산하고 그
> 면적을 적분해 CA를 구하는 2.5D 시뮬레이터다. 코드와 계약은 실제 데이터 시험 직전까지 끝냈고, 남은 것은
> 기존 현장 sim과의 동일 입력 대조다.

### 발표 스크립트

“첫 쪽에서 결론부터 말씀드리겠습니다.

particle-sim은 layout 위의 모든 후보 위치에 이물을 가상으로 놓고, 그 위치에서 불량이 생기는지를 계산합니다.
불량은 네 가지로 나눕니다. 같은 layer 두 전극이 닿는 lateral short, 다른 layer 두 전극이 닿는 vertical
short, 도체가 가려져 연결이 끊기는 open, 그리고 contact hole이 막혀 층간 연결이 되지 않는 CNO입니다.
불량이 생기는 이물 중심 위치가 hotspot이고, 그 면적이 Critical Area, 줄여서 CA입니다.

가운데 세 숫자가 현재 상태입니다. 304/304는 저장소의 자동 시험 304개가 이번 실행에서 모두 통과했다는
뜻입니다. 입력 검증, 계산 규칙, 저장 형식, 합성 반례에 대한 회귀 검사가 통과했다는 의미이고, 실제 제품에서
물리적으로 맞다는 뜻은 아닙니다. 두 번째는 이번에 계산하는 불량이 네 유형이라는 것이고, 세 번째 0 px는
이번 개발의 확인 결과 중 가장 중요한 값입니다. 사용자가 단자를 직접 그려 준 기존 방식과, contact hole에서
단자를 자동으로 만든 새 방식이 CNO로 옮겨 간 위치를 빼면 픽셀 단위로 완전히 같았다는 뜻입니다. 이 내용은
8쪽에서 자세히 보시겠습니다.

오른쪽 표는 구현 범위입니다. 입력 검증부터 2.5D 접촉·open·CNO 계산, 불량 단위별 CA, 중복을 제거한 union
CA, 결과 저장까지 하나의 경로로 연결했습니다. 이번 개선의 핵심은 기존 2.5D 계산에 없던 xy 거리와 높이 차의
대각 거리 CA를 추가한 것과, 공정 산포를 반복 계산할 경로를 만든 것입니다. 신규 유형으로 contact·via mask를
읽어 open 단자를 자동으로 지정하고, contact가 막히는 CNO를 별도 불량으로 계산합니다.

마지막 두 줄이 이 자료를 읽는 기준입니다. 현재 값은 기하 접촉 위험이고 실제 불량률이나 수율로 해석하지
않습니다. 다음 순서는 기존 sim과의 실제 동일 입력 비교, 대체 판정, 그다음이 실제 제품 산포와 Fab 자료
적용입니다.”

### 사실과 한계

| 항목 | 확인된 내용 | 이 항목이 보장하지 않는 것 |
|---|---|---|
| 자동 시험 | 304개 전체 통과 (`evidence/pytest-2026-09-20.log`) | 실제 제품의 물리적 정확성 |
| 불량 4유형 | 네 유형의 계산·배분·출력 경로가 모두 연결됨 | 각 유형의 전기적 성립 조건 |
| 자동 단자 open | CNO로 이동한 위치 외 차이 0 px | 실제 제품 contact 배치에서의 동등성 |
| 현재 단계 | 입력·산포·Fab·출력 계약과 비교기 구현 완료 | 기존 sim 대체 가능 여부 |

## 2페이지 · 개선 목표

### 핵심 메시지

> 기존 방식도 2.5D였다. 부족했던 것은 xy 거리와 높이 차를 하나의 대각 거리로 합치지 못한 점과, mask 공정
> 산포를 반영하지 못한 점이다.

### 발표 스크립트

“먼저 오해를 하나 정리하고 시작하겠습니다. 기존 방식이 2D였고 이번에 2.5D가 된 것이 아닙니다. 기존 방식도
전극 높이를 반영한 2.5D 계산이었습니다. 부족했던 부분은 두 가지입니다.

첫째, 이물 중심에서 전극까지의 xy 거리와 높이 차를 하나의 대각 거리로 결합하지 못했습니다. 그래서 대각으로
떨어진 전극 조합은 계산 대상 자체가 아니었습니다. 이번 구현은 xy와 z를 합친 대각 거리로 판정하므로, 기존에
계산하지 않던 조합의 CA가 새로 나옵니다.

둘째, 고정된 한 가지 형상 조건만 계산했습니다. 이번에는 mask별 overlay와 CD 조건을 바꿔 가며 반복하고,
위치별로 불량이 난 비율과 그 평균 CA를 얻습니다.

표의 세 번째 줄도 중요합니다. 기존에는 전극 조합별 결과만 보았는데, 이번에는 조합별 결과와 모든 조합을 OR한
union 결과를 함께 저장합니다. 원인이 되는 전극과 구조 전체의 위험을 둘 다 봐야 하기 때문입니다. 네 번째
줄은 순서에 대한 약속입니다. Fab 이물 분포는 계산에 섞지 않고, 크기별 시뮬레이션이 끝난 뒤에 적용합니다.
구조 비교와 공정 분포 효과를 분리해서 보기 위해서입니다.

아래 흐름도가 그 순서입니다. 입력, 2.5D 계산, 산포 반복까지가 시뮬레이션이고 Fab 이물 분포는 사후 적용입니다.

마지막 두 문장이 이번 비교의 기준입니다. 첫 판단은 모든 구조에 같은 이물 분포를 적용한 구조 상대 비교입니다.
그리고 기존 결과가 없는 대각 전극 조합은 기존값을 0으로 두지 않고 N/A 또는 new pair로 표시합니다. 0으로
두면 '기존 대비 증가'로 잘못 읽히기 때문입니다.”

### 사실과 한계

- 기존 방식의 성격(2.5D, xy·z 분리)은 사용자와 합의한 내용이며 이 저장소가 기존 sim을 실행해 확인한 것이
  아니다.
- 대각 거리 추가로 늘어나는 CA의 크기는 실제 제품 mask에서 비교해야 확정된다.
- `N/A · new pair` 규칙은 `comparison/legacy_sim.py`에 구현돼 있고 합성 round-trip으로만 검증했다.

### 첨삭 요청

1. 기존 방식 설명을 이 수준으로 유지할지, 실제 기존 sim 문서의 표현에 맞출지.
2. "구조 상대 비교"를 첫 판단으로 삼는 규칙이 실제 검토 절차와 같은지.

### 예상 질문

- **"그럼 기존 계산이 틀렸다는 뜻인가?"** — 아닙니다. 계산 대상이 아니던 조합이 추가되는 것이며, 공통으로
  계산하던 조합의 값이 맞는지는 3번 작업(기존 sim 실제 대조)에서 확인합니다.

## 3페이지 · 입력과 출력

### 핵심 메시지

> 한 layer에 여러 전극이 있고 다른 layer 전극과 복잡하게 겹치므로, 전극마다 독립 mask로 입력하고 조합별
> 결과와 union 결과를 함께 저장한다.

### 발표 스크립트

“입력과 출력의 구조를 먼저 보시겠습니다.

왼쪽 그림은 mask1, mask2, mask3의 상하 배치이고 오른쪽은 평가할 전극 조합입니다. A–B는 같은 mask2 안의
조합이라 lateral short 후보이고, G–A와 B–P는 서로 다른 높이의 조합이라 vertical short 후보입니다.

표는 입력 다섯 묶음입니다. 첫째, 제품 manifest와 이진 mask입니다. 좌표와 축척, 적층 순서, 전극 ID와 net,
이물 유입 공정을 여기서 읽습니다. 둘째, 이물 크기와 평가 전극 조합입니다. 어떤 크기의 이물이 어느 전극
사이를 연결하는지가 결과가 됩니다. 셋째, mask별 산포 YAML입니다. 실측 overlay x/y와 CD 분포를 넣으면
위치별 조건부 확률 지도와 평균 CA가 나옵니다. 넷째, Fab 이물 표입니다. layer·크기별 평균 개수와 검사면적을
넣으면 가중 위험이 나옵니다. 다섯째가 이번에 추가된 contact·via mask입니다. 위·아래 전극을 잇는 hole의
위치를 넣으면 open 단자가 자동으로 잡히고 CNO hotspot과 CA가 나옵니다.

마지막 문장이 실제 제품 입력에서 자주 걸리는 부분입니다. 전극 mask의 합집합이 layer mask와 꼭 같을 필요는
없습니다. 부분집합이면 됩니다. 남는 영역은 TR 등 아직 평가하지 않는 영역으로 면적과 비율만 기록합니다.
TR의 신호 분리 기능을 불량 판정에 넣을지는 24쪽에서 따로 말씀드리겠습니다.”

### 사실과 한계

- 전극 mask ⊂ layer mask 검사, 같은 layer 전극 간 비중첩 검사, layer 밖 전극 오류는 구현·검증됐다.
- TR 잔여 영역은 픽셀 수·면적·비율만 기록하고 어떤 불량 판정에도 넣지 않는다.
- 그림은 합성 형상이며 실제 제품 적층을 나타내지 않는다.

### 첨삭 요청

1. mask1/mask2/mask3 표기를 유지할지, 실제 layer 약어로 바꿀지(현재 규칙은 본문 단순화 + 부록에 실제 ID).
2. 입력 표에 산포 YAML을 계속 둘지. 첫 실제 계산에서는 실측 overlay·CD만 사용하므로 11쪽과 중복될 수 있다.

## 4페이지 · 불량 유형 · 개요

### 핵심 메시지

> 네 유형 모두 "이물 중심이 이 위치에 오면 이 불량이 생기는가"라는 같은 질문에 답한다. 그렇다면 그 위치가
> hotspot이고, hotspot 면적이 CA다.

### 발표 스크립트

“여기서부터 7쪽 분량이 이번 보고의 본론입니다. 네 유형을 하나씩 보기 전에 공통 구조를 먼저 말씀드리겠습니다.

네 유형은 모두 같은 형태의 질문에 답합니다. '이물 중심이 이 위치에 오면 이 불량이 생기는가.' 답이 예인
위치를 모두 모은 것이 hotspot이고, 그 면적이 CA입니다. 판정 규칙만 다르고 출력 구조는 같습니다.

표를 보시면 판정 조건과 필요한 입력이 유형마다 다릅니다. lateral short는 같은 layer의 다른 net 전극 두
개에 이물이 동시에 닿는 경우이고, 전극 mask와 전극 조합만 있으면 계산합니다. vertical short는 다른 layer
전극 두 개에 대각 거리로 동시에 닿는 경우라 적층 두께와 순서가 추가로 필요합니다. open은 이물이 도체를 가려
원래 이어져 있던 단자 사이 경로가 끊기는 경우이고, 단자 영역 mask를 직접 주거나 contact와 ROI 경계에서
자동으로 만듭니다. CNO는 이물이 contact hole의 접촉 영역을 전부 덮어 층간 연결이 안 되는 경우이고,
contact mask와 hole layer, 적용 공정이 필요합니다.

오른쪽 끝의 불량 단위 ID 열이 결과를 읽을 때 기준이 됩니다. short는 전극 조합 ID, open은 open 경로 ID
또는 auto_open과 전극 이름, CNO는 cno와 contact, 아래·위 전극 이름으로 기록됩니다. 그래서 결과 표에서
어떤 유형의 어떤 단위가 위험한지 바로 찾을 수 있습니다.

마지막 문장이 합계 규칙입니다. 네 유형은 같은 이물 유입 공정과 크기에서 OR로 묶어 union을 만듭니다. 한
위치에서 여러 유형이 동시에 걸리면 1/k로 나누어 배분하므로, 배분값의 합계가 union과 정확히 같아집니다.
이 불변식은 자동 시험으로 고정돼 있습니다.”

### 사실과 한계

- 1/k 배분 합계 = union CA 불변식은 비중첩·완전 중첩·부분 중첩 사례에서 자동 검증한다.
- 네 유형 모두 기하 판정이다. 절연막 파괴, 접촉저항, 전기적 성립 조건은 계산하지 않는다.
- `unit_kind`는 전극 조합 / open 경로 / 자동 단자 전극 / contact 연결을 구분한다.

### 첨삭 요청

1. 불량 단위 ID를 이 쪽에서 보여 줄지, 22쪽 출력 가이드로 넘길지.
2. 네 유형의 배열 순서(lateral → vertical → open → CNO)를 발표 순서로 그대로 유지할지.

### 예상 질문

- **"short와 open을 한 union에 합쳐도 되나?"** — 기하 위험 면적으로서 겹치는 위치를 한 번만 세기 위한
  합계이며, 원인별 순위는 조합별·경로별 표로 따로 봅니다. 물리적 심각도를 같다고 보는 것은 아닙니다.

## 5페이지 · 불량 유형 · lateral short

### 핵심 메시지

> 같은 layer의 두 전극까지의 거리가 모두 이물 반지름 이하인 중심 위치가 lateral short hotspot이다. 판정은
> 가장 단순하지만 통합 CA에서 차지하는 비중은 가장 작았다.

### 발표 스크립트

“lateral short는 네 유형 중 판정이 가장 단순합니다.

위쪽 네 단계가 계산 순서입니다. 이물 직경 d에서 반지름 r을 구하고, 후보 중심에서 전극 A와 전극 B까지의
거리를 각각 구합니다. 두 거리가 모두 r에 contact margin을 더한 값 이하이면 그 중심 위치를 hotspot으로
기록합니다. 거리 계산은 전극 mask 전체에 대한 거리 변환이라 후보 위치마다 다시 탐색하지 않습니다.

그림 ①이 그 판정 개념이고, ②는 복합 200² 파일럿에서 D1과 D2 조합의 실제 hotspot입니다. 직경 10 µm,
mask1 형성 후 유입 조건입니다. 두 전극 사이 간격이 좁은 구간을 따라 띠 모양으로 hotspot이 생기는 것이
전형적인 모습입니다. ③은 6개 lateral 조합의 CA 합입니다.

오른쪽 표가 확인 결과입니다. 파일럿에서는 6개 조합에 이물 유입 공정 3개와 직경 5개를 곱해 90개 조건을
계산했습니다. 직경이 커질수록 hotspot이 넓어져야 하는데 이 단조성 위반은 0건이었습니다. 공정 의존성도
의도대로 나왔습니다. mask1 형성 후 유입이 가장 크고, 평탄화막 형성 후 유입은 0 µm²입니다. 평탄화막이
덮인 뒤에 들어온 이물은 그 아래 전극에 닿을 수 없기 때문입니다.

마지막 줄이 해석에서 주의할 부분입니다. 네 유형을 통합해 1/k로 배분했을 때 lateral short가 차지하는 비율은
3.48%였습니다. 다만 이 값은 Fab 가중 전이고 이 합성 형상의 기하 결과입니다. 실제 제품에서 lateral short
비중이 작다는 뜻으로 읽으면 안 됩니다.

아래 각주처럼 contact margin은 현재 0 µm입니다. 도전성 이물과 비도전성 이물의 전기 접촉 거리 차이는
마지막 장 '생각해야 할 부분'에 정리했습니다.”

### 사실과 한계

| 항목 | 값 | 범위 |
|---|---|---|
| 파일럿 조건 수 | 6조합 × 공정 3 × 직경 5 = 90 | 복합 200² contact 파일럿 |
| 크기 단조성 위반 | 0건 | 직경 2·4·6·8·10 µm |
| 평탄화막 형성 후 CA | 0 µm² | 모든 직경 |
| 통합 배분 CA 비중 | 3.48% | Fab 가중 전, 합성 기하 결과 |

- contact margin 0 µm는 "닿아야 short"라는 뜻이다. 전기적으로 근접만으로 불량이 되는 조건은 넣지 않았다.

### 첨삭 요청

1. 3.48%를 첫 쪽 수준의 강조로 둘지, 10쪽 통합 표로만 보낼지.
2. 평탄화막 형성 후 0 µm²를 "정상 동작 확인"으로 제시할지 "입력 가정의 결과"로 제시할지.

## 6페이지 · 불량 유형 · vertical short

### 핵심 메시지

> xy 거리와 높이 차를 하나의 대각 거리 Q로 합쳐 판정한다. 이것이 기존 계산에 없던 부분이고, 이번 합성
> 형상에서는 통합 CA의 61.26%로 가장 컸다.

### 발표 스크립트

“vertical short가 이번 개선의 핵심입니다.

위 수식이 전부입니다. 이물 반지름 r을 구하고, 후보 중심에서 각 전극까지의 xy 거리 D_xy와 높이 차 D_z를
하나의 대각 거리 Q로 합칩니다. Q = √(D_xy² + D_z²)입니다. 여유값 margin은 r에 contact margin을 더한
값에서 Q를 뺀 값이고, 두 전극 모두 margin이 0 이상이면 hotspot입니다. 기존 계산은 xy 거리와 높이를 따로
보았기 때문에, 대각으로 떨어진 조합은 판정 대상에 들어오지 않았습니다.

그림 ①이 대각 거리 Q의 정의이고, ②는 mask1의 G2와 mask2의 D1 조합에서 직경 10 µm일 때의 hotspot입니다.
③은 10개 vertical 조합의 CA 합입니다.

표의 두 번째 줄이 음성 대조입니다. 파일럿에서는 10개 조합에 공정 3개와 직경 5개를 곱해 150개 조건을
계산했고, 그중 일부러 멀리 떨어뜨린 G1–D4와 G3–D3은 모든 조건에서 0 px가 나왔습니다. 가까운 조합에서
hotspot이 나오는 것만큼, 먼 조합에서 나오지 않는 것도 확인해야 계산을 신뢰할 수 있습니다.

공정 의존성은 lateral과 같습니다. mask1 형성 후 유입이 가장 크고, 평탄화막 형성 후 유입은 모든 직경에서
0 µm²입니다.

통합 비중은 61.26%로 네 유형 중 가장 컸습니다. 이 형상에서 상하 전극이 겹치거나 대각으로 교차하는 구간이
많기 때문입니다.

마지막 줄은 꼭 함께 말씀드려야 하는 제한입니다. 여기서 계산한 vertical short는 '기하학상 이물이 두 전극에
동시에 닿을 수 있는 위치'입니다. 절연막이 실제로 파괴되는지, 접촉저항이 불량 수준인지는 계산하지 않습니다.”

### 사실과 한계

| 항목 | 값 | 범위 |
|---|---|---|
| 파일럿 조건 수 | 10조합 × 3 × 5 = 150 | 복합 200² contact 파일럿 |
| 음성 대조 | G1–D4, G3–D3 모두 0 px | 전 조건 |
| 통합 배분 CA 비중 | 61.26% | Fab 가중 전, 합성 기하 결과 |

- 대각 거리 판정은 `geometry/contact.py`, `surfaces.py`에서 축별 픽셀 길이를 반영해 계산한다. 비등방
  격자(픽셀 x/y 길이가 다른 경우)는 18쪽 회귀 항목에서 고정했다.
- 높이 차 D_z는 적층 두께 입력에서 온다. 두께 산포는 근거가 없어 0으로 고정돼 있다.

### 첨삭 요청

1. 수식을 이 쪽에 그대로 둘지, 부록으로 옮기고 그림만 남길지.
2. "기하학상 동시 접촉"과 "전기적 short"의 구분 문장을 더 앞(4쪽 개요)으로 올릴지.

### 예상 질문

- **"61%가 실제로도 가장 큰가?"** — 이 합성 형상의 기하 비율입니다. 실제 제품에서는 상하 중첩 면적과 Fab
  이물 분포에 따라 순위가 바뀔 수 있습니다.

## 7페이지 · 불량 유형 · open ① 알고리즘

### 핵심 메시지

> open은 배선끼리 닿는 불량이 아니라 도체가 끊기는 불량이다. 이물이 없을 때의 연결 상태를 먼저 확인하고,
> 이물을 놓은 뒤 그 연결이 깨지는지를 본다.

### 발표 스크립트

“open은 앞의 두 유형과 판정 방식이 다릅니다. 가장 많이 오해되는 부분이라 정의부터 말씀드리겠습니다.

open은 배선끼리 닿는 불량이 아닙니다. 이물이 도체를 가려서 원래 이어져 있던 두 단자 사이의 연결이 끊기는
불량입니다. 그래서 순서가 중요합니다. 먼저 이물이 없는 상태에서 단자들이 어떻게 이어져 있는지 기준 연결
상태를 만들고, 그다음에 이물을 놓고 그 연결이 깨지는지를 봅니다.

그림은 실제 판정 함수를 작은 배선에 적용한 결과입니다. ②처럼 본선이 끊기면 두 contact 단자가 서로 다른
덩어리로 갈라지므로 open입니다. ③처럼 단자가 없는 가지가 떨어져 나가는 경우는 연결에 영향이 없으므로 open이
아닙니다. 이 구분이 없으면 잔가지가 잘릴 때마다 불량으로 세게 됩니다. ④는 실제 계산된 open 위치를 주황으로,
같은 자리에서 contact가 막히는 CNO 위치를 보라로 표시한 것입니다.

첫 번째 표가 단자를 정하는 세 가지 방식입니다. 이번에 추가된 것이 맨 위의 contact 자동 단자입니다. 전극에
닿은 contact·via hole과 ROI 경계에 닿은 구간을 단자로 씁니다. ROI 경계를 단자로 보는 이유는, 배선이 ROI
밖으로 계속 이어지기 때문입니다. 실제 제품에서는 이 방식이 기본이고 사용자가 단자를 그릴 필요가 없습니다.
두 번째는 사용자가 두 영역을 직접 그리는 방식으로, 특정 경로를 지정하거나 기존 결과와 비교할 때 씁니다.
세 번째 두 점 좌표와 ROI proxy는 합성 시험과 이전 입력 호환용입니다.

두 번째 표가 경계 조건 처리입니다. 여기가 이번 검토에서 고친 부분입니다. 이물이 없어도 이미 끊겨 있는
경로는 명목 입력이면 입력 오류로 막고, 산포 조건에서 생긴 경우는 baseline_open이나 terminal_lost로
분류해 제외합니다. 고치기 전에는 이런 조건에서 후보 위치 전체가 open으로 계산됐습니다. contact 단자가
이물에 완전히 덮인 경우는 open이 아니라 CNO로 보냅니다. ROI 경계 구간이 완전히 덮이면 ROI 밖으로 나가는
배선이 끊긴 것이므로 open입니다. 단자가 2개 미만인 전극은 판정할 대상이 없으므로 insufficient_terminals로
기록하고 계산하지 않습니다.”

### 사실과 한계

- 연결성 판정은 대상 전극의 최소 bounding box 안에서만 수행한다. bounding box 밖에는 그 전극의 픽셀이
  없으므로 결과가 바뀌지 않으며, 이 동등성은 전체 ROI 기준 구현과 픽셀 비교로 고정했다.
- 픽셀 연결 기준은 4-연결이다(대각으로만 닿으면 끊긴 것으로 본다). 이 선택은 23쪽의 결정 항목이다.
- 단자 일부가 가려져도 살아남은 단자 픽셀끼리 같은 덩어리에 있으면 open이 아니다.
- `baseline_open`·`terminal_lost`·`contact_lost`는 실행 기록에 건수로 남는다. contact 파일럿에서는
  모두 0건이었다.

### 첨삭 요청

1. "open은 끊기는 불량"이라는 정의 문장을 1쪽에도 넣을지.
2. 세 가지 단자 지정 방식 중 실제 제품 입력에서 허용할 범위(자동 단자만 / 자동 + 명시)를 확정해야 한다.
3. ROI 경계를 단자로 보는 규칙이 실제 제품 ROI 잘라내기 방식과 맞는지 확인이 필요하다.

### 예상 질문

- **"ROI 경계가 덮이면 무조건 open인가?"** — 현재 규칙은 그렇습니다. ROI 밖 배선이 계속 이어진다고 보기
  때문입니다. ROI를 크게 잡으면 이 조건 자체가 줄어듭니다.
- **"단자가 3개 이상이면?"** — 이물이 없을 때 같은 덩어리였던 단자들이 나뉘면 open입니다. 단자 수 제한은
  없습니다.

## 8페이지 · 불량 유형 · open ② 파일럿

### 핵심 메시지

> contact에서 자동으로 만든 단자는 사용자가 그린 단자와 같은 open 위치를 찾았다. 차이는 전부 contact가
> 완전히 가려져 CNO로 옮겨 간 위치뿐이고, 그 밖의 차이는 0 px다.

### 발표 스크립트

“앞 쪽에서 설명한 자동 단자가 기존 방식과 같은 답을 내는지 확인한 결과입니다. 이번 개발에서 가장 중요한
검증입니다.

방법은 이렇습니다. 복합 200² 파일럿에는 G1, D1, D2 세 경로에 사용자가 그린 단자 영역이 있었습니다. 그
자리에 같은 net의 pad 전극과 contact hole을 넣고, 단자를 전혀 지정하지 않은 채 contact에서 자동으로
단자를 만들게 했습니다. 그리고 두 결과를 전 픽셀에서 비교했습니다.

표를 보시면 G1 경로는 명시 단자에서 10,824 px, 자동 단자에서 10,272 px입니다. 자동 단자에만 있는 위치는
0이고, 명시 단자에만 있는 위치가 552입니다. 이 552가 전부 contact가 완전히 가려진 위치입니다. 명시 단자
방식은 단자가 덮이면 open으로 셌고, 자동 단자 방식은 그 위치를 CNO로 옮겼기 때문입니다. 그래서 맨 오른쪽
'CNO 밖 차이'는 0입니다. D1은 368, D2도 368로 같은 구조이고 CNO 밖 차이는 모두 0입니다.

그림이 그 차이를 보여 줍니다. G1 경로, mask2 형성 후 유입, 직경 10 µm 조건입니다. 주황이 open이고 보라가
CNO로 이동한 위치입니다.

아래 문장이 또 하나의 확인입니다. contact를 넣지 않은 기존 파일럿은 hotspot 배열 5종과 CA·union 표가
이전 결과와 픽셀 단위로 같았습니다. 즉 contact 기능을 추가하면서 기존 입력의 결과를 바꾸지 않았습니다.

표의 숫자는 공정 3개와 직경 5개를 모두 합한 픽셀 수입니다.”

### 사실과 한계

| 경로 | 명시 단자 open | 자동 단자 open | 자동에만 | 명시에만 | CNO 밖 차이 |
|---|---:|---:|---:|---:|---:|
| G1_OPEN | 10,824 | 10,272 | 0 | 552 | 0 |
| D1_OPEN | 7,616 | 7,248 | 0 | 368 | 0 |
| D2_OPEN | 7,132 | 6,764 | 0 | 368 | 0 |

- 이 동등성은 단자 자리에 contact를 놓은 **합성 형상**에서 확인한 것이다. 실제 제품의 contact 배치와 pad
  형상에서 같은 결과가 나오는지는 별도로 확인해야 한다.

### 첨삭 요청

1. 이 쪽을 open 설명 뒤에 두는 현재 순서가 맞는지, 아니면 13쪽 검증 장으로 옮길지.

## 9페이지 · 불량 유형 · CNO

### 핵심 메시지

> CNO는 contact·via hole이 이물로 막혀 층간 연결이 되지 않는 불량이다. 실제 접촉 영역은 hole과 아래
> 전극과 위 전극의 교집합이며, 현재 가림 기준은 잠정이다.

### 발표 스크립트

“CNO는 Contact Not Open의 약자로, 이번에 새로 추가한 불량 유형입니다. 이름 그대로 '열려야 할 contact가
열리지 않는' 불량입니다.

정의부터 보겠습니다. 위·아래 전극을 잇는 contact 또는 via hole이 이물로 막혀 층간 연결이 되지 않는
경우입니다. 여기서 중요한 것은 판정에 쓰는 영역이 hole 전체가 아니라는 점입니다. 실제 접촉이 일어나는
영역은 hole과 아래 전극과 위 전극의 교집합입니다. hole이 전극 밖으로 나간 부분은 애초에 접촉에 쓰이지
않습니다.

그림 ①이 판정 기준이고 ②는 G1 contact에서 직경 10 µm일 때 CNO가 생기는 중심 위치, ③은 hole 6개의 적용
공정별 CNO CA 합입니다.

표가 현재 처리 방식입니다. 첫 두 줄은 반드시 '잠정'이라고 말씀드려야 하는 부분입니다. 현재는 이물 원판이
접촉 픽셀을 전부 덮어야 CNO로 봅니다. 일부만 가려도 접촉저항이 올라가 불량이 될 수 있지만, 어느 비율부터
불량인지는 근거가 없어 정하지 않았습니다. 병렬 hole도 마찬가지입니다. 같은 두 전극을 잇는 hole이 여러 개일
때 현재는 하나만 막혀도 CNO로 봅니다. 이중화를 의도한 설계라면 전부 막혀야 불량일 수 있습니다. 두 기준
모두 23쪽에서 결정을 요청드립니다.

세 번째 줄은 입력 검증입니다. hole마다 아래 전극과 위 전극이 각각 정확히 하나여야 하고 둘은 같은 net이어야
합니다. 하나의 hole이 두 전극에 걸치는 입력은 오류로 막습니다. 네 번째는 적용 공정입니다. contact마다
명시하며, 산포 조건에서 hole이 전극과 떨어지면 contact_lost로 기록하고 CA에 넣지 않습니다. 다섯 번째는
위험도 배분입니다. CNO 기여도는 위·아래 전극에 절반씩 배분하고, contact별 순위는 risk_by_contact 출력으로
따로 볼 수 있습니다.

마지막 각주가 숫자를 읽을 때 필요한 배경입니다. 파일럿의 hole은 5×4 µm라서 직경 6 µm 이하 이물은 접촉
영역을 전부 덮지 못합니다. 그래서 그 크기에서는 CNO가 0입니다. 기준을 '일부 가림'으로 바꾸면 이 값은
크게 달라집니다.”

### 사실과 한계

| 항목 | 현재 처리 | 성격 |
|---|---|---|
| 가림 판정 | 접촉 픽셀을 전부 덮어야 CNO | **잠정** — `CNO_COVERAGE_RULE`, manifest에 기록 |
| 병렬 hole | 하나라도 막히면 CNO | **잠정** |
| 입력 검증 | hole당 아래·위 전극 각 1개, 같은 net | 확정 |
| 산포 제외 | `contact_lost` | 확정 |
| 위험 배분 | 위·아래 전극에 1/2씩, `risk_by_contact.parquet` | 확정 |

- 파일럿 hole 크기는 5×4 µm이므로 직경 6 µm 이하에서는 CNO가 0이다. 이 0은 "불량이 없다"가 아니라
  "현재 잠정 기준에서 0"이다.
- 잠정 기준은 실행 manifest의 `cno_coverage_rule`과 보고서 양쪽에 표시된다.

### 첨삭 요청

1. **CNO 가림 기준(전부 / 일부 + 임계 비율)을 확정해야 한다.** 결정이 필요한 항목 중 영향이 가장 크다.
2. **병렬 hole 규칙**을 하나라도 막힘으로 둘지, 전부 막힘으로 바꿀지.
3. contact별 최대 가림 비율을 출력해 두면 기준 변경 시 재계산 없이 판정을 바꿀 수 있다. 이 출력을 추가할지.

### 예상 질문

- **"기준을 바꾸면 결과가 얼마나 바뀌나?"** — open과 CNO 사이에서 위치가 이동하므로 두 유형을 함께 다시
  봐야 합니다. union 합계는 유지되고 유형별 비중이 바뀝니다.

3.724초와 3.889초로 자동 단자 쪽이 4.4% 느립니다. contact 처리와 CNO 계산이 추가됐기 때문이고, 이 정도

때문입니다. 산포는 가정값입니다. 기준이 아닌 layer의 overlay x/y에 σ 0.2 µm, CD에 σ 0.1 µm를 준

다섯 번째 줄이 내용상 의미 있는 값입니다. 산포 평균 CA를 보면 명시 단자에서는 open이 6,431.9 µm²이고

### 발표 스크립트

“여기서부터는 계산 방법입니다. 먼저 산포입니다.

위 수식이 정의 전부입니다. 어떤 위치에서 P_geom은 그 위치가 hotspot이 된 산포 조건 수를 전체 조건 수로
나눈 값입니다. 평균 CA는 이 비율에 픽셀 면적을 곱해 전부 더한 값입니다. 기준 조건 CA가 0과 1로 된 면적
이라면, 산포 CA는 0과 1 사이 값을 적분한 면적입니다.

무엇을 산포로 줄지가 더 중요합니다. 첫 실제 적용에서는 Fab 실측값이 있는 mask별 overlay x, overlay y,
CD만 씁니다. 이 셋은 서로 독립으로 처리하고 overlay x와 y도 독립으로 둡니다. 근거가 없는 두께, 이물 크기,
중심 이동 산포는 0으로 고정합니다. 근거 없는 산포를 넣으면 결과가 넓어지는데 그 넓어짐이 실제인지 가정인지
구분할 수 없게 되기 때문입니다.

그림 9는 mask1 형성 후 직경 10 µm 조건에서 위치별 접촉 비율입니다. 색 선이 전극 조합별 결과이고, 굵은
남색 선과 면이 union입니다. 여기서 순서가 중요합니다. union은 조합별 확률을 나중에 더한 것이 아니라, 각
산포 조건에서 먼저 조합들을 OR한 다음 비율을 낸 값입니다. 순서를 바꾸면 겹친 위치가 중복으로 들어갑니다.

아래 설명은 Sobol에 대한 오해를 막기 위한 것입니다. Sobol은 0에서 1 사이 누적확률 공간을 고르게 채웁니다.
그 값을 지정한 분포의 역누적분포에 통과시키므로, 정규분포를 지정하면 최종 overlay·CD 변화량은 정규분포를
근사합니다. Sobol이 균일하다는 이유로 실제 변화량이 균일분포가 되는 것이 아닙니다.

수렴은 중첩 표본으로 64, 128, 256 순으로 확인하고 필요하면 512까지 올립니다. 최종 조건 수에서는 scramble
seed를 3개 이상 바꿔 결과 변동도 함께 봅니다. 주 판정값은 이물 유입 공정과 크기별 union이고, 상위 전극
기여도의 순위가 흔들리지 않는지도 같이 봅니다.”

### 사실과 한계

- `P_geom` 정의, union을 조건별 OR 후 집계하는 순서, 산포 0에서 기준 조건과 일치하는 불변식은 자동
  시험으로 고정돼 있다.
- 허용 오차는 코드에 숨은 기본값을 두지 않고 pilot 결과와 함께 명시적으로 고정한다.
- 현재 저장된 산포 결과는 **가정값**으로 돌린 것이다. 실측 overlay·CD는 아직 입력되지 않았다.
- `convergence_delta`는 seed별 마지막 prefix 비교의 최댓값이며 `inf`를 보존한다(18쪽 결함 수정 항목).

### 산포 해석 상세 (→ 부록)

이 쪽의 산포 계산을 해석할 때 필요한 다섯 가지 상세 규칙은 문서 끝 '부록 · 해석 규칙과 판정
기준'에 모았다. 이 쪽이 비대해지는 것을 피하기 위해 부록에 두었으며, 발표 시에는 질문이
들어왔을 때 참조한다.

- **권장 수렴 판정** — 128→256 상대 변화 1% 이하를 기준으로 하고, seed 3개 이상 반복. 수렴
  허용 기준 표가 포함돼 있다.
- **p05·p50·p95의 의미** — 산포 조건별 CA 분포의 백분위이며, 측정 불확실성이나 불량률의
  백분위가 아니다.
- **일반 난수 Monte Carlo와 다른 점** — Sobol이 0~1 공간을 고르게 채우고 역누적분포로 변환하는
  구조를 설명한다.
- **한 위치의 값을 계산하는 예** — P_geom 정의를 구체적 숫자로 보여준다.
- **전극 조합 중복 제거 순서** — 조건별 OR → 평균의 올바른 순서와, 이를 뒤집으면 중복이 생기는
  이유를 설명한다.

### 첨삭 요청

1. 수렴 허용 오차 값을 이 쪽에 명시할지(현재는 pilot과 함께 고정한다고만 적혀 있다).
2. Sobol 설명을 본문에 유지할지 부록으로 옮길지.

### 예상 질문

- **"64조건이면 충분한가?"** — 충분한지를 64·128·256의 변화량으로 판단합니다. 기준을 만족하지 않으면 512로
  올립니다. 실측 산포를 넣은 뒤 이 판정을 다시 합니다.

## 12페이지 · Fab 자료 적용

### 핵심 메시지

> Fab 자료는 layer·크기별 평균 이물 개수와 검사면적이다. 평균 밀도로 바꾼 뒤 시뮬레이션이 끝난 CA에
> 곱한다. 계산 중에 섞지 않는다.

### 발표 스크립트

“Fab 이물 자료를 어떻게 연결하는지입니다.

보유한 자료는 layer별·이물 크기별 평균 이물 개수와, sample 한 장당 검사면적입니다. 평균 개수를 검사면적으로
나누면 mm²당 평균 밀도가 됩니다. 이 밀도를 같은 layer와 같은 크기의 CA에 곱하면 가중 기하 위험이 나옵니다.
단위는 CA가 mm², 밀도가 개/mm²이므로 곱은 개수 차원입니다.

표는 같은 계산을 세 가지 관점으로 본 것입니다. layer별로 보면 '어느 Fab layer의 전체 위험이 큰가'에
답합니다. 이때는 그 유입 공정의 모든 hotspot을 OR한 union CA에 밀도를 곱합니다. 전극 조합별로 보면 '어느
조합이 민감한가'에 답합니다. layer와 전극을 교차해서 보면 '어느 공정의 이물이 어느 전극 불량에 크게
연결되는가'에 답합니다. 실제로 개선 대상을 찾을 때 필요한 것이 이 세 번째 관점입니다.

그림 10은 합성 Fab 분포를 넣은 기능 경로 예시입니다. 여기 값은 전극 조합 단순합이라서 최종 전체 위험값으로
쓰면 안 됩니다. 그 이유가 아래 중복 처리 설명입니다.

raw pair risk는 그 조합 자체의 민감도입니다. 조합끼리 더하면 같은 위치를 여러 번 세게 됩니다. 그래서 한
위치에서 k개 단위가 동시에 걸리면 각 단위에 1/k씩 나눈 배분 기여도를 함께 만듭니다. 배분 기여도의 합은
layer union과 일치합니다. 다만 이 배분은 물리적 원인을 확정하는 식이 아니라, 중복 없이 설명하기 위한 보고
규칙입니다. 그래서 두 값을 모두 남기고 metadata에도 표시합니다.

마지막 문장이 이 쪽의 제한입니다. 가중값은 기하 기반 기대 위험입니다. 실제 전기 불량률이나 예상 불량 개수,
수율로 확정하려면 제품 대조가 필요합니다.”

### 사실과 한계

- 한 크기 bin은 한 대표 직경에만 연결한다. 보간이나 bin 내 적분은 밀도 질량 보존 규칙을 별도 검증한 뒤에
  추가한다.
- `source_step`(이물 유입 공정)과 `fab_distribution_layer`(Fab 측정 공정)는 다른 이름일 수 있고, 표는
  manifest의 명시적 매핑으로만 찾는다.
- 평균 이물 표는 `apply-fab --run`에서만 허용한다(18쪽 결함 수정 항목).
- 현재 그림의 분포는 합성값이다.

### 두 가지 적용 목적

| 적용 방법 | 입력 분포 | 결과 해석 |
|---|---|---|
| 구조 상대 비교 | 비교할 모든 구조에 동일한 공통 이물 분포 | 동일 환경에서 어느 구조가 더 민감한지 보여주는 가중 CA 지수 |
| 실제 Fab 적용 | 제품군·Fab·공정에 연결된 실측 이물 밀도 | 해당 분포에서 예상되는 기하 위험값 |

공통 분포 적용을 먼저 수행한다. 이 단계의 목적은 Fab 환경 차이를 제거하고 구조 자체의 상대 위험을
비교하는 것이다. 실제 Fab 분포 적용은 공정과 제품 연결이 확정된 뒤 수행한다.

실제 밀도와 중복 제거 전체 CA를 곱한 Λ는 단위상 기대 건수 형태가 되지만, 즉시 실제 불량 건수나
수율로 해석해서는 안 된다. 한 이물이 여러 위치에 독립적으로 발생한다는 가정, 조사 면적과 제품 노출
면적의 대응, 이물의 전도성 및 실제 불량 전환율을 추가로 검증해야 한다.

### 크기 구간을 연결하는 권장 방법

첫 실제 적용에서는 Fab의 크기 구간마다 대표 이물 크기를 하나 정하고, 같은 크기로 시뮬레이션한다.

예:

| Fab 크기 구간 | 대표 크기 | 시뮬레이션 CA | 적용 밀도 |
|---|---:|---:|---:|
| 1–3 µm | 2 µm | CA(2 µm) | 해당 구간의 전체 밀도 |
| 3–5 µm | 4 µm | CA(4 µm) | 해당 구간의 전체 밀도 |
| 5–7 µm | 6 µm | CA(6 µm) | 해당 구간의 전체 밀도 |

한 크기 구간의 전체 밀도를 여러 시뮬레이션 직경에 반복 적용하면 이물 수를 중복 집계한다. 따라서
초기에는 **크기 구간 하나당 대표 직경 하나**를 사용한다. 구간 안에서 CA가 빠르게 변하면 Fab bin을
더 잘게 나누거나 구간 내 분포와 적분 규칙을 별도로 정의해야 한다. 관측 범위 밖의 크기는 임의로
외삽하지 않는다.

현재 코드의 `piecewise_constant`는 한 bin에 하나의 대표 직경이 연결될 때 사용한다. `exact_point`는
Fab 대표 크기와 시뮬레이션 크기가 정확히 같을 때 사용할 수 있다. `piecewise_linear`는 bin 전체
밀도의 의미와 보간 규칙이 명확하지 않으면 실제 적용에서 사용하지 않는 편이 안전하다. 원본 이물
표본을 직접 적용하는 `empirical_samples`는 아직 구현되지 않았다.

### 이물 유입 공정과 Fab 측정 공정의 연결

시뮬레이션의 "mask1 형성 후 이물 유입"과 Fab 데이터의 측정 공정 이름이 항상 같지는 않다. 따라서
문자열이 같다는 이유로 자동 연결하지 않고 다음 매핑을 명시해야 한다.

> 시뮬레이션 이물 유입 공정 → 적용할 Fab 측정 공정 → 해당 공정의 크기별 이물 밀도

현재 manifest에는 이를 위한 `fab_distribution_layer`가 있다.

### Fab 데이터 연계 권장안 (→ 부록)

5단계 연계 절차의 상세 내용은 문서 끝 '부록 · 해석 규칙과 판정 기준'의 **Fab 데이터 연계 권장안**에
있다.

### 첨삭 요청

1. 그림 10을 pair 단순합 그대로 둘지, 배분 기여도 기준 그림으로 바꿀지. 현재는 "최종 위험값이 아니다"라는
   각주로 처리하고 있다.
2. 가중값의 이름을 "가중 기하 위험"으로 유지할지.

단위별·union hotspot과 CA가 일치해야 하는데 일치했습니다. 같은 seed와 설정에서는 확률 배열이 재현됐습니다.
open은 단자 영역과 적용 공정을 바꿔 가며 전수 대조해 0 px 차이였습니다. 크기 단조성은 2, 4, 6, 8, 10 µm
에서 위반이 없었습니다. 상부 전극을 이동시키면 hotspot이 그 방향으로 따라 움직이는 것도 확인했습니다.
중복 제거는 OR 결과와 동시 단위 수, 1/k 배분 합계가 일치했습니다.

아래 두 줄이 이번에 추가된 항목입니다. 자동 단자 open은 명시 단자와 동등했고 CNO로 옮겨 간 차이만
있었습니다. CNO 자체도 전수 대조가 일치했습니다. 마지막 줄은 이번 검토에서 고친 부분으로, 기준 단선이나
단자 소실 조건에서 후보 전체를 open으로 세지 않고 분류해 제외하는 것을 확인했습니다.

오른쪽 열이 남은 범위입니다. 실제 제품 입력, 실제 Fab 값에서의 수렴, 실제 단자 mask와 대형 ROI, 비원형
이물, 기존 sim 실측 대조, 실제 제품 위험 순위, CNO 가림 기준 확정, 실제 산포 조건 빈도입니다.

아래 판단 문단이 결론입니다. 합성 결과는 계산 규칙과 다중 전극 처리의 기능 근거입니다. 실제 제품의
유효성이나 기존 현장 sim 대체 가능성을 증명하지는 않습니다. 다음 검증부터는 공통 조합과 신규 대각 조합을
구분해서 비교합니다.

마지막 각주는 용어 혼동을 막기 위한 것입니다. 저장소 안의 legacy_failure는 외부 기존 sim 결과가 아니라
xy kernel 참고값입니다. 대체 판정에 직접 쓰지 않습니다.”

| 이물 중심 offset | 가정값 | 측정·모델 근거 확보 전 산포 0 |
| 접촉 보정거리 | 미사용 | 0 µm 고정 |
| 이물 형상 | 원형·구형 | 비원형 형상은 추후 검토 |

실제 제품의 첫 산포 계산은 보유한 mask별 overlay·CD 실측값을 우선 적용하고, 근거가 없는 산포는
0으로 두는 편이 결과 해석에 안전하다.

### 내부 xy kernel 참고값과 기존 현장 sim의 구분

15쪽 표 아래쪽의 kernel quantization·kernel shape 차이는 저장소 내부의 xy 형태학 kernel과 거리
변환 계산을 비교한 작은 probe다. 외부 기존 현장 sim을 실행해 비교한 결과가 아니다.

- 차이 픽셀 3·30·20: 두 내부 계산이 다르게 표시한 위치 수
- kernel quantization: 직경을 pixel 반복 횟수로 바꾸면서 생긴 차이
- kernel shape: 사각형·원형 kernel 모양에서 생긴 차이
- 미분류 0: 이 작은 probe의 차이가 두 규칙으로 모두 설명됐다는 뜻

이 표를 "기존 방식 검증"이라고 부르면 외부 기존 sim과 비교를 완료한 것으로 오해할 수 있다. 본문에서는
"내부 xy kernel 차이 분류"로 이름을 바꾸고 세부 내용은 부록으로 옮긴다.

## 14페이지 · CA와 중복 제거

### 핵심 메시지

> 전극 조합별 CA는 원인을 찾는 값이고 union CA는 구조 전체 위험이다. 두 값의 차이가 곧 겹침의 크기다.

### 발표 스크립트

“CA 결과를 실제로 어떻게 읽는지 보겠습니다. pilot 형상의 기준 조건, 직경 10 µm입니다.

표에서 mask1 형성 후 유입을 보면 A–B lateral이 700, G–A vertical이 350, B–P vertical이 700이고 전체
union은 1,750 µm²입니다. 단순히 더하면 1,750이 맞습니다. 이 조건에서는 세 조합의 hotspot이 겹치지 않기
때문입니다. mask2 형성 후 유입을 보면 100, 0, 400인데 union은 500입니다. 이것도 합과 같습니다. 평탄화막
형성 후는 모두 0입니다.

그림 11은 mask1 형성 후 이물 크기별 조합 CA입니다. 크기가 커질수록 접촉 가능한 중심 위치가 넓어지므로 CA가
단조 증가합니다.

그림 12와 아래 표가 겹침이 있을 때의 차이를 보여 줍니다. mask2 형성 후 직경 10 µm 조건에서 union은
350 µm²인데 조합별 단순합은 650 µm²입니다. 여러 조합이 같은 중심 위치를 공유하기 때문입니다. 같은 조건에서
직경 6 µm면 둘 다 200 µm²로 같습니다. 겹침이 없기 때문입니다. 그래서 '조합 CA를 더한 값'은 구조 전체
위험이 아니라 민감도의 합으로만 읽어야 합니다.

마지막 문장을 꼭 말씀드려야 합니다. union CA는 그 layer의 전극 mask를 합친 면적이 아닙니다. 같은 이물 유입
공정과 크기에서 선언된 lateral short, vertical short, open, CNO hotspot을 OR한 결과입니다.”

### 사실과 한계

| 이물 유입 시점 (pilot, d=10 µm) | A–B lateral | G–A vertical | B–P vertical | 전체 union |
|---|---:|---:|---:|---:|
| mask1 형성 후 | 700 | 350 | 700 | 1,750 µm² |
| mask2 형성 후 | 100 | 0 | 400 | 500 µm² |
| 평탄화막 형성 후 | 0 | 0 | 0 | 0 µm² |

- 겹침 예시: mask2 형성 후 10 µm에서 union 350 µm² 대 단순합 650 µm², 6 µm에서 200 대 200.
- 근거: `evidence/run/ca.parquet`, `ca_union.parquet`, `triple/ca_union.parquet`.

### union CA의 정확한 범위

현재 `failure_mode=any`의 union CA는 **해당 layer에 그려진 전극 mask 전체의 합집합 면적**이 아니다.
한 이물 유입 공정과 이물 크기에서 선언된 lateral short·vertical short·open·CNO hotspot을 위치별로 OR한
CA다.

예를 들어 mask1 형성 후 들어온 이물이 mask1 안의 두 전극 사이 lateral short와, mask1 전극과 이후
mask2 전극 사이 vertical short를 모두 만들 수 있다면 두 hotspot을 함께 OR한다. 같은 이물 중심 위치가
두 불량을 동시에 만들더라도 한 번만 센다. 이 결과를 mask1의 평균 이물 개수에 연결한다.

따라서 Fab 적용의 주값은 다음과 같이 정의한다.

> Fab layer별 평균 이물 개수 × 그 layer에 연결된 이물 유입 공정의 모든 불량 중복 제거 union CA

원인 분석을 위해 lateral short는 전극 layer별, vertical short는 layer 조합별 union을 별도로 출력할
수 있지만, 이를 다시 더해 전체값을 만들면 hotspot 중복이 생길 수 있다.

### 전극 조합 중복 제거 순서

여러 전극 조합의 확률 지도를 마지막에 더하면 같은 이물 중심 위치가 중복 계산된다. 올바른 순서는
다음과 같다.

1. 하나의 산포 조건에서 각 전극 조합의 0/1 hotspot을 계산
2. 같은 조건 안에서 모든 전극 조합의 hotspot을 OR
3. OR 결과를 64개 조건에 대해 평균
4. 평균 지도를 공간 적분해 중복 제거 전체 평균 CA 계산

따라서 중복 제거 전체 값은 전극 조합별 접촉 비율을 단순히 더한 값이 아니다.

### 첨삭 요청

1. pilot 표와 겹침 예시 표를 둘 다 유지할지, 겹침 예시만 남길지.
2. union 정의 문장을 4쪽과 이 쪽에 모두 둘지(현재 중복).

## 16페이지 · 2차 시험 · TAT

실행했습니다. 시간은 wall time 중앙값이고 메모리는 5회 중 최대 RSS입니다. 조건은 이물 유입 공정 3개, 직경

## 17페이지 · 대형·산포 성능

### 핵심 메시지

> 기준 조건과 산포 계산은 따로 읽어야 한다. open은 공정 간 결과 재사용과 전극 bounding box 판정으로
> 5.27배, 통합은 4.04배 빨라졌고 결과는 픽셀 단위로 같다.

### 발표 스크립트

“성능은 세 가지를 나눠서 보겠습니다. 장비는 Mac mini M4 Pro, 12코어, 메모리 48 GB입니다. 아래 값은 단일
대형 합성 입력의 실측이며 실제 제품 최대치가 아닙니다.

첫 번째 표가 대형·산포 기준선입니다. 1000×1000에서 직경 32개, 공정 3개, 조합 3개의 기준 short 계산이
16.07초입니다. 같은 크기에서 직경 5개로 64개 산포 조건을 돌리면 102.25초, 최대 메모리 1,072.4 MB입니다.
P0 메모리 보완 뒤 같은 입력이 107.32초, 636.8 MB입니다. 시간은 약 5% 늘고 메모리는 약 41% 줄었습니다.
모든 변형 mask를 메모리에 미리 만들지 않고 순차 처리하도록 바꾼 결과입니다.

두 번째 표가 이번 최적화의 핵심입니다. 복합 200² 형상을 불량 유형별로 나눠 측정했습니다. 활성 조건 수를
보시면 lateral 90개, vertical 150개인데 open은 35개로 가장 적습니다. 그런데 최초 TAT는 open이 16.52초로
압도적으로 컸습니다. 조건 수가 적은데도 전체의 83%를 차지했습니다.

두 가지를 고쳤습니다. 첫째, 같은 명목 형상·단자·크기에서 계산한 open 결과를 적용 공정 사이에서 재사용하게
했습니다. 둘째, 연결 성분 판정을 전체 ROI가 아니라 대상 전극의 최소 bounding box 안에서만 하도록 했습니다.
bounding box 밖에는 그 전극 픽셀이 없으므로 결과가 바뀌지 않습니다. 그 결과 open은 16.52초에서 3.14초로,
통합은 17.86초에서 4.42초로 줄었습니다. open이 5.27배, 통합이 4.04배입니다. 최적화 전후 hotspot과 CA는
픽셀 단위로 같음을 확인했습니다.

오른쪽 두 열은 비중입니다. 최종 TAT 기준으로 open이 49.43%, 배분 CA 기준으로는 vertical short가 61.26%로
가장 큽니다. 시간이 많이 드는 유형과 위험이 큰 유형이 다르다는 뜻입니다. CA 비율은 Fab 가중 전 값입니다.

마지막 문단이 확장성 시험입니다. 같은 200² 형상을 1000² 캔버스 중앙에 그대로 두고 측정했습니다. lateral
5.68초, vertical 8.52초, open 4.67초, 통합 16.39초이고 최대 메모리 843.6 MB, 출력 621.4 MB입니다.
open이 1.49배밖에 늘지 않은 것은 bounding box 안에서만 연결성을 보기 때문입니다. 반면 short 지도는 전체
ROI에 저장되므로 출력이 커졌고, 그 대부분이 pair_margin_um입니다. 이 시험은 큰 빈 ROI의 비용을 보는 값이지
실제 긴 배선의 대표값이 아닙니다.”

### 64조건 산포 실행에 실제로 들어간 값

64조건 실행은 합성 시험용 설정을 사용했다. 이 설정에는 다음 가정 산포가 함께 들어 있다.

- GI·mask2·PLN 두께
- mask2·mask3 overlay
- mask2 CD
- 이물 직경 변화
- 이물 중심 offset

설정의 근거 표시는 `assumed`다. 사용자가 확정한 실제 제품 첫 산포 시험은 **mask layer별 Fab 실측
overlay·CD만 적용**하고, 근거가 없는 두께·이물 직경·중심 offset은 0으로 고정한다. 따라서 102.25초
실행은 Sobol 계산 경로의 과거 성능 참고값이지, 앞으로 실행할 실제 제품 조건이나 산포 모델의 근거가
아니다.

### 두 시간으로 속도 배수를 계산하면 안 되는 이유

102.25초를 16.07초로 나눈 약 6.36배를 "64조건 산포의 증가 배수"로 사용하면 안 된다.

- 기준 조건 실행은 이물 크기 32개, 산포 실행은 5개다.
- 산포 실행에는 64개 조건과 여러 가정 변수가 들어 있다.
- 두 실행 모두 1회 측정이라 동시 작업과 시스템 상태의 영향을 분리할 수 없다.
- 16쪽의 복합 입력은 0.5 µm/px, 전극 10개, 전극 조합 16개이므로 형상과 계산량이 다르다.

산포 비용은 같은 형상, 같은 전극 조합, 같은 이물 크기에서 기준 조건과 64·128·256조건을 각각 반복
측정해야 비교할 수 있다.

## 19페이지 · 폐쇄망 재현

### 핵심 메시지

> 입력, 코드, 출력의 버전을 함께 고정해야 결과를 재현할 수 있다. 저장소에는 `uv.lock`이 있지만 폐쇄망
> 반입은 대상 플랫폼 wheelhouse와 빈 환경 설치 시험이 남아 있다.

### 발표 스크립트

“폐쇄망 반입과 재현성입니다.

표의 왼쪽이 현재 확인된 것, 오른쪽이 필요한 조치입니다. Python은 3.12.13에서 실행한 근거가 있고, 대상
환경의 버전을 고정해야 합니다. 의존성은 uv.lock이 있으므로 대상 OS와 CPU에 맞는 wheelhouse를 준비하면
됩니다. 빈 환경에 새로 설치하는 시험은 아직 하지 않았습니다. 설치 시간과 로그, hash를 남기는 것이 다음
작업입니다. 회귀 테스트 304개는 통과했고, 실제 비교 adapter를 추가하면 다시 실행합니다. 실행 추적은 입력과
출력 hash, git commit과 dirty 여부, build ID를 기록하고 있습니다. 다만 최종 비교는 clean commit에서
실행해 보존해야 합니다.

아래 명령이 반입 후 기본 확인 절차입니다. 가상환경을 만들고, 인터넷 없이 wheelhouse에서 설치하고, 테스트를
돌린 다음 입력 검증 명령까지 확인하는 순서입니다.

마지막 문장이 비교 단계에서 꼭 필요한 부분입니다. 최종 비교 manifest에는 기존 sim과 particle-sim의 버전,
입력·출력 hash, 좌표 변환 규칙을 함께 기록합니다. 나중에 결과만 보고도 어떤 조건에서 나온 비교인지 확인할 수
있어야 하기 때문입니다.”

### 사실과 한계

- `run_manifest.json`에는 git commit·dirty, 입력 hash, 주요 산출물의 경로·크기·hash, Sobol seed,
  현재 제한(TR 미평가, contact margin 0, 원형/구형 이물)이 기록된다.
- manifest 자신의 hash는 순환 참조를 피하기 위해 artifacts 목록에서 제외한다.
- 빈 환경 오프라인 설치는 **미측정**이다.

### 권장 반입 방식

설치 도구에 따라 두 방식 중 하나를 선택한다. 보고서에는 둘을 모두 필수 파일처럼 나열하지 않고,
폐쇄망 운영 환경에서 허용하는 방식을 확정한 뒤 하나만 공식 절차로 기록한다.

#### 방식 A · uv 사용이 허용되는 경우

- `pyproject.toml`과 `uv.lock`을 기준으로 한다.
- 인터넷이 가능한 동일 OS·CPU 환경에서 잠금 버전에 해당하는 wheel을 미리 수집한다.
- 폐쇄망에서는 `uv sync --frozen --offline`과 같은 고정·오프라인 방식으로 설치한다.
- 캐시에 우연히 남아 있는 package에 의존하지 않도록 빈 환경에서 시험한다.

#### 방식 B · 표준 venv와 pip만 허용되는 경우

- `uv.lock`에서 대상 Python과 platform에 맞는 고정 버전 requirements를 내보낸다.
- 실행용과 시험·개발용 의존성을 분리한다.
- 모든 package를 wheelhouse에 미리 내려받고 hash 목록을 보존한다.
- 폐쇄망에서는 `pip install --no-index --find-links wheelhouse ...` 방식으로 설치한다.

필요한 것은 **직접 의존성, 잠긴 전체 의존성, 시험용 의존성을 구분할 수 있고 실제 반입 절차와 일치하는
것**이다.

### 반입 검증 순서

1. 폐쇄망 대상 OS, CPU, Python 버전을 고정한다.
2. 같은 platform에서 실행용·시험용 wheel을 수집하고 파일 hash를 기록한다.
3. 기존 `.venv`와 package cache를 사용하지 않는 새 환경을 만든다.
4. 네트워크를 차단한 상태에서 로컬 wheel만으로 설치한다.
5. 설치된 package 버전을 기록하고 잠금 목록과 비교한다.
6. 전체 회귀 테스트를 실행한다.
7. 단순 합성 입력과 복합 1000×1000 입력을 실행해 hotspot·CA hash와 TAT/RSS를 기록한다.
8. 쓰기 가능한 입력·출력·임시·matplotlib cache 경로를 확인한다.

반입 완료 근거에는 설치 명령, 설치 로그, 설치 시간, wheel·source hash, Python과 package 버전, 전체
시험 결과와 대표 계산 결과를 함께 보존한다.

### 첨삭 요청

1. 설치 명령 블록을 본문에 유지할지 부록으로 옮길지.
2. 폐쇄망 반입 작업의 담당과 일정을 이 쪽에 넣을지.

### Zarr와 Parquet의 역할

발표 스크립트의 "지도와 표"를 질문받았을 때 한 단계 더 들어갈 내용이다.

- **Zarr 축 구조:** `이물 유입 공정 × 이물 크기 × 전극 조합 × y × x`. 기준 조건의 0/1 hotspot, 산포 반영
  0~1 확률, 접촉 여유(`pair_margin_um`), 중복 제거 전체 지도를 함께 보존한다.
- **Zarr의 성격:** 사람에게 보여주는 그림 파일이 아니라 계산 수치의 원본 배열이다. 특정 크기·조합의 hotspot을
  다시 그리거나 픽셀 단위로 비교할 때 연다.
- **Parquet 행 구성:** 이물 유입 공정, 이물 크기, 전극 조합 또는 불량 유형, CA가 한 행이다. 기준 CA와 산포
  평균 CA, p05·p50·p95, 조건 수와 수렴값을 함께 담는다.
- **Parquet의 한계:** 위치별 hotspot 픽셀은 저장하지 않는다. 공간 적분이 끝난 요약값만 있으므로, 값이 나온
  위치와 겹침은 Zarr에서 확인해야 한다.

```text
Zarr     = hotspot이 어디에 있는가
Parquet  = 각 조건의 CA가 얼마인가
PNG      = 사람이 보기 위한 설명 그림
```

### 필요한 위험도 세 관점

#### 1. Fab layer별 위험도

각 Fab layer에 연결된 이물 유입 공정에서 모든 lateral short·vertical short·open·CNO hotspot을 먼저 OR해
중복을 제거한다. 이 `failure_mode=any` union CA에 해당 layer·이물 크기의 평균 이물 밀도를 적용한다.
이 결과는 "어느 공정 layer에서 유입된 이물이 구조 전체 위험에 크게 기여하는가"를 보여준다.

#### 2. 전극 조합별·개별 전극별 위험도

전극 조합별 원본 CA는 어떤 두 전극 사이가 이물에 민감한지를 보여준다. 다만 같은 이물 위치가 여러
전극 조합의 hotspot일 수 있으므로 원본 CA를 단순 합산한 값은 전체 위험이 아니다. 최종 출력에는
다음 두 값을 함께 둔다.

- `raw_pair_risk`: 해당 전극 조합의 hotspot 전체를 인정한 민감도. 전극 조합 순위를 보는 값이며
  전극 조합끼리 더하지 않는다.
- `allocated_pair_contribution`: 한 위치에서 동시에 `k`개 전극 조합이 hotspot이면 각 조합에 `1/k`씩
  나눈 기여도. 전극 조합별 값을 합하면 같은 조건의 union 위험과 정확히 같아진다.

개별 전극은 자신이 포함된 전극 조합의 `allocated_pair_contribution`을 모아 순위를 만든다. short는
전극 조합 기여를 두 전극에 절반씩 배분한 **합계 일치 기여도**와, 해당 전극이 관련된 전극 조합의
기여를 전부 보여주는 **관여 점수**를 함께 둔다. open은 해당 배선 전극에 전부 배분한다. 절반·`1/k`
배분은 전기적 원인을 단정하는 물리식이 아니라 중복 없이 합계를 맞추기 위한 보고 규칙이다.

#### 3. Fab layer와 전극을 함께 본 위험도

가장 중요한 분석 단위는 `Fab layer × 이물 크기 × pair_id`다. 여기에는 실제 `electrode_a_id`,
`electrode_b_id`, 두 전극의 layer, 불량 유형과 Fab 이물 밀도를 함께 저장한다. 이 표를 이물 크기에
대해 합산하면 "mask1 공정에서 들어온 이물이 gate1–data3 vertical short에 가장 크게 기여한다"처럼
공정 layer와 실제 전극 조합을 동시에 지정해 순위를 낼 수 있다.

현재 `particle-sim`의 `ca.parquet`에는 실제 전극 ID가 있으므로 기본 정보는 존재한다. 그러나 현재
`particle-sim-compare` 내보내기는 전극 ID를 구조화된 열로 넘기지 않고 전극 역할과 layer 중심으로
비교하며, 실측 평균 이물 개수의 가중 순위도 아직 지원하지 않는다. 따라서 현재 출력은 위치·CA 검증에는
맞지만 최종 전극 중요도 분석에는 불완전하다. 연동 단계에서 전극 ID, 전극 조합 ID, Fab layer와 배분
기여도를 계약에 추가한다.

## 부록 · 해석 규칙과 판정 기준

11쪽과 12쪽에서 참조하는 상세 해석·판정 규칙을 모았다. 각 절은 해당 쪽의 포인터에서 연결된다.

### 권장 수렴 판정

첫 pilot은 같은 scramble seed를 사용한 중첩 Sobol 표본으로 64→128→256조건을 계산한다. 128조건은
64조건을 포함하고 256조건은 128조건을 포함해야 조건 수 증가 효과만 비교할 수 있다.

| 대상 | 권장 기준 |
|---|---|
| 중복 제거 전체 평균 CA | 128→256 상대 변화 1% 이하 또는 절대 변화 1픽셀 면적 이하 |
| 보고 대상 주요 전극 조합 평균 CA | 128→256 상대 변화 2% 이하 또는 절대 변화 1픽셀 면적 이하 |
| p05·p95를 의사결정에 사용할 경우 | 256→512 변화 5% 이하를 추가 확인 |

64→128 변화도 함께 기록하되 최종 판정은 더 많은 조건인 128→256 비교를 기준으로 한다. 기준을
넘으면 512조건으로 늘리고 256→512에서 같은 기준을 다시 적용한다. CA가 0에 가까우면 상대 변화가
불안정하므로 1픽셀 면적의 절대 기준을 사용한다.

최종 제품 pilot에서는 선택한 조건 수로 scramble seed를 3개 이상 바꾸어 반복하는 것을 권장한다.
seed별 중복 제거 전체 평균 CA의 최댓값과 최솟값 차이가 seed 평균의 1%를 넘으면 조건 수를 더
늘린다. 평균 CA가 0에 가까우면 이 비교도 1픽셀 면적의 절대 기준을 사용한다. 이는 일반 Monte
Carlo식 신뢰구간을 만드는 절차라기보다 특정 Sobol scramble에 결과가 민감하지 않은지 확인하는 검사다.

### p05·p50·p95의 의미

64개 산포 조건은 각각 하나의 CA를 만든다. 이 64개 CA를 작은 값부터 정렬해 p05, p50, p95를
계산한다.

- p05: 산포 조건별 CA 분포의 하위 5% 지점
- p50: 중앙값
- p95: 상위 5%가 시작되는 지점

이는 측정 불확실성의 90% 신뢰구간이 아니며 실제 불량률의 백분위도 아니다. 입력한 산포 모델에서
기하 CA가 어느 정도 변하는지 보여주는 요약값이다.

### 일반 난수 Monte Carlo와 다른 점

현재 계산은 일반 난수를 독립적으로 뽑는 Monte Carlo가 아니라 scrambled Sobol 수열을 사용하는
quasi-Monte Carlo 방식이다. Sobol 표본은 다차원 산포 공간을 비교적 고르게 덮도록 만든다.

1. overlay x, overlay y, CD 등 산포 변수마다 0~1 구간의 Sobol 좌표 하나를 배정한다.
2. 각 좌표를 입력 분포의 역누적분포함수로 변환해 실제 µm 단위 변화량을 만든다.
3. 한 Sobol 행에 있는 모든 변화량을 합쳐 하나의 산포 조건을 만든다.
4. 각 조건에서 mask와 stack을 바꾸어 동일한 hotspot 계산을 반복한다.

Sobol이 0~1 공간을 고르게 채운다고 해서 최종 변화량이 균등분포가 되는 것은 아니다. 중앙에
해당하는 0~1 좌표는 평균 근처로 모이고 양 끝 좌표는 정규분포의 꼬리로 이동한다. Sobol은
**어떤 누적확률 구간을 선택할지** 고르게 배치하고, 역변환은 **그 구간을 정규분포 값으로 바꾸는**
역할을 한다.

다만 64개는 유한한 표본이므로 표본 평균과 표준편차가 입력값과 정확히 같지는 않을 수 있다. Sobol
좌표는 일반 난수처럼 서로 독립인 표본도 아니지만, 목표 분포의 적분을 적은 조건 수로 안정적으로
근사하려는 목적에는 맞다. 실제 문제가 되는 경우는 Fab 분포가 정규분포가 아닌데 정규분포로 입력하거나,
실제 상관관계가 있는데 각 변수를 독립으로 변환할 때다. 원시 측정 분포나 상관관계가 확인되면 경험적
누적분포 또는 상관 변환을 적용하도록 입력 모델을 확장해야 한다.

### 한 위치의 값을 계산하는 예

이물 중심 후보 위치 (x, y)를 고정하고 64개 산포 조건을 계산한다.

- 64개 모두 접촉: 값 1.0
- 32개 조건에서 접촉: 값 0.5
- 4개 조건에서 접촉: 값 0.0625
- 한 조건에서도 접촉하지 않음: 값 0

P_geom(x,y | s,d) = 해당 위치가 hotspot인 산포 조건 수 / N

여기서 s는 이물 유입 공정, d는 이물 크기, N은 산포 조건 수다. 보고서 본문에서는 P_geom을
"조건부 기하 확률"보다 **산포 조건 중 접촉 비율**이라고 풀어 쓴다.

산포에 따라 mask 위치나 폭이 변하면 hotspot 경계도 움직인다. 중심부처럼 모든 조건에서 접촉하는
위치는 1에 가깝고, 경계처럼 일부 조건에서만 접촉하는 위치는 0과 1 사이의 값이 된다.

### 전극 조합 중복 제거 순서

여러 전극 조합의 확률 지도를 마지막에 더하면 같은 이물 중심 위치가 중복 계산된다. 올바른 순서는
다음과 같다.

1. 하나의 산포 조건에서 각 전극 조합의 0/1 hotspot을 계산
2. 같은 조건 안에서 모든 전극 조합의 hotspot을 OR
3. OR 결과를 64개 조건에 대해 평균
4. 평균 지도를 공간 적분해 중복 제거 전체 평균 CA 계산

따라서 중복 제거 전체 값은 전극 조합별 접촉 비율을 단순히 더한 값이 아니다.

### Fab 데이터 연계 권장안

Fab 가중은 시뮬레이션 내부 접촉 판정과 분리하고 다음 순서로 진행한다.

```text
시뮬레이션
  source step × particle size × any-union의 산포 평균 CA
                              ↓
연결 계약
  source step ↔ Fab 측정 공정, particle size ↔ Fab size bin
                              ↓
사후 가중
  CA_union_mean(s,d) × common Fab weight(s,bin)
                              ↓
구조 비교
  layer별·전체 weighted CA index
```

#### 1단계 · 시뮬레이션 결과는 합치지 않고 보존

구조별로 다음 표를 먼저 완성한다.

| source_step | particle_size_um | failure_mode | ca_union_mean_um2 |
|---|---:|---|---:|
| S_M1 | 2 | any | … |
| S_M1 | 4 | any | … |
| S_M2 | 2 | any | … |

- CA는 산포 반영 평균값을 사용한다.
- 구조 전체 대표값에는 `failure_mode=any`인 중복 제거 전체 CA를 사용한다.
- 이물 유입 공정과 이물 크기를 유지하며 이 단계에서는 합산하지 않는다.

#### 2단계 · layer 연결표를 별도로 확정

Fab layer는 전극 조합의 상부 또는 하부 전극 layer에서 자동 추론하지 않는다. 이물이 유입된 공정과 Fab 측정 공정의 의미를 확인해 명시적인 연결표를 둔다.

| simulation source_step | fab_distribution_layer | 의미 | 승인 버전 |
|---|---|---|---|
| S_M1 | 담당자 확정값 | M1 이후 유입 이물에 적용할 측정 공정 | v1 |
| S_M2 | 담당자 확정값 | M2 이후 유입 이물에 적용할 측정 공정 | v1 |

현재 manifest에는 `fab_distribution_layer`가 있으므로 이 필드를 연결 기준으로 사용할 수 있다.

#### 3단계 · 시뮬레이션 크기와 Fab bin을 1:1로 맞춤

초기 구조 비교에서는 Fab bin마다 대표 직경 하나를 정하고 그 직경으로 시뮬레이션한다.

| Fab bin | 대표 직경 | 사용할 CA |
|---|---:|---|
| [1, 3) µm | 2 µm | CA(s, 2) |
| [3, 5) µm | 4 µm | CA(s, 4) |

- Fab의 `density_per_mm2`는 해당 bin 전체의 이물 밀도인지, 단위 직경당 밀도인지 명시한다.
- 현재 입력 계약은 bin 전체의 `particle_count / inspection_area_mm2`로 해석한다.
- 한 bin의 전체 밀도를 여러 시뮬레이션 직경에 각각 곱하면 중복 가중되므로 금지한다.
- CA가 bin 안에서 급격히 변하면 bin을 더 잘게 나누거나, 밀도를 직경 구간별로 배분하는 적분 규칙을 별도로 정의한다.
- 관측 범위 밖의 크기는 외삽하지 않고 입력 오류로 처리한다.

#### 4단계 · 공통 분포로 구조 상대 비교

구조 A와 B에 동일한 기준 weight를 사용한다.

```text
weighted_CA_index(design)
  = Σ source_step, size_bin
      CA_union_mean(design, source_step, representative_size)
      × common_weight(source_step, size_bin)
```

- weight를 합계 1로 정규화하면 결과는 상대 비교용 weighted CA index이며 면적 단위를 유지한다.
- 모든 구조에 같은 weight를 적용해야 구조 차이만 비교할 수 있다.
- layer별 점수와 전체 점수를 함께 보존한다.
- lateral·vertical 상세 점수는 원인 분석용이며, 서로 겹칠 수 있으므로 단순 합을 전체 점수로 사용하지 않는다.

#### 5단계 · 실제 Fab 자료가 준비된 뒤 예상 불량으로 확장

실제 bin별 밀도 ρ(s,b) [개/mm²]가 확보되면 다음 값을 계산한다.

```text
expected_count = Σ CA_union_mean_mm2(s,d_b) × ρ(s,b)
```

이 값은 모델상 기대 건수다. 실제 불량확률이나 수율로 바꾸려면 이물 독립성, 조사 기간, 노출 면적과 Poisson 가정 등의 추가 계약 및 제품 대조가 필요하다.

## 보고서 재생성 절차

첨삭 결과는 이 원고가 아니라 `docs/report/build_report.py`에 반영한 뒤 보고서를 다시 만든다. 저장소
루트에서 실행하며, 계산용 Python 환경과 PDF 도구 환경을 분리한다.

```sh
.venv/bin/python docs/report/build_report.py
uv venv docs/report/work/pdf-tools
uv pip install --python docs/report/work/pdf-tools/bin/python playwright==1.63.0 pymupdf==1.28.2
zsh docs/report/render-pdf.sh
```

이미 PDF 도구 환경이 있으면 환경 생성과 설치를 생략한다. 로컬 Google Chrome을 사용하며 브라우저를 따로
내려받지 않는다. 다른 환경에서는 `REPORT_PYTHON`에 도구가 설치된 Python 경로를 지정한다.

재생성 후 확인할 것:

- `evidence/pdf-validation.json`의 페이지 수, footer 여유, 수평 넘침, 쪽별 글자 수량
- 그림의 라벨 의미는 자동 검증되지 않으므로 육안 확인을 병행한다
- 숫자를 바꿨다면 이 원고의 같은 쪽 "사실과 한계" 표도 함께 고친다

그림은 `make_failure_mode_figures.py`가 `docs/report/work`의 파일럿 결과에서 만든다. 파일럿 결과를 다시
만들면 시간과 디스크를 쓰므로, 먼저 `docs/report/evidence`의 저장된 JSON을 확인한다.
