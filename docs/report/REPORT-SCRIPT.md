이 문서는 PDF 문구를 바로 확정하기 전에, 각 페이지가 전달하려는 주장과 근거를 말로 풀어 검토하기 위한 초안이다. 페이지별로 다음 네 항목을 구분한다.

- **핵심 메시지:** 독자가 페이지를 보고 기억해야 할 한 문장

- **첨삭 요청:** 내용 책임자가 맞고 틀림, 강조 순서, 용어를 결정할 항목

## 용어 표기 원칙

본문과 발표에서는 한국어를 먼저 사용한다. YAML 필드명이나 결과 열 이름을 확인해야 하는 곳에서만 영문을 괄호 또는 코드로 병기한다.

| 코드·기존 표현 | 보고서 표현 | 처음 설명할 때의 문장 |
|---|---|---|
| `pair` | 전극 조합 | 접촉 여부를 함께 평가하는 두 전극의 조합 |
| `source_step` | 이물 유입 공정 | 이물이 어느 layer 형성 후 들어왔다고 가정하는 공정 시점 |
| M1, M2, M3 | mask1, mask2, mask3 | 본문과 그림에서는 적층 순서를 쉽게 읽도록 단순화하고 실제 ID는 부록에 기록 |
| `particle_size` | 이물 크기 | 계산에 사용하는 이물 직경 |
| `hotspot` | hotspot | 해당 위치에 이물 중심이 오면 short 또는 open이 발생하는 후보 위치 |
| nominal | 기준 조건 / 산포 미적용 | 두께·위치 등의 산포를 적용하지 않은 한 가지 기준 조건 |
| probability map | 산포 반영 위험 지도 | 여러 산포 조건에서 위치별로 위험이 발생한 비율 |
| `union`, any-union | 중복 제거 전체 결과 / 중복 제거 전체 CA | 같은 이물 유입 공정·크기에서 선언된 전극 조합과 open hotspot을 OR해 겹친 이물 중심 위치를 한 번만 계산한 결과. 전극 형상 mask의 합집합이 아님 |
| lateral short | lateral short | 같은 layer에 있는 두 전극의 이물 매개 접촉 |
| vertical short | vertical short | 서로 다른 layer에 있는 두 전극의 이물 매개 접촉 |
| short | 전극 접촉 | 이물이 두 전극에 동시에 닿는 조건 |
| open | open | 이물이 배선 경로를 가려 두 단자의 연결을 끊는 조건 |
| failure mode | 불량 유형 | lateral short·vertical short·open 등의 구분 |
| `unit` | 평가 대상 | 전극 조합 또는 open 배선 경로를 함께 부르는 내부 명칭 |
| common weighting | 공통 이물 분포 적용 | 모든 구조에 같은 이물 분포를 적용한 상대 비교 |
| actual weighting | 실제 Fab 분포 적용 | 제품·공정에 연결된 Fab 측정 분포를 적용한 계산 |
| `fab_distribution_layer` | Fab 이물 분포 적용 공정 | 시뮬레이션의 이물 유입 공정과 연결할 Fab 측정 공정 또는 layer |

`source_step × particle_size × any-union CA`처럼 코드 축을 그대로 쓰는 문장은 본문에서 다음처럼 풀어 쓴다. 단, `lateral short`, `vertical short`, `open`, `hotspot`은 보고서 용어로 그대로 쓴다.

> 이물 유입 공정별·이물 크기별로 여러 전극 조합의 중복을 제거한 전체 평균 CA

## 1페이지 · 요약

### 첨삭으로 확정한 편집 기준

- 이 자료의 독자는 **기술개발 내부 검토자**다.
- 1페이지의 역할은 **개발내용 요약**이다.
- hotspot은 이물 중심 후보 위치다. 명목 결과는 위치의 binary 영역이며, 산포 결과는 위치별 접촉확률이다.
- CA의 주 비교값은 산포 조건별 접촉확률을 공간 적분한 값이다. 명목 CA는 기준선으로 구분한다.
- open은 배선 간 접촉이 아니다. 이물 크기에 따라 배선 경로가 가려지고 단자 연결이 끊기는 불량이다.
- 전극 수와 전극 조합 수는 비율처럼 보이지 않게 각각 표기한다.
- 13.48초는 1000² 복합 명목 short이며 open·산포가 제외됐음을 숫자 옆에서 강조한다.
- open·산포·Fab은 완성·양산 검증 표현 대신 **기능 경로 구현 및 합성 검증 단계**로 표현한다.
- 실제 제품 및 기존 현장 sim 미대조 사실을 첫 페이지 상단의 핵심 제한으로 표시한다.

### 이 페이지가 전달하려는 핵심 메시지

> particle-sim은 이물 중심 후보 위치의 접촉 여부를 계산하고, 공정 산포 조건에서 얻은 위치별 접촉확률을 공간 적분해 CA를 구하는 도구다. 현재 다중 전극·다층 합성 형상에서는 계산 규칙과 성능을 검증했지만, 실제 제품과 기존 현장 sim의 결과가 같은지는 아직 확인하지 않았다.

이 문장이 현재 보고서 전체의 결론이다. 첫 페이지의 숫자와 표는 이 결론을 뒷받침하는 요약 정보다.

### 먼저 정의해야 하는 용어

- **기준 조건 hotspot:** 전극 자체의 불량 위치가 아니라, 특정 공정 시점과 크기의 이물 중심을 놓았을 때 지정한 전극 조합이 동시에 접촉하는 이물 중심 좌표의 0/1 영역이다.
- **산포 hotspot:** 두께·overlay·CD 등 산포 조건을 반복했을 때 각 이물 중심 위치에서 접촉이 발생한 비율이다.
- **Critical Area, CA:** 명목 기준선은 binary hotspot 면적이다. 산포를 고려한 주 비교값은 위치별 조건부 접촉확률에 픽셀 면적을 곱해 합산한 값이다. 전극 면적이나 실제 불량 면적이 아니다.
- **전극 조합별 CA:** 접촉 여부를 함께 평가하는 두 전극만 대상으로 계산한 CA다.
- **중복 제거 전체 CA:** 같은 조건에서 여러 전극 조합의 hotspot을 합치고, 겹친 위치는 한 번만 계산한 CA다.
- **이물 유입 공정:** 이물이 어느 layer 형성 후 들어왔다고 가정하는 공정 시점이다. 어느 전극이 이미 존재하는지와 이물이 놓이는 표면 높이를 결정한다. YAML에서는 `source_step`이다.
- **조건부 확률:** 입력한 두께·overlay·CD 등의 산포 조건 중 해당 위치가 hotspot이 된 비율이다. 측정된 불량률이 아니다.
- **open:** 이물이 서로 다른 배선을 접촉시키는 현상이 아니라, 이물의 크기만큼 배선 경로가 가려져 두 단자의 연결이 끊기는 현상이다.

### 발표 스크립트 초안

“첫 페이지에서는 이번 작업의 결론부터 말씀드리겠습니다.

particle-sim은 layout 위의 모든 후보 위치에 이물을 가상으로 놓고, 그 이물이 지정한 두 전극에 동시에 닿을 수 있는지를 계산합니다. 산포가 없는 명목 계산에서는 접촉 가능한 이물 중심 위치가 binary hotspot이 됩니다. 산포 계산에서는 두께, overlay, CD 등의 조건을 바꿔 반복하고 각 위치에서 접촉한 비율을 확률 hotspot으로 만듭니다. CA의 주 비교값은 이 위치별 확률에 픽셀 면적을 곱해 합산한 값입니다. 명목 hotspot 면적은 기준선으로 함께 보존합니다.

기존 현장 sim도 전극 높이를 반영한 2.5D 방식이지만 xy 거리와 높이 차이를 합친 대각거리는 계산하지 않았고, G–A처럼 대각으로 떨어진 전극 조합은 계산 대상이 아니었습니다. 이번 구현은 이런 대각 전극 조합의 접촉을 추가로 계산합니다. 저장소의 `legacy_failure`는 외부 기존 sim 전체를 재현한 결과가 아니라 xy kernel 차이를 확인하기 위한 내부 참고값입니다. open은 배선 간 접촉이 아니라 이물이 배선 경로를 가려 두 단자의 연결을 끊는지를 계산합니다. 공정 산포 조건의 반복 계산, Fab 이물 분포 가중, simcompare 전달 형식도 코드 경로로 연결돼 있으며 현재는 합성 검증 단계입니다.

위의 첫 번째 숫자 279/279는 현재 저장소의 자동 테스트 279개가 이번 로컬 실행에서 모두 통과했다는 뜻입니다. 이것은 입력 검증, 계산 규칙, 저장 형식과 합성 반례에 대한 코드 회귀 검사가 통과했다는 의미입니다. 실제 제품에서 물리적으로 정확하다는 뜻은 아닙니다.

두 번째 지표는 복합 합성 테스트의 규모입니다. 전극 10개와 평가 전극 조합 16개를 각각 표시했습니다. mask1에 3개, mask2에 4개, mask3에 3개의 전극을 넣었고, 같은 mask 전극 조합 6개와 서로 다른 mask 전극 조합 10개를 평가했습니다. 복잡한 굴곡, 분기, 떨어진 섬, mask 간 정렬·부분 중첩·대각 교차를 한 입력에 포함했습니다.

세 번째 숫자 13.48초는 이 복합 형상을 1000×1000 픽셀로 확장했을 때의 산포 미적용 short 계산 시간 중앙값입니다. Mac mini M4 Pro에서 1회 워밍업 후 5회 실행했고, 이물 유입 공정 3개, 이물 직경 5개, 전극 조합 16개를 계산했습니다. open 계산과 64조건 산포 반복은 이 시간에 포함하지 않았습니다. 따라서 전체 기능의 실행 시간으로 읽으면 안 됩니다.

구현 범위는 입력 계약 검사, 내부 xy kernel 참고 계산, 대각거리를 추가한 2.5D 접촉, 전극 조합별 CA와 중복 제거 전체 CA, 결과 저장과 그림, simcompare 내보내기까지입니다. open·산포·Fab 가중도 구현돼 있지만, 이번 복합 2nd test는 산포 미적용 short 계산에 한정했습니다.

검증은 두 단계로 진행했습니다. 먼저 작은 단순 도형에서 예상 결과와 픽셀 단위로 비교했고, 다음으로 여러 전극과 여러 layer가 겹치는 복합 합성 도형에서 크기 단조성, 먼 전극 조합의 음성 결과, 전극 조합별 hotspot의 OR와 중복 제거 전체 결과, CA 적분을 확인했습니다. 200×200과 1000×1000 입력의 실행 시간과 최대 메모리도 측정했습니다.

현재 가장 중요한 한계는 실제 제품 mask와 기존 현장 sim 산출물을 동일 입력으로 비교하지 않았다는 점입니다. 따라서 지금 말할 수 있는 결론은 ‘정의한 계산 계약이 합성 데이터에서 일관되게 동작한다’까지입니다. ‘현장 sim을 대체할 수 있다’거나 ‘실제 불량을 정확히 예측한다’고 결론 내릴 단계는 아닙니다.

확률 결과도 같은 제한이 있습니다. 확률값은 입력한 산포 모델을 64조건으로 반복했을 때 위치별로 접촉이 발생한 비율이며, CA는 이 확률을 공간 적분한 값입니다. 현재 산포값은 assumed 설정이므로 실제 공정 불량률, 수율 또는 제품 승인 기준으로 직접 환산하면 안 됩니다.

이 문서는 기술개발 내부자료이며, 첫 페이지는 개발내용의 요약입니다. 검토자는 구현한 기능, 합성 데이터에서 확인한 범위, 기존 sim과 실제 제품 대조가 남아 있다는 점을 먼저 확인하면 됩니다.”

코드 수정 항목은 `docs/CODE-CHANGE-BACKLOG.md`에 현재 동작, 수정 이유, 대상 파일과 완료 기준까지 별도로 정리한다. 이번 문서 수정에서는 해당 제품 코드를 변경하지 않는다.

- 예상 불량 수 계산은 실제 Fab 분포와 검증 자료를 확보한 뒤 확장한다.

- Phase 0~8과 저장소 개발 차수 설명은 2페이지에서 제거한다.
- 2페이지는 계산식을 설명하지 않고, 기존 방식 대비 무엇이 개선됐는지를 설명한다. 계산 순서는 다음 페이지에서 다룬다.

### 이 페이지가 전달하려는 핵심 메시지

> 기존 방식은 전극 높이는 반영했지만 xy 거리와 높이 차이를 결합한 대각 접촉 거리를 계산하지 못했고, 공정 산포도 반영하지 않았다. 이번 구현은 대각 거리를 포함한 2.5D 접촉과 산포 조건별 hotspot·CA를 계산한다. 실제 제품 시험에서는 mask layer별 Fab 실측 overlay·CD 산포를 입력하고, 시뮬레이션이 끝난 뒤 이물 크기 분포를 적용해 구조를 상대 비교한다.

이 페이지는 세부 계산식을 설명하는 페이지가 아니다. **기존 방식에서 무엇이 부족했고 이번 개발에서 무엇을 보완했는지**를 설명하는 페이지다.

### 페이지에서 설명할 계산 구조

#### 1. 기하 입력

- 전극별 이진 mask는 xy 평면 형상을 제공한다.
- stack 두께와 공정 순서는 각 전극의 z 구간과 이물이 놓이는 표면을 정한다.
- 이물 유입 공정은 이물이 어느 공정 시점에 유입됐는지를 나타낸다. YAML 필드명은 `source_step`이다.
- 이물 크기는 이물이 전극에 도달하거나 배선 경로를 가릴 수 있는 범위를 정한다.

#### 2. 조건별 hotspot

- lateral short와 vertical short는 특정 이물 중심 위치에서 지정한 두 전극이 동시에 이물과 접촉하는지 계산한다.
- open은 특정 이물 중심 위치와 크기에서 배선 경로가 가려져 두 단자의 연결이 끊기는지 계산한다.
- 기준 조건 계산은 위치별 결과가 0 또는 1인 hotspot이다.
- 산포 계산은 두께·overlay·CD 등의 조건을 바꿔 같은 판정을 반복한다. 실제 제품에서는 overlay와 CD에 mask layer별 Fab 실측값을 사용한다.

#### 3. 산포 반영 확률과 중복 제거

- 전극 조합 또는 open 경로별 확률은 각 위치에서 hotspot이 된 산포 조건의 비율이다.
- 여러 전극 조합의 전체 위험을 계산할 때 전극 조합별 확률을 단순히 더하면 안 된다.
- 각 산포 조건 안에서 전극 조합별 0/1 hotspot을 먼저 OR하고, 중복 제거 결과를 조건 수로 평균해야 한다.
- 이 순서를 지켜야 같은 이물 중심 위치가 여러 전극 조합을 동시에 만들더라도 한 번만 집계된다.

#### 4. CA 적분

- CA를 계산할 때 적분하는 축은 y와 x다.
- 이물 유입 공정, 이물 크기, 전극 조합 또는 open 경로 축은 유지한다.
- 기준 조건 CA는 0/1 hotspot에 픽셀 면적을 곱해 합한 값이다.
- 산포 반영 CA는 위치별 조건부 확률에 픽셀 면적을 곱해 합한 값이다.
- 이물 크기를 먼저 합치면 Fab의 크기별 이물 분포를 나중에 적용하거나 바꿀 수 없으므로 원본 결과에서는 크기 축을 유지한다.

#### 5. Fab 가중

- 기하 계산은 “해당 크기의 이물이 이 위치에 있을 때 접촉 또는 open이 가능한가”를 계산한다.
- Fab 가중은 “그 크기의 이물이 해당 공정에서 얼마나 발생하는가”를 별도로 적용한다.
- 따라서 구조 차이와 Fab 이물 환경을 분리해 비교할 수 있다.
- 현재 보고서의 이물 크기 분포와 산포 숫자는 합성 입력이므로 실제 기대 불량 수로 해석하지 않는다. 실제 계산에서는 실측 overlay·CD와 이물 크기 분포를 각각 출처가 다른 입력으로 구분한다.

1. 제목은 “대각 접촉 거리와 산포를 추가했다”는 기존 방식 대비 개선점을 직접 보여주는 편이 정확하다.

4. 중복 제거는 산포 조건별 OR 후 평균한다는 계산 순서를 명시해야 한다.
5. 흐름도는 2페이지에서 세부 계산을 나열하기보다 `기존: 높이 반영·고정 조건 → 개선: 대각 거리·산포 → 사후 Fab 가중·구조 비교`로 단순화한다.
6. 원본 축 설명에서 hotspot 배열과 CA 표의 축을 구분해야 한다. hotspot은 y·x를 유지하고 CA는 y·x 적분 후 나머지 축을 유지한다.
7. “AI 연구 계획과의 관계”는 후속 활용 방향만 한 문단으로 줄인다.
8. Phase 명칭 설명은 제거한다.

### 확인이 필요한 두 가지 선택

1. **확정:** 구조 A와 B를 비교할 때 산포 반영 평균 CA를 첫 번째 대표값으로 사용한다. 명목 CA는 기존 방식 대조와 계산 확인용 기준값으로 제시한다.
2. **Fab 연계 기준:** 구조 전체 비교에는 이물 유입 공정·이물 크기별 중복 제거 전체 산포 평균 CA를 사용한다. 전극 조합별 CA와 lateral short·vertical short별 중복 제거 결과는 원인 분석용 상세값으로 유지한다.

### Fab 데이터 연계 권장안

Fab 가중은 시뮬레이션 내부 접촉 판정과 분리하고 다음 순서로 진행한다.

```text
시뮬레이션
  source step × particle size × any-union의 산포 평균 CA
                              ↓
연결 계약
  source step ↔ Fab 측정 공정, particle size ↔ Fab size bin
                              ↓
사후 가중
  CA_union_mean(s,d) × common Fab weight(s,bin)
                              ↓
구조 비교
  layer별·전체 weighted CA index
```

#### 1단계 · 시뮬레이션 결과는 합치지 않고 보존

구조별로 다음 표를 먼저 완성한다.

| source_step | particle_size_um | failure_mode | ca_union_mean_um2 |
|---|---:|---|---:|
| S_M1 | 2 | any | … |
| S_M1 | 4 | any | … |
| S_M2 | 2 | any | … |

- CA는 산포 반영 평균값을 사용한다.
- 구조 전체 대표값에는 `failure_mode=any`인 중복 제거 전체 CA를 사용한다.
- 이물 유입 공정과 이물 크기를 유지하며 이 단계에서는 합산하지 않는다.

#### 2단계 · layer 연결표를 별도로 확정

Fab layer는 전극 조합의 상부 또는 하부 전극 layer에서 자동 추론하지 않는다. 이물이 유입된 공정과 Fab 측정 공정의 의미를 확인해 명시적인 연결표를 둔다.

| simulation source_step | fab_distribution_layer | 의미 | 승인 버전 |
|---|---|---|---|
| S_M1 | 담당자 확정값 | M1 이후 유입 이물에 적용할 측정 공정 | v1 |
| S_M2 | 담당자 확정값 | M2 이후 유입 이물에 적용할 측정 공정 | v1 |

현재 manifest에는 `fab_distribution_layer`가 있으므로 이 필드를 연결 기준으로 사용할 수 있다. 실제 가중 코드는 현재처럼 `source_step`이 Fab 표와 같다고 가정하지 말고 `fab_distribution_layer`를 조회해야 한다.

#### 3단계 · 시뮬레이션 크기와 Fab bin을 1:1로 맞춤

초기 구조 비교에서는 Fab bin마다 대표 직경 하나를 정하고 그 직경으로 시뮬레이션한다.

| Fab bin | 대표 직경 | 사용할 CA |
|---|---:|---|
| [1, 3) µm | 2 µm | CA(s, 2) |
| [3, 5) µm | 4 µm | CA(s, 4) |

- Fab의 `density_per_mm2`는 해당 bin 전체의 이물 밀도인지, 단위 직경당 밀도인지 명시한다.
- 현재 입력 계약은 bin 전체의 `particle_count / inspection_area_mm2`로 해석한다.
- 한 bin의 전체 밀도를 여러 시뮬레이션 직경에 각각 곱하면 중복 가중되므로 금지한다.
- CA가 bin 안에서 급격히 변하면 bin을 더 잘게 나누거나, 밀도를 직경 구간별로 배분하는 적분 규칙을 별도로 정의한다.
- 관측 범위 밖의 크기는 외삽하지 않고 입력 오류로 처리한다.

#### 4단계 · 공통 분포로 구조 상대 비교

구조 A와 B에 동일한 기준 weight를 사용한다.

```text
weighted_CA_index(design)
  = Σ source_step, size_bin
      CA_union_mean(design, source_step, representative_size)
      × common_weight(source_step, size_bin)
```

- weight를 합계 1로 정규화하면 결과는 상대 비교용 weighted CA index이며 면적 단위를 유지한다.
- 모든 구조에 같은 weight를 적용해야 구조 차이만 비교할 수 있다.
- layer별 점수와 전체 점수를 함께 보존한다.
- lateral·vertical 상세 점수는 원인 분석용이며, 서로 겹칠 수 있으므로 단순 합을 전체 점수로 사용하지 않는다.

#### 5단계 · 실제 Fab 자료가 준비된 뒤 예상 불량으로 확장

실제 bin별 밀도 `ρ(s,b) [개/mm²]`가 확보되면 다음 값을 계산한다.

```text
expected_count = Σ CA_union_mean_mm2(s,d_b) × ρ(s,b)
```

이 값은 모델상 기대 건수다. 실제 불량확률이나 수율로 바꾸려면 이물 독립성, 조사 기간, 노출 면적과 Poisson 가정 등의 추가 계약 및 제품 대조가 필요하다.

#### 실제 Fab 적용 전에 필요한 코드 보완

1. 확률 실행의 중복 제거 표에 `ca_union_mean_um2`를 명시적으로 저장한다. 현재는 확률 평균이 `ca_union_nominal_um2` 열에 들어가 의미가 모호하다.
2. Fab 가중 함수가 전극 조합별 `ca.parquet`뿐 아니라 `ca_union.parquet`의 `failure_mode=any`를 입력으로 받을 수 있게 한다.
3. Fab 조회 키를 `source_step` 고정 일치에서 명시적 `fab_distribution_layer` 매핑으로 바꾼다.
4. 한 Fab bin에 여러 시뮬레이션 크기가 연결돼 밀도가 중복 적용되는 것을 검증 단계에서 차단한다.
5. 상대 비교 결과는 `weighted_CA_index`, 실제 밀도 적용 결과는 `expected_defect_count`로 이름과 단위를 분리한다.

### 2페이지 수정 방향 초안

첨삭 후 PDF에는 다음 순서로 반영하는 것이 이해하기 쉽다.

1. 기존 방식: 높이는 반영했지만 대각 거리와 산포는 미반영
2. 이번 개선: xy·z 결합 거리와 산포 조건별 hotspot·CA
3. 시뮬레이션 이후 공통 Fab 분포 적용
4. 우선 목표: 동일 조건에서 구조 상대 비교
5. 후속 목표: 실제 Fab 자료를 이용한 예상 불량 수 확장
6. AI 연구 계획과의 관계를 한 문단으로 요약
7. 세부 계산 축과 순서는 다음 페이지로 이동

## 3페이지 · 입력과 출력

### 이 페이지가 전달하려는 핵심 메시지

> 한 번의 실행에서 제품 형상, 적층 구조, 이물 유입 공정, 이물 크기와 평가할 전극 조합을 읽고, 이물 중심 위치별 hotspot과 CA를 조건별로 보존한다. 한 mask에 여러 전극이 있을 수 있으며, 전극 외 TR 역할 영역이 남을 수 있다. 서로 다른 mask의 중첩과 높이 차이도 함께 계산한다.

3페이지는 계산식을 설명하는 페이지가 아니다. **무엇을 입력하고, 어떤 순서로 계산하며, 어떤 결과 파일을 남기는지**를 연결하는 페이지다.

### 입력에서 구분해야 하는 항목

| 입력 | 역할 | 주의할 점 |
|---|---|---|
| layer mask | mask1·mask2처럼 공정 mask 전체의 패턴과 표면 형상 | 전극 외 TR 역할 영역이 포함될 수 있음. 현재 TR의 전기적 기능은 계산하지 않음 |
| 전극 mask | 하나의 mask 안에서 short 평가 대상으로 구분한 각 전극 | 한 mask에 여러 개 가능, 서로 중첩되지 않고 layer mask 안에 있어야 함 |
| stack | layer의 형성 순서·재질·두께 | 전극의 z 구간과 이물이 놓이는 표면 높이를 결정 |
| 이물 유입 공정 | 이물이 어느 layer 형성 후 유입됐는지 | YAML 필드명은 `source_step`이며 전극 layer 이름과 같은 의미가 아님 |
| 이물 크기 | 계산할 이물 직경 목록 | 입력 크기와 개수는 고정되지 않음 |
| 전극 조합 | lateral short 또는 vertical short를 평가할 두 전극 | YAML의 `electrode_pairs`에 선언한 조합만 계산 |
| open 경로 | open을 평가할 배선과 두 단자 | open을 계산하지 않으면 빈 목록 사용 |
| 산포 입력 | layer별 overlay·CD와 다른 물리 산포 | 실제 제품의 overlay·CD는 Fab 실측값을 연결하고 출처를 기록 |

### 한 mask에 여러 전극이 있는 경우

- 예를 들어 mask2에 A, B, C, D 전극이 있으면 mask2 layer mask 하나와 전극 mask 네 개를 입력한다.
- 네 전극 mask는 mask2 layer mask 안에 있어야 하지만, 합집합이 layer mask 전체와 같을 필요는 없다.
- layer mask에서 전극 mask에 포함되지 않은 부분은 TR 역할 영역이나 현재 평가하지 않는 영역일 수 있다.
- TR은 전기 신호를 분리하는 역할을 하지만, 현재 이물 해석에는 그 기능을 반영하지 않는다. 현 단계에서는 남는 영역을 허용하고 기록하며, TR의 전기적 역할을 불량 판정에 포함할지는 추가 검토한다.
- A와 B가 같은 mask에서 가까우면 lateral short 전극 조합으로 지정할 수 있다.
- mask2의 A와 mask3의 P가 서로 겹치거나 대각으로 가까우면 vertical short 전극 조합으로 지정할 수 있다.
- 다른 layer의 mask는 xy 평면에서 서로 겹쳐도 된다. 2.5D 계산이 xy 거리와 z 높이 차이를 함께 사용한다.
- 현재 구현은 가능한 전극 조합을 자동으로 모두 만들지 않는다. 실제 제품에서는 전극 조합 누락 방지 기능을 추가해야 하며 `CODE-CHANGE-BACKLOG.md`에 수정 이유와 완료 기준을 기록했다.

### 입력 이미지 크기

- 입력 크기는 200×200으로 고정되지 않는다.
- 모든 layer·전극 mask가 같은 픽셀 shape를 가져야 한다.
- `픽셀 수 × 픽셀 크기`가 manifest의 ROI 실제 크기와 맞아야 한다.
- 200×200은 계산 확인용 합성 입력이며, 1000×1000은 성능 확인용이다.
- 실제 제품은 1000×1000보다 클 수 있으며, 그 경우 전체 이미지 계산의 메모리와 TAT를 먼저 확인한다.

### 현재 그림 1의 의미

그림 1은 입력과 출력 흐름을 설명하기 위한 단순 pilot이다.

- mask1: G 전극 1개
- mask2: A·B 전극 2개
- mask3: P 전극 1개
- 전극 조합: A__B lateral short, G__A·B__P vertical short
- 이물 크기: 2, 4, 6, 8, 10 µm
- 이물 유입 공정: mask1 이후, mask2 이후, 평탄화 이후<br>  (실제 합성 fixture ID는 `S_M1`, `S_M2`, `S_PLN`)

현재 평면 그림은 mask의 상하 관계가 보이지 않아 vertical short를 확인하기 어렵다. 세 mask를 높이 방향으로 분리한 3D 개념도로 바꾸고 A__B에는 lateral short, G__A와 B__P에는 vertical short를 표시한다. 이 그림은 여러 전극과 복잡한 중첩 형상을 대표하지 않으며, 복합 형상은 10페이지의 2nd test에서 별도로 보여준다.

### 계산과 출력의 연결

1. **입력 확인**  
   모든 mask의 크기·축척, layer와 전극의 관계, stack 순서, 전극 조합과 open 단자를 확인한다.
2. **조건별 계산**  
   이물 유입 공정, 이물 크기와 전극 조합을 바꾸면서 내부 xy kernel 참고값과 대각거리 적용 2.5D hotspot을 계산한다. open 경로가 있으면 같은 이물 크기로 배선 연결 여부를 계산한다. 외부 기존 sim과 비교할 때는 기존 sim이 실제로 계산하는 전극 조합만 공통 비교 대상으로 삼는다.
3. **CA와 중복 제거**  
   전극 조합별 hotspot의 픽셀 면적을 적분해 CA를 구한다. 여러 전극 조합의 hotspot이 겹치면 OR하여 같은 이물 중심 위치를 한 번만 센 전체 CA도 저장한다.
4. **산포 계산**  
   layer별 overlay·CD 등 산포 조건을 반복하고, 위치별로 hotspot이 된 조건의 비율과 CA 분포를 저장한다. 실제 제품의 overlay·CD는 Fab 실측값을 사용한다.
5. **사후 활용**  
   시뮬레이션이 끝난 CA에 이물 크기 분포를 적용하거나 simcompare가 읽을 형식으로 내보낸다.

### hotspot 산포 계산을 쉽게 설명하는 방법

현재 구현은 일반적인 난수 Monte Carlo가 아니라 **Sobol 표본을 사용하는 준몬테카를로 방식**이다.

1. 산포 변수마다 0~1 사이의 표본 축을 만든다. 예를 들어 mask2 overlay x, mask2 overlay y,
   mask2 CD, mask3 overlay x가 각각 하나의 축이다.
2. Sobol 저불일치 수열로 여러 축의 조합 공간을 비교적 고르게 채운다. 현재 `m=6`이면
   `2⁶=64`개 조건을 만든다.
3. 각 0~1 값을 역누적분포 함수로 변환해 입력 분포의 실제 단위 값으로 바꾼다. 현재 코드는
   overlay·CD에 정규분포의 평균과 표준편차를 사용한다.
4. 각 조건에서 mask를 이동·확대·축소하고 0/1 hotspot을 다시 계산한다.
5. 한 위치가 64조건 중 48조건에서 hotspot이면 그 위치의 조건부 기하 확률은 `48/64=0.75`다.
6. 위치별 확률에 픽셀 면적을 곱해 모두 더하면 산포가 반영된 평균 CA가 된다.

```text
조건 1: hotspot 0 또는 1
조건 2: hotspot 0 또는 1
...
조건 64: hotspot 0 또는 1
                ↓ 위치별 평균
산포 반영 hotspot: 0.0 ~ 1.0
                ↓ y·x 방향 공간 적분
산포 반영 평균 CA
```

Sobol 방식도 넓은 의미에서는 Monte Carlo 계열의 수치 적분이지만, 독립 난수를 무작위로 뽑는
일반 Monte Carlo와는 다르다. 공간을 더 균일하게 덮는 수열을 사용해 같은 조건 수에서 변동을
줄이는 것이 목적이다. 현재 구현은 scramble과 seed를 사용하므로 같은 seed에서 재현된다.

여러 전극 조합을 합친 전체 hotspot은 전극 조합별 확률을 마지막에 더하지 않는다. 각 Sobol 조건
안에서 0/1 hotspot을 먼저 OR한 뒤, OR 결과를 64조건에 대해 평균한다. 이 순서를 지켜야 한 이물
중심 위치가 여러 전극 조합을 동시에 만들 때 한 번만 계산된다.

현재 코드는 정규분포의 평균·표준편차만 직접 입력한다. Fab 실측 overlay·CD가 정규분포로 정리된
값이면 그 값을 연결할 수 있다. x/y별 산포가 다르거나 상관관계가 있거나 원본 분포가 비정규라면
현재 입력 구조로는 그대로 표현할 수 없으므로 `CODE-CHANGE-BACKLOG.md`의 산포 입력 수정이 먼저다.

### Zarr와 Parquet의 역할

#### Zarr — 위치를 보존하는 다차원 지도

- 이미지처럼 y·x 위치가 있는 큰 배열을 여러 조각으로 나누어 압축 저장하는 형식이다.
- 이 보고서에서는 `이물 유입 공정 × 이물 크기 × 전극 조합 × y × x` 형태의 hotspot을 저장한다.
- 기준 조건의 0/1 hotspot, 산포 반영 0~1 확률, 접촉 여유와 중복 제거 전체 지도를 보존한다.
- 특정 이물 크기와 전극 조합의 hotspot 위치를 다시 그리거나 픽셀 단위로 비교할 때 사용한다.
- 사람에게 보여주는 그림 파일이 아니라 계산 수치의 원본 배열이다.

#### Parquet — 조건별 결과를 정리한 표

- 행과 열로 구성된 압축 표 형식이다.
- 한 행에는 이물 유입 공정, 이물 크기, 전극 조합 또는 불량 유형과 CA가 들어간다.
- 기준 조건 CA, 산포 평균 CA, p05·p50·p95, 조건 수와 수렴값을 필터링·집계하기 쉽다.
- 위치별 hotspot 픽셀 전체는 저장하지 않고, 공간 적분이 끝난 요약값을 저장한다.
- Fab 가중, 구조 비교, simcompare 전달과 보고서 표 생성에 사용한다.

```text
Zarr     = hotspot이 어디에 있는가
Parquet  = 각 조건의 CA가 얼마인가
PNG      = 사람이 보기 위한 설명 그림
```

### 발표 스크립트 초안

“세 번째 페이지에서는 한 번의 실행이 어떤 입력을 읽고 어떤 결과를 남기는지 설명드리겠습니다.

입력은 크게 제품 형상과 계산 조건으로 나뉩니다. 제품 형상은 mask1, mask2와 같은 전체 layer mask, 전극별 mask와 stack 정보로 구성됩니다. 한 mask에 전극이 하나만 있어야 하는 것은 아닙니다. 같은 mask 안에 여러 전극을 각각 구분할 수 있고, 다른 mask의 전극과 xy 평면에서 복잡하게 겹쳐 있어도 됩니다.

layer mask는 해당 공정 mask의 전체 패턴을 나타냅니다. 전극 mask는 그중 short 평가에 사용하는 전극 영역입니다. 같은 mask의 전극끼리는 겹치면 안 되고 layer mask 밖으로 나가서도 안 됩니다. 다만 전극 mask의 합집합이 layer mask 전체와 같을 필요는 없습니다. layer mask에는 전극 외에 TR 역할 영역이 포함될 수 있기 때문입니다. TR은 전기 신호를 분리하지만, 현재 이물 해석에는 그 기능을 반영하지 않습니다. 우선 남는 영역을 허용하고 면적을 기록하며, TR의 신호 분리 효과를 불량 판정에 넣을지는 물리 기준과 검증 데이터가 마련된 뒤 결정합니다. 현재 코드는 부분집합 관계를 검사하고 남는 픽셀 수·면적·비율을 실행 기록에 저장합니다.

stack 정보는 각 layer의 형성 순서와 두께를 정의합니다. 이물 유입 공정은 이물이 어느 layer 형성 후에 들어왔다고 보는지를 정합니다. YAML에서는 `source_step`이라는 필드명을 사용하지만, 본문에서는 이물 유입 공정이라고 부르겠습니다. 이 값은 전극 layer 이름 자체가 아니라, 이물이 놓이는 시점과 표면을 구분하는 조건입니다.

그림 1은 계산 흐름을 설명하기 위한 단순 pilot입니다. 아래쪽 mask1에 G, 중간 mask2에 A와 B, 위쪽 mask3에 P가 있습니다. A와 B는 같은 높이에서 평가하는 lateral short이고, G와 A 및 B와 P는 서로 다른 높이에서 평가하는 vertical short입니다. 기존 평면 그림은 위아래 관계가 보이지 않으므로 세 mask를 높이 방향으로 분리한 3D 개념도로 바꾸고, 전극 조합별 lateral short와 vertical short를 그림 안에 표시하겠습니다.

계산은 이물 유입 공정과 이물 크기, 전극 조합을 바꾸어 반복합니다. 각 조건에서 이물 중심을 모든 후보 위치에 놓아 hotspot을 계산하고, 픽셀 면적을 적분해 CA를 구합니다. 여러 전극 조합의 hotspot이 같은 위치에서 겹치면 중복 제거 전체 결과에서는 그 위치를 한 번만 셉니다.

산포 계산에서는 mask layer별 overlay와 CD 조건을 바꾸어 같은 계산을 반복합니다. 실제 제품의 overlay와 CD는 보유한 Fab 실측값을 layer별로 연결해야 합니다. 현재 합성 pilot에 사용한 숫자는 기능 확인용 가정값이므로 실제 제품 결과와 구분합니다. 두께와 이물 관련 산포는 별도의 측정 근거가 필요합니다.

출력은 두 종류로 나뉩니다. Zarr에는 위치별 hotspot과 확률 지도를 저장하고, Parquet에는 전극 조합별 CA와 중복 제거 전체 CA를 저장합니다. 그림 파일은 설명용이며 수치의 원본은 Zarr와 Parquet입니다.

이 페이지에서 확인할 핵심은 입력 이미지 크기가 고정돼 있지 않다는 점, 한 mask에 여러 전극을 넣을 수 있고 TR 영역이 별도로 남을 수 있다는 점, 그리고 이물 유입 공정·이물 크기·전극 조합 정보를 합치지 않고 결과에 보존한다는 점입니다.”

### 3페이지에서 강조할 문구

1. **한 mask에 여러 전극을 입력할 수 있다.**
2. **전극 mask 합집합이 layer mask 전체와 같을 필요는 없으며 TR 영역이 남을 수 있다. 현재 계산은 TR의 전기적 기능을 반영하지 않는다.**
3. **다른 mask 전극의 xy 중첩과 대각 거리를 함께 계산한다.**
4. **입력 크기는 고정되지 않으며 200×200은 검증용이다.**
5. **실제 제품의 overlay·CD는 mask별 Fab 실측 산포를 사용한다.**
6. **위치 지도는 Zarr, CA 표는 Parquet가 수치 원본이다.**
7. **layer mask 부분집합 검증과 가능한 전극 조합 전수 감사가 schema 2.0에 구현되었다.**

### 3페이지 PDF 수정 방향

- 현재 그림과 표의 `source step`은 이물 유입 공정으로 바꾼다.
- `pair`는 전극 조합으로 바꾼다.
- 평면 배치 대신 mask1·mask2·mask3의 높이 차가 보이는 3D 개념도를 사용한다.
- A__B에는 lateral short, G__A와 B__P에는 vertical short를 그림 안에 표시한다.
- pilot이 단순 설명용 입력이라는 문장을 그림 바로 아래에 둔다.
- 한 mask에 여러 전극이 가능하고 TR 영역 때문에 전극 mask 합집합이 layer mask 전체와 다를 수 있음을 설명한다. TR의 전기적 신호 분리 기능은 현재 계산 범위 밖이며 추후 검토 항목임을 함께 표시한다.
- 산포 입력에서 overlay·CD가 실제 제품에서는 Fab 실측값이라는 점을 표시한다.
- 세부 파일명과 YAML 필드명은 16~17페이지 부록에서 설명한다.

## 4페이지 · 접촉 계산

### 이 페이지가 전달하려는 핵심 메시지

> 각 이물 중심 후보 위치에서 이물이 두 전극에 모두 닿는지 계산한다. 이물 유입 전에 이미 형성된 전극은 xy 거리와 높이 차이를 결합한 대각거리로 판정하고, 이물 유입 후 형성되는 전극은 별도의 후속 전극 가정으로 판정한다.

이 페이지는 hotspot 산포를 설명하는 페이지가 아니다. 하나의 고정된 형상과 하나의 이물 크기에서
**특정 위치가 왜 hotspot인지**를 설명하는 페이지다.

### 먼저 구분해야 하는 두 계산

#### 1. 이물 유입 전에 이미 형성된 전극

이물 중심 후보를 \((x,y)\)라고 하면 그 위치의 표면 높이에서 이물 중심 높이를 정한다.

\[
z_{center}(x,y)=z_{surface}(x,y)+r-embedding\ depth
\]

각 전극 \(e\)에 대해 다음 거리를 계산한다.

- \(D_{xy,e}\): 이물 중심의 xy 위치에서 해당 전극 mask까지의 가장 짧은 평면 거리
- \(D_{z,e}\): 이물 중심 높이에서 해당 전극의 아래·위 높이 구간까지의 가장 짧은 거리
- \(Q_e\): 두 거리를 합친 대각거리

\[
Q_e=\sqrt{D_{xy,e}^{2}+D_{z,e}^{2}}
\]

전극별 접촉 판정값은 다음과 같다.

\[
m_e=r+contact\ margin-Q_e
\]

- \(m_e \ge 0\): 이물이 전극 \(e\)에 닿는 것으로 판정
- \(m_e < 0\): 닿지 않는 것으로 판정

여기서 `contact margin`은 계산상 이물의 접촉 반경에 더하는 보정 거리다. 예를 들어 이물 반지름이
5 µm이고 `contact margin`이 0.2 µm이면 실제 간격이 5.2 µm 이하인 위치까지 접촉으로 처리한다.
표면 거칠기나 계산에 없는 효과를 보수적으로 포함할 때 사용할 수 있지만, 실측 근거 없이 값을 넣으면
CA가 임의로 커지거나 작아진다. 따라서 근거가 마련되기 전에는 0 µm로 고정해 순수 기하 조건만
계산한다.

#### 2. 이물 유입 후에 형성되는 전극

후속 전극에는 위의 \(D_z\)와 \(Q\)를 그대로 적용하지 않는다. 현재 구현은 선택한 후속 전극 정책으로
먼저 접촉 가능 여부를 정하고, 가능하다고 판단된 전극에는 xy 거리만 적용한다.

| 현재 YAML 값 | 보고서에서 풀어 쓸 표현 | 의미 |
|---|---|---|
| `exclude` | 후속 전극 제외 | 이물 이후 형성되는 전극은 접촉 대상에서 제외 |
| `protrusion` | 이물 돌출 여부로 판정 | 이물이 중간 절연층 위로 남는다고 판단될 때 후속 전극 접촉을 허용 |
| `wrap_contact` | 후속 전극 접촉 허용 | 후속 전극이 이물과 접촉할 수 있다고 보수적으로 가정 |

현재 pilot은 `protrusion`을 사용하지만, 절연막 피복 파괴나 실제 step coverage를 검증한 물리 모델은
아니다. 따라서 이 설정에 따른 vertical short는 확정 불량이 아니라 `potential_vertical_short`, 즉
**기하상 가능한 vertical short**로 해석해야 한다.

기하상 가능한 vertical short의 예시는 다음과 같다.

1. mask1 전극 가장자리에 놓인 이물이 아래 전극에 닿고, 절연층 위로 돌출된 상태에서 이후 mask2 전극이 이물 위나 옆을 지나가는 경우
2. 위·아래 전극이 평면상 정확히 겹치지 않더라도 큰 이물이 아래 전극의 측면과 위 전극 방향에 동시에 닿을 수 있는 대각 배치
3. 부분 평탄화나 단차 부근에서 이물이 아래 전극과 접촉한 채 노출되고, 이후 형성된 위 전극이 노출된 이물에 접촉할 수 있는 경우

현재 계산은 이 형상 조건을 후보로 찾는다. 이물이 실제로 도전성인지, 절연막이 끊어지는지, 전류가
흐를 만큼 접촉저항이 낮은지는 판단하지 않으므로 실제 vertical short 확정 결과와 구분한다.

### 두 전극을 하나의 hotspot으로 합치는 방법

전극 A와 B의 개별 접촉 결과를 각각 \(H_A\), \(H_B\)라고 하면 전극 조합 hotspot은 다음과 같다.

\[
H_{A,B}(x,y)=H_A(x,y)\land H_B(x,y)
\]

두 전극에 모두 닿아야 1이고, 하나에만 닿으면 0이다. 전극 조합의 접촉 여유는 두 전극 중 더
불리한 값으로 정한다.

\[
m_{A,B}(x,y)=\min(m_A,m_B)
\]

- 같은 mask의 서로 다른 전극 조합이면 `lateral short`
- 서로 다른 mask의 전극 조합이면 `vertical short`
- 현재 계산 대상은 전극 mask이며 TR의 전기적 신호 분리 기능은 포함하지 않음

### 현재 그림 2가 의미하는 것

현재 예시는 **mask1 형성 후 유입된 직경 10 µm 이물**이 G와 A에 동시에 닿을 수 있는 중심 위치를
보여준다. G는 이물 유입 전에 존재하므로 대각거리로 계산하고, A는 이후 형성되는 전극이므로
`protrusion` 가정을 적용한다.

- 기존 현장 sim에서는 G–A 대각 전극 조합을 계산하지 않았으므로 기존 CA는 0이 아니라 **결과 없음(N/A)**이다.
- 이번 합성 예시에서 새로 계산한 G–A hotspot은 이물 중심 x 위치 28–31.5 µm이며 CA는 350 µm²다.
- 현재 그림의 28–35 µm, 700 µm²는 외부 기존 sim 결과가 아니라 저장소 내부의 xy-only 참고 계산이다.
- xy-only 참고값은 대각거리 적용 효과를 설명하는 보조 자료로만 사용할 수 있으며 기존 대비 CA로 표시하면 안 된다.
- G–A의 350 µm²는 새로 확인한 전극 조합별 후보 면적이다. 다른 전극 조합과 겹칠 수 있으므로 제품 전체 CA가 반드시 350 µm² 증가한다는 의미는 아니다.

### 현재 문구에서 바로잡을 부분

현재 페이지는 두 부분을 바로잡아야 한다. 첫째, “중심에서 각 전극까지의 수평·수직 거리를 결합해
Q를 구한다”는 문장은 모든 전극에 같은 계산을 적용하는 것처럼 읽힌다. 둘째, 내부 xy-only 참고값을
외부 기존 sim 결과처럼 표시하고 있다. 본문은 다음처럼 바꾼다.

> 기존 방식도 높이를 반영한 2.5D 계산이지만 G–A와 같은 대각 전극 조합은 계산 대상이 아니었다. 이번 구현은 이물 유입 전에 형성된 전극에 xy 거리와 높이 차이를 합친 대각거리를 적용하고, 이후 형성되는 전극은 이물의 잔여 돌출 높이와 후속 전극 정책으로 접촉 가능성을 판정한다. 두 전극 모두 접촉할 때 해당 이물 중심 위치를 새로운 hotspot으로 기록한다.

### 그림 2 수정 방향

1. 첫 패널을 단순 전극 평면 투영 대신 x-z 단면 개념도로 바꾼다.
2. 단면에 이물 원, 중심점, 반지름 \(r\), \(D_{xy}\), \(D_z\), 대각거리 \(Q\)를 직접 표시한다.
3. mask 이름은 M1·M2 대신 mask1·mask2로 표시한다.
4. `S_M1`은 본문에서 “mask1 형성 후 이물 유입”으로 풀어 쓴다.
5. 기존 현장 sim의 G–A 결과는 `N/A`, 이번 구현은 350 µm²로 표시한다.
6. 28–35 µm의 xy-only 계산은 필요하면 “내부 설명용 참고값”으로만 작게 표시하고 기존 결과로 부르지 않는다.
7. 28–31.5 µm가 **이물 중심 후보 구간**임을 제목에 표시한다.
8. 세 번째 패널은 0 이상 구간이 hotspot이라는 점과 곡선이 전극 조합의 최소 접촉 여유임을 표시한다.
9. G는 기존 전극의 대각거리 계산, A는 후속 전극 가정이라는 차이를 그림 아래에 명시한다.

### 발표 스크립트 초안

“네 번째 페이지에서는 한 위치가 hotspot으로 판정되는 과정을 설명드리겠습니다.

기존 방식도 전극 높이를 반영한 2.5D 계산이었습니다. 다만 G와 A처럼 평면과 높이 방향으로 비껴 있는
전극 조합은 계산 대상에 포함되지 않았고, xy 거리와 높이 차이를 하나의 대각거리로 계산하지 않았습니다.
이번 구현은 먼저 이물의 반지름과 이물이 놓이는 표면 높이로 이물 중심 높이를 구합니다. 이물 유입
시점에 이미 만들어져 있는 전극은 이물 중심에서 전극까지의 xy 거리와 높이 차이를 함께 계산하고,
두 값을 합친 대각거리가 이물 반지름 안에 들어오면 접촉으로 판정합니다.

전극 두 개의 접촉 결과를 각각 계산한 다음, 두 전극에 모두 닿는 위치만 해당 전극 조합의 hotspot으로
남깁니다. 같은 mask의 두 전극이면 lateral short, 서로 다른 mask의 전극이면 vertical short로
분류합니다. 접촉 여유 그래프에서 값이 0 이상인 구간이 hotspot이며, 전극 조합의 값은 두 전극 중
접촉 여유가 더 작은 값을 사용합니다.

한 가지 구분이 필요합니다. 이물이 들어온 뒤에 만들어지는 전극은 이미 존재하는 전극과 같은 대각거리
식으로 계산하지 않습니다. 현재 pilot에서는 이물이 중간막 위로 돌출돼 있으면 후속 전극이 접촉할 수
있다는 가정을 사용합니다. 예를 들어 mask1 전극 가장자리의 이물이 아래 전극에 닿은 채 절연층 위로
돌출되고, 이후 mask2 전극이 그 이물 위나 옆을 지나가면 두 전극을 연결할 기하 조건이 만들어집니다.
두 전극이 평면상 정확히 겹치지 않아도 큰 이물이 대각 방향으로 양쪽에 닿는 경우도 포함됩니다.

이것을 기하상 가능한 vertical short라고 부르겠습니다. 실제 절연막 파괴, 이물 전도성 또는 접촉저항까지
계산한 결과는 아니므로 확정 불량과는 구분합니다.

그림의 G–A 예시는 mask1 형성 후 들어온 10 µm 이물을 계산한 합성 결과입니다. 기존 현장 sim에서는
이 대각 전극 조합을 계산하지 않았기 때문에 비교할 기존 CA가 없습니다. 이번 구현에서는 이물 중심
x 위치 28에서 31.5 µm가 hotspot이고, 전극 조합별 CA는 350 µm²로 계산됐습니다. 이는 기존 값이
350 µm²로 증가했다는 뜻이 아니라, 이전 계산 대상에 없던 대각 위험 면적을 새로 계산했다는 뜻입니다.
다른 전극 조합과 hotspot이 겹칠 수 있으므로 제품 전체 CA의 순증가는 중복 제거 전체 결과로 별도
확인해야 합니다.

현재 계산은 전극 mask의 접촉을 대상으로 합니다. 앞 페이지에서 설명한 TR의 전기적 신호 분리 기능은
이 판정에 포함하지 않았으며 추후 검토 항목으로 남겨둡니다.”

### 4페이지에서 확정한 내용

1. **확정:** 후속 전극은 `protrusion` 가정으로 처리한다.
2. **확정:** `potential_vertical_short`는 본문에서 “기하상 가능한 vertical short”로 표현한다.
3. **확정:** 접촉 보정거리(`contact_margin_um`)는 실측 또는 물리 근거가 생기기 전까지 0 µm로 고정한다.
4. **수정:** G–A는 기존 CA와 증감 비교하지 않고, 기존 계산 대상에 없던 대각 전극 조합의 CA 350 µm²가 새로 계산됐다고 설명한다.
5. **추후 검토:** 전도성·비전도성 이물에 따라 전기적 연결 조건이나 유효 접촉거리가 달라질 수 있다. 이를 단순 거리 보정값에 포함할지, 별도의 이물 재질·계면 모델로 분리할지는 측정 근거를 확보한 뒤 결정한다.

PDF와 그림 2는 전체 페이지 첨삭이 끝난 뒤 수정한다.

## 5페이지 · open 계산

### 이 페이지가 전달하려는 핵심 메시지

> open은 이물이 두 배선을 연결하는 현상이 아니다. 한 배선 위에 이물 크기만큼 가려지는 영역을 만들었을 때 지정한 두 단자 사이의 유일한 연결 경로가 끊기는지를 계산한다.

이 페이지는 이물 하나가 배선의 어느 부분을 가리면 open이 발생할 수 있는지 설명한다. orange 영역은
손상된 배선 자체가 아니라 **open을 만드는 이물 중심 후보 위치**, 즉 open hotspot이다.

### 위치 하나를 판정하는 순서

배선 mask를 \(W\), 두 단자를 \(T_1,T_2\), 후보 위치 \(c=(x,y)\), 이물 반지름을 \(r\)이라고 한다.
현재 접촉 보정거리는 0 µm이므로 이물 footprint는 반지름 \(r\)인 원으로 계산한다.

1. 후보 위치 \(c\)에 이물 원을 놓는다.
2. 원에 덮이는 배선 픽셀을 배선 mask에서 제거한다.
3. 남은 배선 픽셀을 상·하·좌·우 방향의 4-연결 기준으로 묶는다.
4. 두 단자가 같은 연결 성분에 남아 있는지 확인한다.
5. 단자가 가려졌거나 서로 다른 연결 성분으로 나뉘면 그 후보 위치를 open hotspot으로 기록한다.

수식으로 쓰면 다음과 같다.

\[
W_c'=W-B(c,r)
\]

여기서 \(B(c,r)\)는 후보 위치 \(c\)에 놓인 이물이 가리는 픽셀이다. \(W_c'\)에서 두 단자가
연결되지 않으면 \(H_{open}(c)=1\), 연결돼 있으면 0이다.

모든 ROI 픽셀에서 전체 연결성 검사를 시작하지는 않는다. 이물 원이 배선 픽셀에 하나도 닿지 않는
위치는 배선을 끊을 수 없으므로, 배선에서 반지름 \(r\) 이내에 있는 중심 위치만 후보로 만든다.
이 후보 축소는 계산량을 줄이기 위한 것이며 최종 hotspot의 의미는 바뀌지 않는다.

### 그림 3 읽는 방법

- 회색: 손상 전 배선
- 청록색 점: 연결 여부를 확인할 두 단자
- 주황색: 그 위치에 이물 중심이 오면 open이 되는 후보 위치
- 주황색 한 픽셀씩은 서로 다른 독립적인 이물 배치 조건

주황색은 한 번의 이물이 동시에 차지하는 전체 영역이 아니다. 예를 들어 주황색 띠가 길게 이어져
있더라도 긴 이물 하나를 뜻하지 않고, 그 띠 안의 각 위치에 이물을 하나씩 가상으로 놓아 계산한 결과다.

| 도형 | 확인하려는 내용 |
|---|---|
| 직선 | 좁은 단일 경로를 이물이 가렸을 때 두 단자가 분리되는지 확인 |
| 우회 | 일부 경로가 가려져도 다른 경로가 남으면 open이 아닌지 확인 |
| 분기 | 단자로 이어지지 않는 가지가 잘려도 주 연결은 유지되는지 확인 |
| ㄱ자 | 모서리 부근의 후보 위치가 누락되지 않고 연결성을 올바르게 판정하는지 확인 |

위·아래 행은 배선 형상이 다른 것이 아니라 픽셀의 물리 크기가 다르다.

- 위: \(dy=dx=0.5\) µm/px
- 아래: \(dy=1.0\), \(dx=0.5\) µm/px

같은 직경 4 µm 이물이라도 아래 행에서는 y 방향 한 픽셀이 더 크므로 이물 원이 차지하는 픽셀 모양과
hotspot 두께가 달라진다. 계산은 픽셀 개수가 아니라 각 축의 실제 µm 크기를 사용한다.

### 표의 0 px를 쉽게 표시하는 방법

현재 표의 `0 px`는 open hotspot이 없다는 뜻으로 오해하기 쉽다. 이 숫자는 구현 결과와 24×24
격자의 모든 이물 중심을 하나씩 직접 계산한 기준 결과 사이의 **불일치 픽셀 수**다.

표 제목과 열 이름을 다음처럼 바꾼다.

> 검증 결과 · 구현과 전수 계산의 불일치 위치

각 셀의 `0 px` 표기는 `일치 · 불일치 0개`로 바꾼다. 표 바로 위에는 다음 문장을 둔다.

> 주황색 open hotspot은 존재한다. 아래 표의 0은 hotspot 개수가 아니라 구현과 전수 계산이 다르게 판정한 위치의 개수다.

따라서 표는 open hotspot이 없다는 뜻이 아니라, 그림의 hotspot 위치가 전수 계산과 완전히
일치했음을 보여준다. open CA는 주황색 hotspot 픽셀 수에 픽셀 면적을 곱해 구한다.

### 단자 입력과 결과 이름

open은 어떤 두 지점 사이의 연결을 유지해야 하는지 정의해야 하므로 두 단자의 개념은 필요하다. 다만
실제 제품에서 한 픽셀의 `(y, x)` 좌표를 직접 입력하는 방식은 어렵고 mask 해상도 변경에도 취약하다.

schema 2.0에서는 두 개의 작은 **단자 영역 mask**를 기본 입력으로 사용한다. 사용자는 원본 배선 mask
위에서 연결을 유지해야 하는 시작 영역과 도착 영역을 각각 칠한다. 두 영역은 대상 배선 안에 있고,
비어 있지 않으며 서로 겹치지 않아야 한다. 기존 점 좌표는 합성 시험과 이전 입력 호환용으로 유지한다.

- 두 단자 영역을 명시한 결과: 지정 단자 영역 기준 open
- 단자 없이 ROI 경계 규칙으로 임시 단자를 정한 결과: open proxy

코드의 `open_confirmed`는 전기적으로 실제 open이 확인됐다는 뜻이 아니라 **두 단자가 입력된 기하
연결성 결과**라는 뜻이다. 보고서 본문에서는 오해를 피하기 위해 “지정 단자 기준 open”으로 표시한다.
실제 제품 검증에서는 `roi_boundary` 자동 선택을 사용하지 않고 두 단자 영역을 mask로 확인한다.

### 현재 계산의 범위

- 하나의 전극 mask 안에서 두 단자의 2D 연결성만 검사한다.
- 이물이 덮은 배선 픽셀은 전부 사용할 수 없어진다고 가정한다.
- 배선이 부분적으로 얇아지는 현상, 저항 증가와 불완전 open은 계산하지 않는다.
- 다른 layer나 via를 통한 우회 연결은 계산하지 않는다.
- 전도성 이물이 끊어진 부분을 다시 연결할 가능성은 계산하지 않는다.

마지막 항목은 이물 재질과 관련된 후속 검토 대상이다. 전도성·비전도성에 따라 open과 short의 판정이
달라질 수 있지만, 현재는 접촉 보정거리로 임의 처리하지 않고 별도의 물리 모델 후보로 남긴다.

### 발표 스크립트 초안

“다섯 번째 페이지에서는 open을 계산하는 방법을 설명드리겠습니다.

여기서 open은 이물이 배선 사이를 연결하는 현상이 아닙니다. 이물이 한 배선의 일부를 가려 두 단자
영역 사이의 연결 경로를 끊는 경우입니다. 실제 입력에서는 검사할 배선 mask 위에 연결을 유지해야 할
시작 영역과 도착 영역을 작은 이진 mask로 표시합니다.

계산할 때는 각 후보 위치에 지정한 크기의 원형 이물을 하나씩 놓습니다. 이물에 덮이는 배선 픽셀을
제거한 뒤, 남은 배선에서 두 단자가 상하좌우 방향으로 계속 연결돼 있는지 확인합니다. 단자가 직접
가려지거나 두 단자가 서로 다른 영역으로 분리되면 그 이물 중심 위치를 open hotspot으로 기록합니다.

그림에서 회색은 원래 배선이고 청록색 점은 두 단자입니다. 주황색은 손상된 배선 영역이 아니라,
그 위치에 이물 중심이 오면 open이 발생하는 후보 위치입니다. 주황색 띠 전체가 하나의 이물을
나타내는 것은 아니며 각 픽셀을 독립적인 이물 중심 위치로 봐야 합니다.

직선은 유일한 경로가 끊기는 경우를 확인합니다. 우회 도형은 한쪽 경로가 가려져도 다른 경로가 남으면
open이 되지 않는지 확인합니다. 분기 도형은 단자 연결과 무관한 가지가 잘려도 주 경로가 유지되는지,
ㄱ자 도형은 모서리 주변의 후보 위치가 빠지지 않는지를 확인합니다.

위 행과 아래 행은 픽셀의 물리 크기만 다릅니다. 같은 4 µm 이물이라도 y 방향 픽셀 크기가 달라지면
이물 원과 hotspot의 픽셀 모양이 달라집니다. 계산은 각 축의 실제 µm 크기를 사용합니다.

그림에는 주황색 open hotspot이 실제로 존재합니다. 표의 0은 hotspot 수가 아니라 구현과 전수 계산이
다르게 판단한 위치의 수입니다. 불일치가 0개이므로 이 작은 합성 도형에서는 구현이 찾은 모든 hotspot이
전수 계산과 픽셀 단위로 일치했습니다.

현재 결과는 지정한 배선 mask와 두 단자의 기하 연결성 판정입니다. 실제 전기 측정으로 open을 확정한
결과는 아닙니다. 배선이 부분적으로 얇아지는 현상, 다른 layer를 통한 우회 연결, 전도성 이물이 다시
연결하는 현상은 포함하지 않았으며 향후 물리 모델 검토 항목입니다.”

### 5페이지에서 확정한 내용과 추후 확인할 내용

1. 배선 연결은 현재 상·하·좌·우의 4-연결 기준이다. 대각선으로 모서리만 닿은 픽셀을 연결로 볼지 확인이 필요하다.
2. 실제 제품 입력은 한 픽셀 좌표 대신 배선별 두 단자 영역 mask를 기본으로 하고, 점 좌표는 합성 시험 호환용으로 유지한다.
3. open은 short보다 계산 비용이 커서 복합 short TAT와 분리한 2B 시험으로 측정했다. 3개 open
   경로의 중앙 TAT는 16.523초였고, 6개 lateral short 조합은 1.444초, 10개 vertical short 조합은
   1.785초였다.
4. 전도성 이물이 끊어진 배선을 다시 연결하는 효과는 현재 미반영이며 이물 재질 모델과 함께 추후 검토한다.
5. **표현 확정:** 표의 `0 px`는 `일치 · 불일치 0개`로 바꾸고, 주황색 open hotspot이 존재한다는 문장을 표 위에 표시한다.
6. **추후 검토:** 현재 이물은 원형 footprint로 계산한다. 타원형·길쭉한 형상·불규칙 형상과 방향각은 별도 형상 모델로 검토한다.

## 6페이지 · 산포를 반영한 hotspot과 CA

### 이 페이지가 전달하려는 핵심 메시지

> 하나의 고정 형상만 계산하지 않고 overlay·CD 등의 산포 조건을 바꾸어 같은 접촉 계산을 반복한다. 위치별로 전체 조건 중 접촉한 비율을 기록하고, 이를 공간 적분해 산포가 반영된 평균 CA를 구한다.

그래프의 세로축은 실제 불량확률이나 수율이 아니다. **입력으로 만든 산포 조건 중 해당 위치가
hotspot이 된 비율**이다. 실제 Fab 불량확률로 확장하려면 검증된 공정 산포와 이물 발생 분포를
추가로 연결해야 한다.

### 일반 난수 Monte Carlo와 다른 점

현재 계산은 일반 난수를 독립적으로 뽑는 Monte Carlo가 아니라 scrambled Sobol 수열을 사용하는
quasi-Monte Carlo 방식이다. Sobol 표본은 다차원 산포 공간을 비교적 고르게 덮도록 만든다.

1. overlay x, overlay y, CD 등 산포 변수마다 0~1 구간의 Sobol 좌표 하나를 배정한다.
2. 각 좌표를 입력 분포의 역누적분포함수로 변환해 실제 µm 단위 변화량을 만든다.
3. 한 Sobol 행에 있는 모든 변화량을 합쳐 하나의 산포 조건을 만든다.
4. 각 조건에서 mask와 stack을 바꾸어 동일한 hotspot 계산을 반복한다.

Sobol이 0~1 공간을 고르게 채운다고 해서 최종 변화량이 균등분포가 되는 것은 아니다. 0~1 값
\(u\)를 정규분포의 역누적분포함수 \(\Phi^{-1}\)에 넣으면 \(x=\Phi^{-1}(u)\)는 지정한 평균과
표준편차의 정규분포를 따른다. 중앙에 해당하는 0~1 좌표는 평균 근처로 모이고 양 끝 좌표는 정규분포의
꼬리로 이동한다. Sobol은 **어떤 누적확률 구간을 선택할지** 고르게 배치하고, 역변환은 **그 구간을
정규분포 값으로 바꾸는** 역할을 한다.

다만 64개는 유한한 표본이므로 표본 평균과 표준편차가 입력값과 정확히 같지는 않을 수 있다. Sobol
좌표는 일반 난수처럼 서로 독립인 표본도 아니지만, 목표 분포의 적분을 적은 조건 수로 안정적으로
근사하려는 목적에는 맞다. 실제 문제가 되는 경우는 Fab 분포가 정규분포가 아닌데 정규분포로 입력하거나,
실제 상관관계가 있는데 각 변수를 독립으로 변환할 때다. 원시 측정 분포나 상관관계가 확인되면 경험적
누적분포 또는 상관 변환을 적용하도록 입력 모델을 확장해야 한다.

`m=6`이면 조건 수는 \(2^6=64\)개다. `seed=42`는 scrambled Sobol 표본을 같은 순서로 다시 만들기
위한 재현 조건이다. 64개가 충분하다는 뜻은 아니며 128·256조건 결과와 비교해 CA 변화가 허용 범위
안으로 들어오는지 확인해야 한다.

### 한 위치의 값을 계산하는 예

이물 중심 후보 위치 \((x,y)\)를 고정하고 64개 산포 조건을 계산한다.

- 64개 모두 접촉: 값 1.0
- 32개 조건에서 접촉: 값 0.5
- 4개 조건에서 접촉: 값 0.0625
- 한 조건에서도 접촉하지 않음: 값 0

\[
P_{geom}(x,y\mid s,d)=\frac{\text{해당 위치가 hotspot인 산포 조건 수}}{N}
\]

여기서 \(s\)는 이물 유입 공정, \(d\)는 이물 크기, \(N\)은 산포 조건 수다. 보고서 본문에서는
\(P_{geom}\)을 “조건부 기하 확률”보다 **산포 조건 중 접촉 비율**이라고 풀어 쓴다.

산포에 따라 mask 위치나 폭이 변하면 hotspot 경계도 움직인다. 중심부처럼 모든 조건에서 접촉하는
위치는 1에 가깝고, 경계처럼 일부 조건에서만 접촉하는 위치는 0과 1 사이의 값이 된다.

### 그래프 읽는 방법

- 가로축: 이물 중심의 x 위치
- 세로축: 64개 산포 조건 중 접촉한 비율
- 주황색: A–B lateral short
- 청록색: G–A vertical short
- 녹색: B–P vertical short
- 굵은 남색선과 옅은 영역: 전극 조합 중 하나 이상이 hotspot인 중복 제거 전체 결과

이 합성 pilot은 y 방향 결과가 같으므로 2D 확률 지도의 한 행을 x 프로파일로 줄여 표시했다. 실제
제품 형상에서는 y 방향으로도 값이 달라지므로 2D 지도로 확인해야 한다.

그래프에서 1인 평탄한 구간은 해당 위치가 64개 조건 모두에서 hotspot이라는 뜻이다. 경계의 계단형
값은 overlay·CD·두께 등의 변화로 hotspot 경계가 조건마다 이동했기 때문에 생긴다. 값이 0.5인
위치는 실제 불량률 50%가 아니라 현재 입력한 64개 조건 중 32개에서 기하 접촉이 발생했다는 뜻이다.

### 산포 반영 평균 CA

위치별 접촉 비율에 픽셀 면적을 곱해 전체 ROI에서 합산한다.

\[
CA_{mean}(s,d)=\sum_{x,y}P_{geom}(x,y\mid s,d)\times pixel\ area
\]

이 값은 각 산포 조건에서 얻은 binary hotspot CA 64개를 평균한 값과 같다. 따라서 다음 두 계산은
같은 결과를 낸다.

1. 위치별 접촉 비율 지도를 먼저 만들고 면적 적분
2. 조건별 CA를 각각 계산한 뒤 64개 평균

현재 합성 예시의 A–B 평균 CA 650.78 µm²와 중복 제거 전체 평균 CA 1,624.22 µm²는 입력한 가정
산포에 대한 결과다. 실제 Fab 산포를 연결한 제품 수치가 아니다.

### 전극 조합 중복 제거 순서

여러 전극 조합의 확률 지도를 마지막에 더하면 같은 이물 중심 위치가 중복 계산된다. 올바른 순서는
다음과 같다.

1. 하나의 산포 조건에서 각 전극 조합의 0/1 hotspot을 계산
2. 같은 조건 안에서 모든 전극 조합의 hotspot을 OR
3. OR 결과를 64개 조건에 대해 평균
4. 평균 지도를 공간 적분해 중복 제거 전체 평균 CA 계산

따라서 중복 제거 전체 값은 전극 조합별 접촉 비율을 단순히 더한 값이 아니다.

### p05·p50·p95의 의미

64개 산포 조건은 각각 하나의 CA를 만든다. 이 64개 CA를 작은 값부터 정렬해 p05, p50, p95를
계산한다.

- p05: 산포 조건별 CA 분포의 하위 5% 지점
- p50: 중앙값
- p95: 상위 5%가 시작되는 지점

이는 측정 불확실성의 90% 신뢰구간이 아니며 실제 불량률의 백분위도 아니다. 입력한 산포 모델에서
기하 CA가 어느 정도 변하는지 보여주는 요약값이다.

### 합성 검증값과 실제 제품 입력의 구분

현재 페이지 표의 모든 σ는 기능 확인을 위해 만든 `assumed` 값이다.

| 항목 | 합성 pilot | 실제 제품 적용 방향 |
|---|---|---|
| mask별 overlay | 가정값 | Fab 실측 분포 사용 |
| mask별 CD | 가정값 | Fab 실측 분포 사용 |
| 두께 | 가정값 | 근거 확보 전 산포 0 |
| 이물 크기 변화 | 가정값 | Fab 이물 크기 분포와 역할을 구분한 뒤 적용 |
| 이물 중심 offset | 가정값 | 측정·모델 근거 확보 전 산포 0 |
| 접촉 보정거리 | 미사용 | 0 µm 고정 |
| 이물 형상 | 원형·구형 | 비원형 형상은 추후 검토 |

실제 제품의 첫 산포 계산은 보유한 mask별 overlay·CD 실측값을 우선 적용하고, 근거가 없는 산포는
0으로 두는 편이 결과 해석에 안전하다.

현재 YAML과 코드는 실제 Fab 데이터를 연결하기 전에 다음 보완이 필요하다.

- overlay x와 y에 서로 다른 평균·σ 입력
- x/y 상관관계 및 mask 간 상관관계 입력
- 기준 mask와 overlay 부호 정의
- CD 실측값이 전체 선폭 변화인지 한쪽 경계 이동량인지 구분
- 변수별로 `measured`와 `assumed` 근거를 각각 기록

### 그래프와 표 수정 방향

1. 그래프 제목의 `S_M1`은 “mask1 형성 후 이물 유입”으로 바꾼다.
2. 세로축은 “조건부 기하 확률” 대신 “64개 산포 조건 중 접촉 비율”로 표시한다.
3. 범례의 A__B·G__A·B__P는 A–B·G–A·B–P로 읽기 쉽게 바꾸고 short 유형을 함께 표시한다.
4. 그래프 아래에 “실제 불량확률 아님”을 직접 표시한다.
5. 산포 표는 “합성 검증용 가정값”이라는 제목을 붙인다.
6. 실제 제품에서는 overlay·CD 실측값을 사용하고 나머지 근거 없는 산포는 0으로 시작한다고 적는다.
7. 64조건은 수렴 완료값이 아니라 첫 비교점이며 128·256조건 비교가 남았음을 표시한다.

### 발표 스크립트 초안

“여섯 번째 페이지에서는 공정 산포가 hotspot과 CA에 어떻게 반영되는지 설명드리겠습니다.

기준 조건 계산은 하나의 고정된 mask와 stack에서 hotspot을 구합니다. 산포 계산에서는 overlay와 CD
같은 조건을 바꿔 동일한 계산을 반복합니다. 현재는 일반 난수를 무작위로 뽑는 방식이 아니라 산포
공간을 비교적 고르게 덮는 Sobol 표본을 사용합니다. 이번 합성 pilot에서는 64개 조건을 계산했습니다.

Sobol이 처음 만드는 값은 0에서 1 사이를 고르게 채우지만, 이 값을 정규분포의 역누적분포로
변환합니다. 따라서 실제 계산에 들어가는 overlay와 CD 변화량은 지정한 정규분포를 근사합니다.
Sobol은 정규분포를 없애는 것이 아니라 정규분포의 누적확률 구간을 고르게 선택하는 역할을 합니다.
다만 실제 Fab 분포가 정규분포가 아니거나 변수 사이에 상관관계가 있으면 그 분포와 상관구조를
추가로 반영해야 합니다.

그래프의 가로축은 이물 중심의 x 위치이고 세로축은 64개 산포 조건 중 그 위치가 hotspot이 된
비율입니다. 값이 1이면 모든 조건에서 접촉했고, 0.5면 64개 중 32개 조건에서 접촉했다는 뜻입니다.
이 값은 실제 Fab 불량확률 50%를 의미하지 않습니다.

hotspot 중심부는 대부분의 산포 조건에서 접촉하므로 1에 가깝습니다. 경계에서는 overlay와 CD 등에
따라 접촉 여부가 바뀌기 때문에 0과 1 사이의 계단형 값이 나타납니다. 이 위치별 접촉 비율에 픽셀
면적을 곱해 전체 영역에서 합산하면 산포가 반영된 평균 CA가 됩니다.

여러 전극 조합의 전체 CA는 전극 조합별 비율을 단순히 더하지 않습니다. 하나의 산포 조건 안에서
전극 조합별 hotspot을 먼저 합치고 겹친 위치를 한 번만 센 뒤, 그 결과를 64개 조건에 대해 평균합니다.

p05, p50, p95는 64개 조건에서 계산된 CA의 분포를 요약한 값입니다. 측정값의 신뢰구간이나 실제
불량률의 백분위는 아닙니다.

현재 표의 산포값은 모두 합성 검증을 위한 가정값입니다. 실제 제품 계산에서는 보유한 mask별 Fab
overlay와 CD 실측 분포를 먼저 적용합니다. 두께, 이물 크기 변화와 중심 offset처럼 아직 근거가 없는
항목은 우선 산포를 0으로 두고, 측정 근거가 확보될 때 하나씩 추가합니다. 접촉 보정거리는 0 µm로
고정하고 이물은 현재 원형으로 계산합니다.

64조건만으로 결과가 수렴했다고 판단하지는 않습니다. 같은 입력을 128개와 256개 조건으로 계산해
평균 CA 변화가 정한 허용 범위 안에 들어오는지 확인해야 합니다.”

### 6페이지에서 확정한 내용

1. **확정:** 실제 제품의 첫 계산은 Fab 실측 overlay·CD만 산포로 적용하고 나머지 미확정 변수는 고정값으로 둔다.
2. **구분:** 이물 Fab 데이터에서 작은 이물이 많고 큰 이물이 적은 것은 이물 크기별 발생 분포다. 이를 Sobol 산포 변수로 넣지 않고, 크기별 CA 계산이 끝난 뒤 크기 구간별 이물 밀도로 가중한다.
3. **미확인:** 이물 크기와 유입 공정·위치·기간 사이의 상관관계는 아직 확인하지 않았다. 우선 공통 크기 분포로 구조를 상대 비교하고, 추후 분리 가능한 Fab 데이터가 확보되면 공정별 분포로 확장한다.
4. **확정:** mask별 CD·overlay와 overlay x/y는 서로 독립으로 처리한다. x와 y의 평균·표준편차는 별도 입력할 수 있게 하고 독립 조건을 결과 manifest에 남긴다.
5. **표현 확정:** 그래프의 세로축은 “실제 불량확률”이 아니라 “입력 산포 조건 중 접촉 비율”로 표시한다.

### 권장 수렴 판정

첫 pilot은 같은 scramble seed를 사용한 중첩 Sobol 표본으로 64→128→256조건을 계산한다. 128조건은
64조건을 포함하고 256조건은 128조건을 포함해야 조건 수 증가 효과만 비교할 수 있다.

| 대상 | 권장 기준 |
|---|---|
| 중복 제거 전체 평균 CA | 128→256 상대 변화 1% 이하 또는 절대 변화 1픽셀 면적 이하 |
| 보고 대상 주요 전극 조합 평균 CA | 128→256 상대 변화 2% 이하 또는 절대 변화 1픽셀 면적 이하 |
| p05·p95를 의사결정에 사용할 경우 | 256→512 변화 5% 이하를 추가 확인 |

64→128 변화도 함께 기록하되 최종 판정은 더 많은 조건인 128→256 비교를 기준으로 한다. 기준을
넘으면 512조건으로 늘리고 256→512에서 같은 기준을 다시 적용한다. CA가 0에 가까우면 상대 변화가
불안정하므로 1픽셀 면적의 절대 기준을 사용한다.

최종 제품 pilot에서는 선택한 조건 수로 scramble seed를 3개 이상 바꾸어 반복하는 것을 권장한다.
seed별 중복 제거 전체 평균 CA의 최댓값과 최솟값 차이가 seed 평균의 1%를 넘으면 조건 수를 더
늘린다. 평균 CA가 0에 가까우면 이 비교도 1픽셀 면적의 절대 기준을 사용한다. 이는 일반 Monte
Carlo식 신뢰구간을 만드는 절차라기보다 특정 Sobol scramble에 결과가 민감하지 않은지 확인하는 검사다.

PDF와 그림 4는 전체 페이지 첨삭이 끝난 뒤 수정한다.

## 7페이지 · 시뮬레이션 결과에 Fab 이물 분포 적용

### 이 페이지가 전달하려는 핵심 메시지

> 먼저 이물 크기별 hotspot과 CA를 계산하고, 계산이 끝난 뒤 Fab에서 측정한 크기별 이물 밀도를 적용한다. 같은 공통 분포를 적용하면 구조를 상대 비교할 수 있고, 제품·공정에 연결된 실제 분포를 적용하면 예상 위험으로 확장할 수 있다.

Fab 이물 분포를 시뮬레이션 안에 섞어 한 번에 계산하지 않는다. 기하 계산 결과와 Fab 발생 분포를
분리해 두어야 같은 구조에 다른 Fab 분포를 적용하거나, 여러 구조에 동일한 분포를 적용해 비교할 수
있다.

### 확정한 계산 순서

1. mask, stack, 전극과 이물 유입 공정을 입력한다.
2. 2·4·6·8·10 µm처럼 정한 이물 크기마다 hotspot과 CA를 계산한다.
3. 이물 유입 공정·이물 크기·전극 조합 정보를 유지한 채 결과를 저장한다.
4. 구조 전체 비교에는 전극 조합이 겹친 위치를 한 번만 센 중복 제거 전체 CA를 선택한다.
5. 계산이 끝난 뒤 Fab의 공정별·크기 구간별 이물 밀도를 연결한다.
6. 공통 분포로 구조 상대 순위를 비교하거나 실제 제품 분포로 예상 위험을 계산한다.

이 순서에서는 Fab 이물 분포가 바뀌어도 기하 시뮬레이션을 다시 실행할 필요가 없다. 동일한 이물 크기
격자와 이물 유입 공정 매핑을 유지한 경우 저장된 CA에 새 분포를 다시 적용하면 된다.

### layer별 평균 이물 개수의 적용

보유한 Fab 자료는 layer별·이물 크기 구간별 평균 이물 개수다. 평균이 한 장 또는 한 검사 단위당
개수라면 해당 검사 단위의 면적을 함께 사용해 평균 밀도로 바꾼다.

\[
mean\ density_{l,b}=\frac{mean\ particle\ count_{l,b}}{inspection\ area\ per\ sample_l}
\quad [\text{개}/mm^2]
\]

여기서 \(l\)은 Fab 측정 layer, \(b\)는 이물 크기 구간이다. 검사 면적이 모든 layer와 sample에서
동일하면 평균 개수 자체를 구조 상대 비교용 weight로 사용할 수도 있지만, 예상 건수 형태로 계산하려면
반드시 면적 단위로 정규화해야 한다. 일반적으로 작은 이물 구간은 밀도가
높고 큰 이물 구간은 낮을 수 있다. 반대로 CA는 이물 크기가 커질수록 커지는 경향이 있으므로 어느
크기 구간이 전체 위험에 가장 많이 기여하는지는 두 값을 곱해야 알 수 있다.

\[
contribution_{l,b}=CA_{union,s(l),d(b)}[mm^2]\times mean\ density_{l,b}[\text{개}/mm^2]
\]

여기서 \(s(l)\)은 Fab 측정 layer에 연결한 시뮬레이션 이물 유입 공정이다. 전체 가중값은 모든 Fab
layer와 크기 구간의 기여를 더한다.

\[
\Lambda=\sum_{l,b} contribution_{l,b}
\]

### union CA의 정확한 범위

현재 `failure_mode=any`의 union CA는 **해당 layer에 그려진 전극 mask 전체의 합집합 면적**이 아니다.
한 이물 유입 공정과 이물 크기에서 선언된 lateral short·vertical short·open hotspot을 위치별로 OR한
CA다.

예를 들어 mask1 형성 후 들어온 이물이 mask1 안의 두 전극 사이 lateral short와, mask1 전극과 이후
mask2 전극 사이 vertical short를 모두 만들 수 있다면 두 hotspot을 함께 OR한다. 같은 이물 중심 위치가
두 불량을 동시에 만들더라도 한 번만 센다. 이 결과를 mask1의 평균 이물 개수에 연결한다.

따라서 Fab 적용의 주값은 다음과 같이 정의한다.

> Fab layer별 평균 이물 개수 × 그 layer에 연결된 이물 유입 공정의 모든 불량 중복 제거 union CA

원인 분석을 위해 lateral short는 전극 layer별, vertical short는 layer 조합별 union을 별도로 출력할
수 있지만, 이를 다시 더해 전체값을 만들면 hotspot 중복이 생길 수 있다.

### 두 가지 적용 목적

| 적용 방법 | 입력 분포 | 결과 해석 |
|---|---|---|
| 구조 상대 비교 | 비교할 모든 구조에 동일한 공통 이물 분포 | 동일 환경에서 어느 구조가 더 민감한지 보여주는 가중 CA 지수 |
| 실제 Fab 적용 | 제품군·Fab·공정에 연결된 실측 이물 밀도 | 해당 분포에서 예상되는 기하 위험값 |

공통 분포 적용을 먼저 수행한다. 이 단계의 목적은 Fab 환경 차이를 제거하고 구조 자체의 상대 위험을
비교하는 것이다. 실제 Fab 분포 적용은 공정과 제품 연결이 확정된 뒤 수행한다.

실제 밀도와 중복 제거 전체 CA를 곱한 \(\Lambda\)는 단위상 기대 건수 형태가 되지만, 즉시 실제
불량 건수나 수율로 해석해서는 안 된다. 한 이물이 여러 위치에 독립적으로 발생한다는 가정, 조사
면적과 제품 노출 면적의 대응, 이물의 전도성 및 실제 불량 전환율을 추가로 검증해야 한다.

### 크기 구간을 연결하는 권장 방법

첫 실제 적용에서는 Fab의 크기 구간마다 대표 이물 크기를 하나 정하고, 같은 크기로 시뮬레이션한다.

예:

| Fab 크기 구간 | 대표 크기 | 시뮬레이션 CA | 적용 밀도 |
|---|---:|---:|---:|
| 1–3 µm | 2 µm | CA(2 µm) | 해당 구간의 전체 밀도 |
| 3–5 µm | 4 µm | CA(4 µm) | 해당 구간의 전체 밀도 |
| 5–7 µm | 6 µm | CA(6 µm) | 해당 구간의 전체 밀도 |

한 크기 구간의 전체 밀도를 여러 시뮬레이션 직경에 반복 적용하면 이물 수를 중복 집계한다. 따라서
초기에는 **크기 구간 하나당 대표 직경 하나**를 사용한다. 구간 안에서 CA가 빠르게 변하면 Fab bin을
더 잘게 나누거나 구간 내 분포와 적분 규칙을 별도로 정의해야 한다. 관측 범위 밖의 크기는 임의로
외삽하지 않는다.

현재 코드의 `piecewise_constant`는 한 bin에 하나의 대표 직경이 연결될 때 사용한다. `exact_point`는
Fab 대표 크기와 시뮬레이션 크기가 정확히 같을 때 사용할 수 있다. `piecewise_linear`는 bin 전체
밀도의 의미와 보간 규칙이 명확하지 않으면 실제 적용에서 사용하지 않는 편이 안전하다. 원본 이물
표본을 직접 적용하는 `empirical_samples`는 아직 구현되지 않았다.

### 이물 유입 공정과 Fab 측정 공정의 연결

시뮬레이션의 “mask1 형성 후 이물 유입”과 Fab 데이터의 측정 공정 이름이 항상 같지는 않다. 따라서
문자열이 같다는 이유로 자동 연결하지 않고 다음 매핑을 명시해야 한다.

> 시뮬레이션 이물 유입 공정 → 적용할 Fab 측정 공정 → 해당 공정의 크기별 이물 밀도

현재 manifest에는 이를 위한 `fab_distribution_layer`가 있지만 가중 코드가 `source_step`으로 Fab
표를 직접 조회한다. 실제 적용 전에 `fab_distribution_layer`를 사용하도록 수정해야 한다.

### 현재 7페이지 결과의 한계

현재 막대그래프와 표는 실제 Fab 데이터가 아니라 합성 Fab 분포를 사용한다. 또한 `ca.parquet`의
전극 조합별 가중값을 더했기 때문에 같은 이물 중심 위치에서 여러 전극 조합이 겹치면 중복된다.
그러므로 현재의 0.0004416과 0.0005446은 제품 전체 위험값으로 사용할 수 없다.

구조 전체 비교에는 다음 값을 사용해야 한다.

> 이물 유입 공정별·이물 크기별 중복 제거 전체 산포 평균 CA × 동일한 공통 이물 분포

원인 분석이 필요할 때만 lateral short·vertical short·open 또는 전극 조합별 가중값을 별도로 본다.

### 그림 6 수정 방향

1. 현재 합성 Fab 막대그래프를 계산 순서 중심 그림으로 바꾼다.
2. `이물 크기별 시뮬레이션 → 중복 제거 전체 CA → Fab 크기별 밀도 적용 → 구조 상대 비교`를 왼쪽에서 오른쪽으로 표시한다.
3. 작은 이물은 밀도가 높고 CA가 작으며, 큰 이물은 밀도가 낮고 CA가 클 수 있다는 예를 나란히 표시한다.
4. 전극 조합별 단순합을 제품 전체 값으로 표시하지 않는다.
5. 실제 데이터가 들어오기 전까지 합성 가중 수치는 본문 대표 결과에서 제거하거나 “기능 시험용”으로만 표시한다.
6. 공통 분포와 실제 Fab 분포의 목적을 별도 상자로 구분한다.

### 발표 스크립트 초안

“일곱 번째 페이지에서는 시뮬레이션 결과에 Fab 이물 분포를 적용하는 순서를 설명드리겠습니다.

먼저 Fab 이물 개수와 관계없이 각 이물 크기의 hotspot과 CA를 계산합니다. 계산 결과는 이물 유입
공정과 크기별로 따로 저장합니다. 그 다음 Fab에서 측정한 layer별·크기 구간별 평균 이물 개수를 검사
면적으로 정규화해 연결합니다. 따라서
Fab 분포가 바뀌어도 같은 크기 조건이라면 기하 시뮬레이션을 다시 실행하지 않고 가중만 다시 적용할
수 있습니다.

Fab에서는 작은 이물이 많고 큰 이물이 적은 경향이 있습니다. 그러나 작은 이물은 CA가 작고 큰 이물은
CA가 클 수 있습니다. 어느 크기가 전체 위험에 더 많이 기여하는지는 크기별 CA와 이물 밀도를 곱해서
확인해야 합니다.

구조를 비교할 때는 모든 구조에 같은 공통 이물 분포를 적용합니다. 이렇게 하면 Fab 환경 차이를
제외하고 구조 자체의 상대적인 민감도를 비교할 수 있습니다. 제품과 공정의 실제 이물 분포가 확정되면
그 분포를 적용해 예상 위험으로 확장합니다.

구조 전체 대표값에는 전극 조합별 CA의 단순합을 사용하지 않습니다. union CA는 전극 mask의 합집합
면적이 아니라, 해당 이물 유입 공정에서 모든 불량 hotspot을 OR한 면적입니다. 하나의 이물 위치가
여러 전극 조합에 동시에 영향을 주어도 한 번만 세고, 이 결과에 해당 Fab layer의 평균 이물 밀도를
적용합니다. 전극 조합별 결과는 원인 분석용으로 유지합니다.

현재 페이지의 막대그래프와 숫자는 합성 Fab 자료로 기능 경로를 확인한 결과입니다. 실제 제품값이
아니며, 현재 코드는 전극 조합별 값을 합산해 중복될 수 있으므로 제품 전체 위험으로 해석할 수 없습니다.
실제 적용 전에는 중복 제거 전체 CA 가중과 이물 유입 공정에서 Fab 측정 공정으로의 명시적 매핑을
구현해야 합니다.”

### 7페이지에서 확정한 내용

1. **계산 순서:** 이물 크기별 시뮬레이션을 먼저 완료한 뒤 Fab 크기별 이물 분포를 적용한다.
2. **구조 비교:** 모든 구조에 동일한 공통 이물 분포를 적용한 중복 제거 전체 가중 CA를 사용한다.
3. **실제 적용:** 제품·공정 매핑이 확정된 뒤 실제 Fab 분포로 예상 위험을 계산한다.
4. **크기 연결:** 첫 적용은 Fab 크기 구간 하나당 대표 시뮬레이션 직경 하나를 사용한다.
5. **현재 수치:** 합성 Fab 및 전극 조합별 단순합 결과이므로 제품 전체 대표값으로 사용하지 않는다.
6. **Fab 입력:** 실제 자료는 layer별·크기별 평균 이물 개수이며, 예상 건수 계산에는 검사 단위 면적을 함께 보존한다.
7. **union 범위:** 주값은 전극 형상의 layer union이 아니라, Fab layer에 연결된 이물 유입 공정에서 모든 선언 불량 hotspot을 OR한 CA다.

PDF와 그림 6은 전체 페이지 첨삭이 끝난 뒤 수정한다.

## 8페이지 · 합성 검증 범위와 남은 검증

### 이 페이지가 전달하려는 핵심 메시지

> 자동 테스트와 합성 도형 검증으로 계산 규칙이 코드 의도대로 동작하는 것은 확인했다. 기존 현장 sim과의 동일 입력 비교 및 실제 제품·불량 데이터 검증은 아직 남아 있다.

이 페이지의 목적은 테스트 개수를 강조하는 것이 아니라 **무엇을 검증했고 무엇은 아직 검증하지
않았는지** 구분하는 것이다. 자동 테스트 통과는 구현 오류를 찾는 근거이지만 물리적 정확성이나 기존
sim 대체 가능성을 직접 증명하지 않는다.

### 검증 단계를 구분하는 표

| 단계 | 현재 상태 | 확인한 내용 | 아직 확인하지 못한 내용 |
|---|---|---|---|
| 코드 단위·입력 계약 | 통과 | 입력 오류, 단위 변환, 저장 형식과 계산 함수 | 실제 공정 물리 |
| 단순 합성 도형 | 통과 | 예상 위치, open 전수 계산, 중복 제거와 재현성 | 실제 mask 대표성 |
| 복합 합성 도형 | 통과 | 다중 전극·다층 중첩, 단조성, 음성 대조, TAT | 기존 sim과 실제 제품 일치 |
| 기존 현장 sim 동일 입력 비교 | 미수행 | 없음 | 공통 계산 대상의 hotspot·CA 일치와 신규 대각 CA |
| 실제 제품·불량 대조 | 미수행 | 없음 | hotspot 위치와 실제 불량 상관성, 예상 위험 보정 |

### 합성 검증에서 확인한 항목

#### 산포 0과 기준 조건의 일치

모든 산포를 0으로 두었을 때 산포 계산 경로의 hotspot과 CA가 기준 조건 계산과 같았다. 이는 산포
반복 코드가 산포가 없는 경우 기존 기준 계산을 바꾸지 않는다는 뜻이다. 실제 산포 모델이 정확하다는
증명은 아니다.

#### 같은 설정의 재현성

같은 입력과 같은 Sobol seed로 반복했을 때 위치별 접촉 비율 지도와 중복 제거 지도가 배열 단위로
같았다. 실행 시각과 run ID는 달라질 수 있으므로 전체 결과 폴더의 모든 byte가 같다는 뜻은 아니다.

#### open 전수 계산 대조

직선·우회·분기·ㄱ자 도형과 두 픽셀 축척에서 모든 이물 중심을 하나씩 직접 계산한 결과와 구현 결과를
비교했다. 8개 조건 모두 불일치 위치가 0개였다. 예를 들어 첫 직선 도형에는 open hotspot 168개가
있었고, 구현과 전수 계산이 다르게 판정한 위치가 0개였다. 따라서 `0 px`는 hotspot이 없다는 뜻이
아니다.

#### 이물 크기 단조성

같은 고정 형상과 가정에서 이물 크기가 커질 때 작은 이물의 hotspot이 큰 이물의 hotspot 안에
포함되는지 확인했다. 이는 거리 계산이나 크기 순서 처리 오류를 찾기 위한 합성 불변조건이다.

#### 대각 전극 위치 변화

상부 전극을 x 방향으로 이동한 합성 도형에서 대각 hotspot의 중심 위치도 같은 방향으로 이동했다.
대각거리 계산이 전극 위치 변화를 반영한다는 정성 검증이며, 절대 CA의 물리 정확성을 증명하지는 않는다.

#### 중복 제거

전극 조합별 hotspot을 픽셀 OR한 결과와 저장된 중복 제거 전체 지도가 같은지 확인했다. hotspot이
겹치면 중복 제거 전체 CA가 전극 조합별 단순합보다 작고, 겹치지 않으면 두 값이 같았다.

### 내부 xy kernel 참고값과 기존 현장 sim의 구분

현재 페이지 아래쪽의 kernel quantization·kernel shape 표는 저장소 내부의 xy 형태학 kernel과 거리
변환 계산을 비교한 작은 probe다. 외부 기존 현장 sim을 실행해 비교한 결과가 아니다.

- 차이 픽셀 3·30·20: 두 내부 계산이 다르게 표시한 위치 수
- kernel quantization: 직경을 pixel 반복 횟수로 바꾸면서 생긴 차이
- kernel shape: 사각형·원형 kernel 모양에서 생긴 차이
- 미분류 0: 이 작은 probe의 차이가 두 규칙으로 모두 설명됐다는 뜻

이 표를 “기존 방식 검증”이라고 부르면 외부 기존 sim과 비교를 완료한 것으로 오해할 수 있다. 본문에서는
제거하거나 “내부 xy kernel 차이 분류”로 이름을 바꾸고 세부 내용은 부록으로 옮긴다.

### 기존 현장 sim과 비교할 때의 기준

기존 sim도 높이를 반영한 2.5D 계산이다. 따라서 다음 두 결과를 분리한다.

1. **공통 계산 대상:** 기존 sim과 현재 구현이 모두 계산하는 전극 조합은 같은 입력으로 hotspot 위치와 CA를 직접 비교한다.
2. **신규 대각 전극 조합:** G–A처럼 기존 sim이 계산하지 않은 조합은 기존값을 0으로 놓지 않고 `N/A` 또는 신규 계산으로 표시한다.

공통 계산 대상의 차이는 좌표계, 픽셀 크기, 경계 처리, 이물 크기 해석과 거리 규칙으로 원인을
분류한다. 신규 대각 전극 조합은 추가된 CA를 별도로 보고하고, 제품 전체 영향은 중복 제거 전체 CA로
계산한다.

### 페이지 수정 방향

1. 상단의 테스트 개수와 실행 시간은 최종 코드 수정 후 다시 실행한 값으로 갱신한다.
2. 테스트 개수보다 `합성 검증 완료 / 기존 sim 대조 미완료 / 실제품 검증 미완료`를 먼저 표시한다.
3. `open 차이 0 px`는 “hotspot 존재, 전수 계산과 불일치 0개”로 풀어 쓴다.
4. “기존 형태학·EDT”는 “내부 xy kernel 참고 비교”로 변경한다.
5. kernel 차이 상세 표는 부록으로 이동하고 본문에는 검증 단계 표를 둔다.
6. 실제 제품 물리 정확성을 증명하지 않았다는 제한을 페이지 상단에 표시한다.

### 발표 스크립트 초안

“여덟 번째 페이지에서는 지금까지 완료한 검증과 아직 남은 검증을 구분해서 설명드리겠습니다.

현재 자동 테스트와 합성 도형 검증은 통과했습니다. 입력 오류 처리, 산포가 0일 때 기준 조건과의 일치,
같은 Sobol seed의 재현성, 이물 크기에 따른 hotspot 포함 관계, 전극 조합 중복 제거를 확인했습니다.

open은 직선, 우회, 분기와 ㄱ자 도형에서 모든 이물 중심을 하나씩 직접 계산한 결과와 비교했습니다.
8개 도형·축척 조건에서 불일치 위치는 0개였습니다. 예를 들어 직선 도형에는 open hotspot이 168개
있었고, 구현이 전수 계산과 다르게 판단한 위치가 0개였습니다.

대각거리 계산은 상부 전극을 x 방향으로 옮기면 hotspot도 같은 방향으로 움직이는지 확인했습니다.
이는 대각 전극 위치를 계산에 반영한다는 검증이며 실제 제품 CA의 정확성을 증명하는 것은 아닙니다.

현재 페이지의 kernel 차이 표는 저장소 안의 두 계산 규칙을 비교한 결과입니다. 기존 현장 sim을 실행한
결과가 아닙니다. 기존 sim도 높이를 반영한 2.5D 방식이므로 실제 대체 검증은 동일 제품 입력에서
공통 전극 조합의 hotspot과 CA를 직접 비교해야 합니다. 기존 sim에 없던 G–A 같은 대각 조합은 기존값
0으로 비교하지 않고 이번에 새로 계산된 위험으로 분리합니다.

따라서 현재 결론은 합성 형상에서 계산 계약과 구현 일관성을 확인했다는 것입니다. 기존 현장 sim과의
동일 입력 대조와 실제 제품·불량 데이터 검증은 아직 남아 있습니다.”

### 8페이지에서 확정할 표현

1. 자동 테스트 통과는 코드 검증이며 실제 공정 물리 검증이 아니다.
2. 내부 `legacy_failure`는 기존 현장 sim 결과가 아니다.
3. 기존 sim 공통 계산 대상과 신규 대각 전극 조합을 분리해 비교한다.
4. 실제품 검증 전에는 “대체 완료”, “정확도 개선 완료”라고 표현하지 않는다.

PDF는 전체 페이지 첨삭과 코드 수정이 끝난 뒤 테스트를 다시 실행해 갱신한다.

## 9페이지 · CA 결과와 중복 제거

### 이 페이지가 전달하려는 핵심 메시지

> CA는 해당 크기의 이물 중심이 불량을 만들 수 있는 위치의 면적이다. 전극 조합별 CA는 원인 분석에 사용하고, 구조 전체 비교에는 겹친 위치를 한 번만 센 중복 제거 전체 CA를 사용한다.

이 페이지의 모든 값은 합성 도형의 결과다. 실제 제품 CA나 Fab 불량률이 아니며 기존 현장 sim과의
대조 결과도 아니다.

### CA 숫자의 의미

산포 미적용 기준 조건에서 hotspot은 0 또는 1인 이물 중심 후보 지도다. CA는 hotspot 픽셀 수에
픽셀 면적을 곱한 값이다.

\[
CA=\sum_{x,y}H(x,y)\times pixel\ area
\]

예를 들어 CA가 350 µm²라는 것은 실제로 손상된 전극 면적이 350 µm²라는 뜻이 아니다. ROI 안에서
이물 중심을 놓았을 때 해당 불량 조건을 만드는 후보 위치의 면적이 350 µm²라는 뜻이다.

현재 pilot ROI는 100×100 µm이므로 전체 면적은 10,000 µm²다. CA 350 µm²는 ROI 면적의 3.5%에
해당하지만, 이것도 이물 위치가 균일하다는 단순 조건에서의 기하 비율이며 실제 불량확률은 아니다.

### 위쪽 CA 표 읽는 방법

표는 직경 10 µm 이물의 결과를 이물 유입 공정별로 보여준다.

| 이물 유입 공정 | A–B lateral short | G–A vertical short | B–P vertical short | 중복 제거 전체 CA |
|---|---:|---:|---:|---:|
| mask1 형성 후 | 700 µm² | 350 µm² | 700 µm² | 1,750 µm² |
| mask2 형성 후 | 100 µm² | 0 µm² | 400 µm² | 500 µm² |
| 평탄화 후 | 0 µm² | 0 µm² | 0 µm² | 0 µm² |

이물 유입 시점이 달라지면 이물이 놓이는 표면 높이와 이미 형성된 전극, 이후 형성될 전극이 달라지므로
CA도 달라진다.

- mask1 형성 후 G–A 350 µm²는 기존 현장 sim에 있던 값의 증가·감소가 아니라, 이번 대각거리 계산에서 새로 추가된 전극 조합의 CA다.
- mask2 형성 후 G–A가 0인 것은 이 합성 형상과 현재 후속 전극 가정에서 hotspot이 없었다는 뜻이다.
- 평탄화 후 값이 모두 0인 것도 이 합성 조건의 결과이며 해당 실제 공정이 안전하다는 뜻이 아니다.
- 이 표에서는 세 전극 조합의 hotspot이 서로 겹치지 않아 전극 조합별 CA 합과 중복 제거 전체 CA가 같다.

### 전극 조합별 단순합과 중복 제거 전체 CA

전극 조합별 CA 단순합은 다음과 같다.

\[
CA_{sum}=\sum_p CA_p
\]

구조 전체 CA는 hotspot 지도를 먼저 OR한 뒤 면적을 계산한다.

\[
CA_{union}=Area\left(\bigvee_p H_p\right)
\]

따라서 항상 \(CA_{union}\le CA_{sum}\)이다. 같은 이물 중심 위치가 여러 전극 조합을 동시에 만들면
단순합은 그 위치를 여러 번 세지만 중복 제거 전체 CA는 한 번만 센다.

`triple_overlap` 합성 도형의 예시는 다음과 같다.

- mask2 형성 후, 10 µm: 중복 제거 전체 CA 350 µm², 전극 조합별 단순합 650 µm²
- 두 값의 차이 300 µm²는 여러 전극 조합에서 중복된 후보 위치의 효과다.
- mask2 형성 후, 6 µm: 두 값이 모두 200 µm²이므로 이 조건에서는 hotspot 중복이 없다.

구조 간 전체 위험 비교와 Fab 가중에는 중복 제거 전체 CA를 사용하고, 어떤 전극 조합이 원인인지
분석할 때 전극 조합별 CA를 사용한다.

### 왼쪽 크기별 CA 그래프의 문제와 수정 방향

현재 그래프의 실선은 대각거리를 적용한 현재 계산이고 점선은 저장소 내부의 xy kernel 참고값이다.
점선을 “기존 방식”이라고 표시하면 외부 기존 현장 sim 결과로 오해할 수 있다. 특히 G–A는 기존 sim의
계산 대상이 아니었으므로 두 선을 기존 대비 증감으로 비교하면 안 된다.

최종 그래프는 다음처럼 수정한다.

1. 내부 xy kernel 점선을 본문 그래프에서 제거한다.
2. 현재 계산의 A–B, G–A, B–P 크기별 CA만 표시한다.
3. G–A에는 “신규 대각 전극 조합”이라고 표시한다.
4. 필요하면 내부 xy kernel 비교는 8페이지 부록 항목으로 이동한다.
5. 제목의 `S_M1`은 “mask1 형성 후 이물 유입”으로 바꾼다.
6. 전극 조합 이름 옆에 lateral short 또는 vertical short를 표시한다.

### 산포가 반영된 CA 표 읽는 방법

현재 A–B, mask1 형성 후, 10 µm 합성 예시는 다음과 같다.

| 값 | 결과 | 의미 |
|---|---:|---|
| 기준 조건 CA | 700 µm² | 산포를 적용하지 않은 한 가지 형상 |
| 산포 조건 평균 CA | 650.78 µm² | 64개 가정 산포 조건 CA의 평균 |
| p05 | 557.5 µm² | 조건별 CA 분포의 하위 5% 지점 |
| p95 | 750 µm² | 조건별 CA 분포의 상위 5% 지점 |

평균이 기준 조건보다 작게 나온 것은 이 합성 산포 조합의 결과다. 산포를 넣으면 CA가 항상 작아진다는
뜻이 아니며 형상과 분포에 따라 커지거나 작아질 수 있다. 현재 산포값은 Fab 실측값이 아니므로 구조
결론에도 사용하지 않는다. 실제 제품 비교에서는 Fab 실측 overlay·CD와 수렴 조건을 적용한 평균 CA를
대표값으로 사용한다.

### 페이지 수정 방향

1. 제목을 “이물 유입 시점별 CA와 중복 제거 효과”로 바꾼다.
2. `S_M1`, `S_M2`, `S_PLN`을 mask1 형성 후, mask2 형성 후, 평탄화 후로 표시한다.
3. A__B 같은 내부 ID는 A–B와 short 유형으로 표시한다.
4. 왼쪽 그래프에서 내부 xy kernel 점선을 제거한다.
5. G–A 350 µm²는 기존 대비 감소값이 아니라 신규 대각 CA라고 표시한다.
6. 오른쪽 그래프는 중복 제거 전체 CA와 전극 조합별 단순합의 차이를 유지한다.
7. 산포 표에는 “합성 가정 산포 64조건·수렴 미확정”을 표시한다.

### 발표 스크립트 초안

“아홉 번째 페이지에서는 CA 숫자를 어떻게 읽어야 하는지 설명드리겠습니다.

CA는 실제로 손상된 전극 면적이 아닙니다. 해당 크기의 이물 중심을 ROI 안에 놓았을 때 short나 open을
만들 수 있는 후보 위치의 면적입니다. 예를 들어 G–A의 CA 350 µm²는 이물 중심 후보 영역의 면적이
350 µm²라는 뜻입니다.

위 표는 직경 10 µm 이물의 결과입니다. mask1 형성 후에는 A–B lateral short가 700 µm², G–A
vertical short가 350 µm², B–P vertical short가 700 µm²입니다. G–A는 기존 sim 결과가 줄어든 것이
아니라 기존 계산 대상에 없었던 대각 전극 조합의 CA가 새로 계산된 것입니다.

이물 유입 시점이 mask2 이후나 평탄화 이후로 바뀌면 이물이 놓이는 표면과 접촉 가능한 전극이 달라져
CA도 변합니다. 평탄화 이후 값이 0인 것은 이 합성 구조와 가정에서 hotspot이 없었다는 뜻이며 실제
공정이 안전하다는 의미는 아닙니다.

구조 전체 CA는 전극 조합별 CA를 단순히 더하지 않습니다. 같은 위치가 여러 전극 조합의 hotspot이면
단순합은 그 위치를 여러 번 셉니다. 오른쪽 합성 예시에서 10 µm 이물의 전극 조합별 합은 650 µm²지만,
겹친 위치를 한 번만 세면 전체 CA는 350 µm²입니다. 구조 비교와 Fab 가중에는 이 중복 제거 전체 CA를
사용합니다.

아래 산포 표에서 기준 조건 CA는 700 µm²이고 64개 조건의 평균은 650.78 µm²입니다. p05와 p95는
입력한 산포 조건에서 CA가 변한 범위를 요약합니다. 현재 산포는 합성 가정값이므로 실제 제품 결론으로
사용하지 않습니다. 실제 비교에서는 Fab 실측 overlay·CD를 넣고 수렴을 확인한 평균 CA를 사용합니다.”

### 9페이지에서 확정할 해석

1. CA는 손상 면적이 아니라 불량을 만드는 이물 중심 후보 위치의 면적이다.
2. G–A 350 µm²는 기존 대비 변화가 아니라 새로 추가된 대각 전극 조합 결과다.
3. 전체 비교와 Fab 가중은 중복 제거 전체 CA를 사용한다.
4. 전극 조합별 CA는 원인 분석용으로 유지한다.
5. 합성 산포 평균과 백분위는 실제 제품 결과로 해석하지 않는다.

PDF와 그래프는 전체 페이지 첨삭이 끝난 뒤 수정한다.

## 10페이지 · 2차 합성 시험 — 다중 전극과 다층 중첩

### 이 페이지가 전달하려는 핵심 메시지

> 한 mask에 여러 전극이 있고 서로 다른 mask가 복잡하게 겹치는 합성 형상에서도 선언한 lateral short·vertical short, 중복 제거와 CA 계산이 일관되게 동작하는 것을 확인했다. 실제 제품과 기존 현장 sim의 검증 결과는 아니다.

이 시험은 첫 pilot보다 복잡한 입력에서 계산 코드가 깨지지 않는지 확인하기 위해 만들었다. 실제 제품
형상을 복사한 것이 아니라 필요한 반례를 한 입력에 넣은 합성 시험이다.

### 입력 형상

| 항목 | 2차 합성 시험 |
|---|---|
| 이미지 크기 | 200×200 px |
| 축척과 ROI | 0.5 µm/px, 100×100 µm |
| mask1 | 전극 3개 |
| mask2 | 전극 4개 |
| mask3 | 전극 3개 |
| 전체 전극 | 10개 |
| 평가 전극 조합 | 16개: lateral short 6개, vertical short 10개 |
| 이물 유입 공정 | 3개 |
| 이물 크기 | 2·4·6·8·10 µm |
| 계산 범위 | 산포 미적용 short |
| 제외 | open, overlay·CD 산포, Fab 이물 분포 |

형상에는 L자와 T자 분기, 좁은 간격, 하나의 전극에 속한 떨어진 섬, mask 간 완전 정렬·부분 중첩과
대각 교차를 포함했다. 같은 mask 안에 여러 전극이 있고 다른 mask 전극과 여러 위치에서 겹치도록
구성했다.

### 그림 9를 읽는 방법

현재 그림은 mask별 전극 형상을 한 평면에 겹쳐 보여준다. 다중 전극과 xy 중첩은 확인할 수 있지만
전극 ID와 mask 높이가 작게 보여 어떤 전극이 lateral short 또는 vertical short 대상인지 알기 어렵다.

최종 그림은 다음처럼 수정한다.

1. M1·M2·M3 표기를 mask1·mask2·mask3으로 바꾼다.
2. mask별 개별 평면도 세 개와 전체 중첩도 하나를 함께 표시한다.
3. 각 전극 형상 안이나 가까이에 G1·G2·D1 등의 ID를 표시한다.
4. 같은 mask 전극 조합은 lateral short, 다른 mask 전극 조합은 vertical short라는 범례를 둔다.
5. 완전 정렬·부분 중첩·대각 교차의 대표 위치에 표시선을 넣는다.
6. 색만으로 구분하지 않고 선 모양이나 label을 함께 사용한다.

복잡한 형상을 모두 3D로 겹치면 전극과 ID가 가려질 수 있다. 3페이지에서 mask 높이를 3D 개념도로
설명하고, 이 페이지에서는 mask별 평면도와 전체 중첩도를 사용하는 편이 실제 형상을 읽기 쉽다.

### 그림 10의 의미와 수정 필요 사항

현재 그림 10은 mask1 형성 후 유입된 직경 10 µm 이물에 대해 G2–D3 vertical short를 보여준다.
G2는 mask1, D3는 mask2에 있으며 대각 방향으로 가까운 전극 조합이다.

현재 첫 패널의 “기존 방식 hotspot”은 외부 기존 현장 sim 결과가 아니라 저장소 내부 xy kernel
참고값이다. 이 표현은 제거한다. 최종 그림은 다음 세 패널로 구성한다.

1. G2와 D3의 입력 형상 및 mask 높이 관계
2. 현재 대각거리 계산의 vertical short hotspot
3. 전극 조합의 접촉 여유 지도

hotspot은 이물이 놓인 실제 위치가 아니라 이물 중심 후보 위치이며, 접촉 여유가 0 이상인 영역과
hotspot 경계가 일치하는지도 함께 표시한다.

### 자동 대조 결과의 의미

#### 계획한 vertical short 양성 대조

mask1 형성 후, 직경 10 µm 조건에서 기하상 접촉하도록 설계한 vertical short 전극 조합 8개가 모두
0보다 큰 hotspot을 만들었다. 이는 대각·정렬·부분 중첩 형상이 계산에서 누락되지 않았다는 뜻이다.
실제 전기적 short가 확인됐다는 뜻은 아니다.

#### 먼 거리 음성 대조

의도적으로 멀리 배치한 G1–D4와 G3–D3은 hotspot이 0이었다. 가까운 전극만 양성으로 나오는지
확인하기 위한 음성 대조다.

#### 이물 크기 단조성

선언한 모든 이물 유입 공정과 전극 조합에서 2→4→6→8→10 µm로 이물이 커질 때 기존 hotspot이
사라지는 경우가 없었다. 위반 건수는 0이었다.

#### 중복 제거와 동시 영향 전극 조합 수

각 조건에서 전극 조합별 hotspot을 직접 OR한 결과와 저장된 중복 제거 지도가 같았다. 한 이물 중심
위치에서 동시에 hotspot이 된 전극 조합은 최대 4개였다. 이 결과는 복합 형상에서 중복 제거 로직이
실제로 사용됐음을 보여준다.

#### CA 적분

hotspot 픽셀 수×0.25 µm²로 직접 계산한 값과 저장된 CA의 최대 차이는 0 µm²였다. 이는 픽셀 면적
적분과 표 저장이 일치한다는 뜻이며 물리 모델의 정확성을 뜻하지 않는다.

#### 내부 xy kernel 차이

2,911개 차이 픽셀은 외부 기존 sim 비교값이 아니다. 저장소 내부 xy kernel과 거리변환 참고 계산의
차이며 kernel 모양과 양자화 규칙으로 분류됐다. 8페이지에서 설명한 것처럼 본문 검증 결과에서는
제외하고 부록 근거로만 남긴다.

### 이 시험으로 아직 확인하지 않은 것

- 기존 현장 sim과 동일 입력의 hotspot·CA 비교
- 실제 제품 mask에서의 결과
- Fab 실측 overlay·CD 산포
- open과 산포 계산의 TAT
- layer mask에서 전극 합집합을 제외하고 남는 TR 영역
- 선언하지 않은 전극 조합을 자동으로 찾아 누락을 경고하는 기능
- 비원형 이물과 전도성·비전도성 차이

현재 코드는 전극 mask 합집합과 layer mask의 완전 일치를 요구하므로 이번 fixture에도 별도 TR 잔여
영역이 없다. 부분집합 검증으로 코드를 수정한 뒤 TR 영역이 남는 합성 입력을 추가하되, TR의 전기적
기능은 계산하지 않고 미반영 제한으로 기록한다.

또한 전극 조합 16개는 manifest에 직접 선언한 목록이다. 가능한 모든 조합의 누락을 자동으로 검사한
결과가 아니므로 실제 제품 적용 전에 전극 조합 누락 검사 기능을 추가해야 한다.

### 발표 스크립트 초안

“열 번째 페이지에서는 첫 pilot보다 복잡한 2차 합성 시험을 설명드리겠습니다.

입력 크기는 200×200 픽셀이고 mask1에 전극 3개, mask2에 4개, mask3에 3개를 배치했습니다. 전체
전극은 10개이며 lateral short 6개와 vertical short 10개, 총 16개 전극 조합을 계산했습니다.
형상에는 L자와 T자 분기, 좁은 간격, 떨어진 섬, mask 간 정렬·부분 중첩과 대각 교차를 포함했습니다.

이 시험은 산포 미적용 short 계산에 한정했습니다. open, overlay·CD 산포와 Fab 이물 분포는 포함하지
않았습니다.

mask1 형성 후 직경 10 µm 조건에서 양성이 되도록 설계한 vertical short 조합 8개는 모두 hotspot이
나왔고, 의도적으로 멀리 둔 두 조합은 0이었습니다. 모든 조건에서 이물이 커질 때 기존 hotspot이
사라지는 경우는 없었습니다.

한 이물 중심 위치에서 동시에 최대 네 개 전극 조합이 hotspot이 됐습니다. 전극 조합별 결과를 직접
합친 지도와 중복 제거 전체 결과가 일치했고, hotspot 픽셀 수로 다시 계산한 CA와 저장된 CA의 차이도
0이었습니다.

이 결과는 여러 전극과 여러 mask가 겹친 합성 형상에서 선언한 계산 규칙이 일관되게 동작한다는
검증입니다. 기존 현장 sim이나 실제 제품과 비교한 결과는 아닙니다. 현재 fixture에는 별도 TR 잔여
영역도 없으며, 전극 조합 16개는 자동 생성이 아니라 직접 선언한 목록입니다. 이 두 항목은 실제 제품
입력 전에 코드 보완과 추가 시험이 필요합니다.”

### 10페이지에서 확정할 해석

1. 여러 전극과 mask 간 복합 중첩은 현재 2차 합성 시험에 포함돼 있다.
2. 시험 범위는 산포 미적용 short이며 open·산포·Fab은 제외됐다.
3. 양성·음성 대조, 크기 단조성, 중복 제거와 CA 적분이 통과했다.
4. TR 잔여 영역과 전극 조합 자동 누락 검사는 아직 포함되지 않았다.
5. 외부 기존 sim과 실제 제품 대조는 아직 수행하지 않았다.

PDF와 그림 9·10은 전체 페이지 첨삭이 끝난 뒤 수정한다.

## 11페이지 · 2차 합성 시험 TAT와 메모리

### 이 페이지가 전달하려는 핵심 메시지

> 산포 미적용 short 계산에서 이미지 크기와 전극·전극 조합 수가 증가하면 TAT와 메모리가 증가했다. 복합 1000×1000 입력은 13.48초와 최대 RSS 745.1 MB였으며, 이 값에는 open과 Sobol 산포 계산이 포함되지 않는다.

TAT는 명령을 시작해 결과 저장을 마칠 때까지의 wall time이다. 계산 함수만의 시간이 아니라 입력
로딩, 거리 계산, CA 집계와 Zarr·Parquet 저장 시간이 포함된다.

### 측정 조건

- 장비: Mac mini M4 Pro
- 실행: 1회 워밍업 후 5회 반복
- TAT: 5회 wall time의 중앙값
- 메모리: 5회 중 프로세스 최대 RSS
- 공통 조건: 이물 유입 공정 3개, 이물 크기 5개
- 포함: 산포 미적용 lateral short·vertical short와 결과 저장
- 제외: open, overlay·CD 산포, Fab 이물 분포 적용

같은 실행을 반복한 wall time 변동계수는 약 0.3~1.3%로 작았다. 따라서 현재 장비와 합성 입력에서
반복 측정값은 안정적이었다. 다른 PC나 병렬 부하가 있는 환경으로 그대로 일반화할 수는 없다.

### 측정 결과

| 입력 | 전극 / 전극 조합 | TAT 중앙값 | 최대 RSS | 출력 크기 |
|---|---:|---:|---:|---:|
| pilot 200×200 | 4 / 3 | 1.24초 | 196.4 MB | 0.08 MB |
| 복합 200×200 | 10 / 16 | 2.24초 | 218.5 MB | 14.00 MB |
| pilot 1000×1000 | 4 / 3 | 3.36초 | 420.5 MB | 0.95 MB |
| 복합 1000×1000 | 10 / 16 | 13.48초 | 745.1 MB | 65.16 MB |

### 전극·전극 조합 증가의 영향

같은 1000×1000 크기에서 pilot은 전극 4개와 전극 조합 3개이고, 복합 입력은 전극 10개와 전극
조합 16개다.

- TAT: 3.36초 → 13.48초, 약 4.01배
- 최대 RSS: 420.5 MB → 745.1 MB, 약 1.77배

전극 조합 수는 약 5.33배지만 TAT는 약 4.01배 증가했다. 각 이물 유입 공정·크기에서 전극별 접촉
지도를 전극 조합 사이에 공유하므로 전극 조합 수에 정확히 비례하지 않는다. 다만 복합 형상과 전극
수가 함께 바뀌었기 때문에 이 측정만으로 전극 하나 또는 전극 조합 하나의 단위 비용을 분리할 수는 없다.

### 이미지 크기 증가의 영향

복합 입력을 200×200에서 1000×1000으로 늘리면 픽셀 수는 25배가 된다. 이 시험에서는 같은 200×200
형상을 5×5로 반복해 픽셀 크기와 국부 간격을 유지했다.

- TAT: 2.24초 → 13.48초, 약 6.02배
- 최대 RSS: 218.5 MB → 745.1 MB, 약 3.41배
- 저장 파일: 14.00 MB → 65.16 MB, 약 4.66배

증가율이 픽셀 수 25배와 같지 않은 이유는 프로세스 시작, 입력 검사와 메타데이터 저장 같은 고정 비용,
전극별 거리 지도 재사용, 배열 압축의 영향을 함께 받기 때문이다. 이 결과로 더 큰 이미지의 TAT를
단순 선형 외삽하면 안 된다.

### 출력 크기 해석

출력 크기는 Zarr 압축 후 실제 파일 크기의 합이다. hotspot 형태, 접촉 여유 값의 변화, 전극 조합 수와
chunk 구성에 따라 압축률이 달라진다. 따라서 출력 크기 배율은 계산량이나 원시 배열 크기의 배율과
같지 않다.

복합 200×200 출력이 pilot 200×200보다 크게 증가한 것도 전극 조합 수뿐 아니라 복잡한 접촉 여유
지도가 압축되는 정도가 달라졌기 때문이다. 실제 제품 적용 전에는 논리 배열 크기와 디스크 저장 크기를
분리해 다시 측정해야 한다.

### 현재 값에 포함되지 않은 비용

- open 후보별 배선 연결성 검사
- Sobol 64·128·256조건 반복
- 여러 Sobol scramble seed 반복
- Fab 이물 분포 적용
- 기존 현장 sim 비교 파일 변환과 픽셀 대조
- 1000×1000보다 큰 실제 제품 ROI
- 코드 수정 후 추가될 TR 잔여 영역 검증과 전극 조합 누락 검사

따라서 13.48초를 전체 제품 분석 TAT로 사용하면 안 된다. 현재 값은 **1000×1000 복합 합성 입력의
산포 미적용 short 계산 TAT**다.

### 그래프 정리 방향

앞서 항목이 많아 깨졌던 그래프는 다음 기준으로 단순화한다.

1. 그래프는 TAT와 최대 RSS 두 패널만 유지한다.
2. 각 패널에는 pilot 200×200, 복합 200×200, pilot 1000×1000, 복합 1000×1000 네 막대만 둔다.
3. 출력 크기와 배율은 그래프에 추가하지 않고 표 또는 부록으로 이동한다.
4. 막대 위 숫자는 소수점 한 자리까지만 표시한다.
5. `200²`, `1000²` 대신 `200×200`, `1000×1000`으로 표시한다.
6. 그래프 제목에 “산포 미적용 short·open 제외”를 표시한다.
7. 가장 중요한 복합 1000×1000의 13.48초·745.1 MB를 강조색으로 표시한다.

현재 두 패널 구조는 유지할 수 있지만, 아래의 세 가지 배율 표는 본문에서 제거하거나 핵심 비교 두
개만 문장으로 남겨 정보 밀도를 줄인다.

### 발표 스크립트 초안

“열한 번째 페이지에서는 복합 형상과 이미지 크기가 TAT와 메모리에 미치는 영향을 설명드리겠습니다.

모든 조건은 같은 Mac mini M4 Pro에서 한 번 워밍업한 뒤 다섯 번 실행했습니다. 시간은 명령 시작부터
결과 저장까지의 중앙값이고, 메모리는 다섯 번 중 가장 큰 RSS입니다. 이물 유입 공정 세 개와 이물
크기 다섯 개를 계산했으며 open과 산포 반복은 포함하지 않았습니다.

1000×1000 크기에서 단순 pilot은 3.36초, 복합 입력은 13.48초였습니다. 전극은 4개에서 10개로,
전극 조합은 3개에서 16개로 증가했고 TAT는 약 4배 늘었습니다. 접촉 지도를 전극 조합 사이에서
재사용하기 때문에 전극 조합 수에 정확히 비례하지는 않습니다.

복합 입력을 200×200에서 1000×1000으로 확대하면 픽셀 수는 25배지만 TAT는 약 6배, 최대 메모리는
약 3.4배 증가했습니다. 고정 실행 비용, 배열 재사용과 압축이 함께 포함되므로 이 결과를 더 큰 입력에
단순 비례로 외삽할 수는 없습니다.

현재 가장 중요한 측정값은 복합 1000×1000 기준의 13.48초와 745.1 MB입니다. 다만 이것은 산포
미적용 short 계산만의 값입니다. open, Sobol 반복과 실제 제품 크기를 포함한 전체 TAT는 별도로
측정해야 합니다.”

### 11페이지에서 확정할 해석

1. 복합 1000×1000 산포 미적용 short TAT는 13.48초, 최대 RSS는 745.1 MB다.
2. 이 값에는 open·산포·Fab 가중이 포함되지 않는다.
3. 전극 수와 전극 조합 수가 함께 변했으므로 각각의 비용을 독립적으로 추정한 결과는 아니다.
4. 1000×1000보다 큰 실제 ROI는 별도 측정이 필요하다.
5. 그래프는 TAT·RSS 두 패널과 각 네 막대로 제한한다.

PDF와 그림 11은 전체 페이지 첨삭과 코드 수정이 끝난 뒤 같은 조건으로 다시 측정해 갱신한다.

## 12페이지 · 기존 대형·산포 성능 실측의 해석

### 이 페이지가 전달하려는 핵심 메시지

> 기존 1000×1000 실행으로 대형 입력과 64조건 산포 계산이 실제로 완료되는 것은 확인했다. 그러나 두
> 결과는 단일 실행이고 입력 조건도 서로 다르므로 성능 배수나 최종 제품 TAT의 기준으로 사용할 수 없다.
> 실제 제품 조건에 맞춘 공통 입력과 반복 측정으로 산포 기준선을 다시 만들어야 한다.

이 페이지의 16.07초와 102.25초는 실패하지 않고 실행된 과거 참고 기록이다. 11페이지처럼 입력 복잡도
효과를 비교하기 위해 통제한 benchmark는 아니다.

### 저장된 두 실행의 정확한 조건

| 실행 | 형상·축척 | 전극 / 전극 조합 | 이물 크기 | 산포 | 결과 |
|---|---|---:|---:|---|---|
| 대형 기준 조건 | 1000×1000 px, 0.25 µm/px, ROI 250×250 µm | 4 / 3 | 32개: 1~30·40·50 µm | 없음 | 16.07초, 533.6 MB |
| 대형 산포 | 같은 형상·축척 | 4 / 3 | 5개: 2·4·6·8·10 µm | Sobol 64조건 | 102.25초, 1072.4 MB |

두 실행 모두 이물 유입 공정 3개와 short 전극 조합 3개를 사용했고 open은 제외했다. 각각 한 번만
실행했으며, 일부 다른 검증 작업과 실행 시간이 겹쳤다. 따라서 중앙값이나 변동 범위가 없다.

### 64조건 산포 실행에 실제로 들어간 값

64조건 실행은 `configs/scenarios/nominal.yaml`의 합성 시험용 설정을 사용했다. 이 설정에는 다음 가정
산포가 함께 들어 있다.

- GI·mask2·PLN 두께
- mask2·mask3 overlay
- mask2 CD
- 이물 직경 변화
- 이물 중심 offset

설정의 근거 표시는 `assumed`다. 사용자가 확정한 실제 제품 첫 산포 시험은 **mask layer별 Fab 실측
overlay·CD만 적용**하고, 근거가 없는 두께·이물 직경·중심 offset은 0으로 고정한다. 따라서 102.25초
실행은 Sobol 계산 경로의 과거 성능 참고값이지, 앞으로 실행할 실제 제품 조건이나 산포 모델의 근거가
아니다.

### 두 시간으로 속도 배수를 계산하면 안 되는 이유

102.25초를 16.07초로 나눈 약 6.36배를 “64조건 산포의 증가 배수”로 사용하면 안 된다.

- 기준 조건 실행은 이물 크기 32개, 산포 실행은 5개다.
- 산포 실행에는 64개 조건과 여러 가정 변수가 들어 있다.
- 두 실행 모두 1회 측정이라 동시 작업과 시스템 상태의 영향을 분리할 수 없다.
- 11페이지의 복합 입력은 0.5 µm/px, 전극 10개, 전극 조합 16개이므로 형상과 계산량이 다르다.

산포 비용은 같은 형상, 같은 전극 조합, 같은 이물 크기에서 기준 조건과 64·128·256조건을 각각 반복
측정해야 비교할 수 있다.

### failure mode별 2B 파일럿 결과

같은 200×200 복합 형상에서 failure mode만 분리한 세 실행과 모두 포함한 통합 실행을 1회 워밍업 후
5회 측정했다. 공통 조건은 이물 유입 공정 3개와 이물 크기 2·4·6·8·10 µm다. open은 G1, D1,
D2의 굴곡·분기 배선에 서로 떨어진 두 단자 영역을 지정하고 경로별 적용 공정에서만 계산했다.

| 실행 | 활성 계산 조건 | TAT 중앙값 | 단독 TAT 합 내 비율 | 조건당 시간 | 최대 RSS |
|---|---:|---:|---:|---:|---:|
| lateral short | 90 | 1.444초 | 7.31% | 0.0160초 | 198.0 MB |
| vertical short | 150 | 1.785초 | 9.04% | 0.0119초 | 205.7 MB |
| open | 35 | 16.523초 | 83.65% | 0.4721초 | 193.5 MB |
| 통합 | 275 | 17.862초 | 단독 합의 90.44% | 0.0650초 | 224.6 MB |

open의 총 TAT는 lateral short의 11.45배, vertical short의 9.26배다. 활성 계산 조건 하나당으로
정규화하면 각각 29.43배와 39.67배다. 현재 open 구현은 이물 중심 후보마다 손상된 전체 전극의 연결
성분을 다시 계산하므로 전극 조합 수가 더 적어도 TAT를 지배한다.

통합 실행에서 중복 hotspot을 `1/k`로 나눈 CA 구성비는 lateral short 3.48%, vertical short
61.26%, open 35.27%였다. 배분 CA 합과 `union:any` CA 합은 모두 17,188 µm²로 일치했다. 이 값은
다섯 이물 크기와 적용 공정을 같은 비중으로 합한 합성 기하 결과이며 Fab 이물 개수로 가중한 실제
위험도나 불량률이 아니다.

첫 안전 최적화로 명목 실행에서 동일 전극 형상·단자·이물 크기·접촉 여유의 open 결과를 적용 공정
사이에서 재사용했다. 적용 공정 여부는 그대로 유지하며 cache에는 binary open 결과만 저장한다.
open 연결성 계산은 35회에서 15회로 줄었다. 산포 실행에는 큰 지도가 조건 수만큼 쌓이는 무제한
메모리 cache를 적용하지 않았으며 bounded 또는 disk cache가 후속 항목이다.

| 실행 | 수정 전 TAT | 수정 후 TAT | 속도 향상 | 수정 후 최대 RSS |
|---|---:|---:|---:|---:|
| lateral short | 1.444초 | 1.436초 | 1.02배 | 198.3 MB |
| vertical short | 1.785초 | 1.760초 | 1.01배 | 207.4 MB |
| open | 16.523초 | 7.545초 | 2.19배 | 193.7 MB |
| 통합 | 17.862초 | 8.810초 | 2.03배 | 222.3 MB |

open TAT는 54.3%, 통합 TAT는 50.7% 감소했다. 수정 후에도 open은 단독 TAT 합의 70.25%를
차지한다. 최적화 전후 5개 Zarr 배열은 모든 픽셀과 디렉터리 hash가 같고, CA 285행과 union CA
60행도 실행 ID를 제외한 모든 값이 같다.

두 번째 최적화에서는 이물 중심과 footprint의 전체 좌표계를 유지하면서 연결 성분 판정만 전극의
최소 bounding box로 제한했다. G1, D1, D2 open 경로의 판정 영역은 전체 40,000 px의 각각 17.7%,
12.2%, 12.3%다.

| 실행 | 최초 기준선 | 공정 간 cache | 전극 bounding box | 최초 대비 |
|---|---:|---:|---:|---:|
| lateral short | 1.444초 | 1.436초 | 1.447초 | 변화 없음 |
| vertical short | 1.785초 | 1.760초 | 1.761초 | 1.01배 |
| open | 16.523초 | 7.545초 | 3.135초 | **5.27배** |
| 통합 | 17.862초 | 8.810초 | 4.423초 | **4.04배** |

최초 기준선 대비 open은 81.0%, 통합은 75.2% 감소했다. 최종 단독 TAT 합에서 open 비율은
49.43%다. 최초 기준선과 최종 결과의 Zarr 배열·CA 표·union CA 표 동등성을 다시 확인했다.

같은 200×200 복합 형상을 1000×1000 중앙에 둔 확장성 시험도 5회 측정했다. 형상과 단자를 함께
이동했으므로 절대 CA는 200×200과 같다.

| 실행 | padded 1000² TAT | 200² 대비 | 최대 RSS | 출력 |
|---|---:|---:|---:|---:|
| lateral short | 5.678초 | 3.92배 | 534.1 MB | 243.7 MB |
| vertical short | 8.522초 | 4.84배 | 650.3 MB | 377.8 MB |
| open | 4.669초 | 1.49배 | 333.4 MB | 0.07 MB |
| 통합 | 16.385초 | 3.70배 | 843.6 MB | 621.4 MB |

open 연결성은 전극 bounding box 안에서 계산하므로 빈 ROI 증가의 영향이 작았다. 통합 출력
621.4MB 중 float32 `pair_margin_um` 지도가 621.3MB(594MiB)를 차지했다. Zarr 공간 chunk를
512에서 1024로 키운 탐색은 출력이 502.1MB로 줄었지만 TAT 17.673초, 최대 RSS 920.0MB로
악화돼 적용하지 않았다. 이 padded 시험은 긴 배선이나 실제 제품 layout을 대표하지 않는다.

다음 성능 작업은 전극별 실제 mask 구조를 대표하는 입력 측정과 산포용 bounded/disk open cache
검토다. 추가 알고리즘 변경도 작은 격자의 모든 후보 위치와 현재 결과가 픽셀 단위로 일치할 때만
채택한다. 실측 overlay·CD 산포는 64→128→256조건 순으로 CA 수렴과 TAT를 별도 측정한다.

### 발표 스크립트 초안

“열두 번째 페이지는 앞 페이지의 복합 형상 benchmark와 목적이 다른 과거 성능 기록입니다.

1000×1000 픽셀, 0.25 마이크로미터 간격의 합성 형상에서 기준 조건 계산은 16.07초와 최대 메모리
533.6 MB였습니다. 이 실행은 전극 네 개, 전극 조합 세 개와 이물 크기 32개를 계산했습니다.

같은 형상에서 이물 크기 다섯 개와 Sobol 64조건을 계산한 실행은 102.25초와 1072.4 MB였습니다.
두 실행 모두 open은 포함하지 않았습니다. 대형 입력과 산포 계산이 실제로 완료된다는 점은 확인했지만,
각각 한 번만 실행했고 이물 크기 수도 다르므로 두 시간을 나누어 산포의 속도 배수로 해석할 수는
없습니다.

또한 64조건 실행에는 합성 시험용으로 가정한 두께, overlay, CD, 이물 직경과 중심 이동 산포가 함께
들어 있습니다. 실제 제품 첫 시험에서는 보유한 mask별 overlay·CD 실측값만 사용하고 나머지 산포는
0으로 고정하기로 했습니다. 따라서 102.25초는 실제 제품 산포 TAT가 아니라 과거 계산 경로의 참고값입니다.

다음 성능 측정은 동일한 실제 제품 입력에서 기준 조건과 Sobol 64·128·256조건을 반복해 비교합니다.
같은 seed의 조건을 누적해 CA 수렴과 TAT를 함께 확인하고, 선택한 조건 수에서는 여러 scramble seed로
결과 안정성을 확인합니다.

추가한 200×200 복합 파일럿에서는 lateral short가 1.44초, vertical short가 1.79초, open이
16.52초였고 모두 포함한 실행은 17.86초였습니다. 동일 형상과 이물 크기의 open 결과를 적용 공정
사이에서 재사용한 뒤 open은 7.55초, 통합은 8.81초로 각각 2.19배와 2.03배 빨라졌습니다. 이어서
연결 성분 판정을 전극 bounding box로 제한하자 open은 3.14초, 통합은 4.42초가 됐습니다. 최초
기준선보다 각각 5.27배와 4.04배 빠릅니다. 각 단계의 hotspot과 CA는 픽셀 단위로 같았습니다. 최종
open 비중은 단독 실행 시간 합의 49.43%입니다. 통합 결과의 중복 배분 CA 구성비는 lateral short
3.48%, vertical short 61.26%, open 35.27%였습니다. 이 CA 비율은 Fab 분포를 적용하기 전 합성
기하 결과입니다.

같은 형상을 1000×1000 중앙에 그대로 배치한 확장성 시험에서 lateral short는 5.68초, vertical
short는 8.52초, open은 4.67초, 통합은 16.39초였습니다. 통합 최대 메모리는 843.6 MB였고 출력은
621.4 MB였습니다. open은 전극 bounding box만 계산해 200×200보다 1.49배 늘었지만, 전체 ROI에
저장하는 short margin 지도 때문에 통합 출력이 크게 증가했습니다. 이 시험은 큰 canvas의 비용을
분리한 값이며 실제 긴 배선의 성능은 아닙니다.

다음 순서는 전극별 실제 mask 구조를 대표하는 입력에서 open을 재측정하고, 산포 계산은 큰 지도를
메모리에 무제한 보관하지 않는 bounded 또는 disk cache를 검토하는 것입니다.”

### 12페이지에서 확정할 해석

1. 16.07초와 102.25초는 실행 가능성을 보여주는 단일 참고 측정이다.
2. 입력 조건이 달라 두 값의 비율은 산포 비용 배수가 아니다.
3. 102.25초 실행의 산포는 모두 합성 가정값이며 실제 제품 첫 산포 조건과 다르다.
4. 실제 제품 첫 산포 시험에는 mask별 실측 overlay·CD만 적용하고 나머지는 0으로 고정한다.
5. 200×200 mode별 파일럿에서 open은 최초 83.65%, cache 후 70.25%, bounding box 후 49.43%를 차지했다.
6. 통합 CA 구성비는 lateral short 3.48%, vertical short 61.26%, open 35.27%이며 Fab 가중 전 값이다.
7. 두 최적화를 합쳐 open은 5.27배, 통합은 4.04배 빨라졌고 결과 동등성을 확인했다.
8. 동일 형상 padded 1000² 통합은 16.385초, 최대 RSS 843.6MB, 출력 621.4MB다.
9. padded 시험은 ROI·출력 확장성 결과이며 실제 긴 배선이나 제품 layout 대표값이 아니다.
10. `pair_margin_um` 저장 정책은 계약 변경이므로 별도 결정하고, 실제 제품형 입력을 추가 측정한다.

PDF는 전체 첨삭이 끝난 뒤 수정한다. 12페이지의 성능값도 최종 코드와 확정된 실제 제품 조건으로 다시
측정하기 전까지 참고값으로 표시한다.

## 13페이지 · 반례와 회귀 테스트

### 이 페이지가 전달하려는 핵심 메시지

> 정상 사례 몇 개를 실행하는 것만으로는 좌표 경계와 복잡한 배선에서 발생하는 계산 오류를 찾기 어렵다.
> 작은 반례의 모든 이물 중심 위치를 기준 계산과 비교해 오류를 수정했고, 같은 오류가 다시 생기면
> 자동 시험에서 검출되도록 남겼다.

이 페이지는 물리 모델이 실제 제품에서 정확하다는 증명이 아니다. 코드가 현재 정의한 계산 규칙을
일관되게 수행하는지를 검사한 내용이다.

### 수정한 결함을 쉽게 설명하는 방법

#### 1. 이물 중심의 x·y 이동 방향

산포 계산에서 이물 중심을 x 방향으로 이동해야 하는데 배열 좌표의 y 방향으로 적용되는 문제가 있었다.
이미지 배열은 `(y, x)`, 물리 좌표는 `(x, y)` 순서를 사용하기 때문에 발생한 오류다.

이 오류가 있으면 overlay나 이물 중심 offset을 x 방향으로 주었는데 hotspot이 위아래로 움직일 수 있다.
현재는 x만 이동한 사례와 y만 이동한 사례를 각각 실행해 hotspot 이동 방향을 확인한다.

실제 제품 첫 산포 시험에서는 이물 중심 offset을 0으로 고정하지만, 이후 해당 입력을 사용할 가능성과
좌표 변환 공통 경로를 보호하기 위해 회귀 테스트는 유지한다.

#### 2. ㄱ자·분기 배선의 open 후보 누락

open은 이물이 배선을 가렸을 때 두 단자 사이의 연결이 끊기는지를 확인한다. 계산 시간을 줄이기 위해
가능성이 있는 이물 중심만 먼저 고르는데, 이전 후보 선택 방식은 ㄱ자 모서리 주변의 일부 위치를
제외할 수 있었다. 이 경우 실제로 연결을 끊는 위치가 정상으로 빠진다.

후보 범위를 배선 전체에 이물이 닿을 수 있는 거리 기준으로 넓혔다. 직선, 우회 경로, 분기, ㄱ자
배선과 x·y 픽셀 크기가 다른 격자에서 모든 이물 중심을 하나씩 계산한 기준 결과와 비교했고, 저장된
재검사 결과의 차이 픽셀은 모두 0이었다.

이 검사는 현재 open 결과의 후보 누락을 작은 합성 형상에서 확인한 것이다. 실제 제품의 긴 우회 경로나
향후 open 최적화까지 자동으로 보장하지는 않는다.

#### 3. x·y 픽셀 크기가 다를 때의 CD 보정

픽셀의 실제 폭과 높이가 다르면 전극 경계에서 반 픽셀에 해당하는 물리 거리도 방향마다 다르다. 이전
방식은 경계 방향과 관계없이 같은 반 픽셀 보정을 적용할 수 있어, 같은 CD 변화가 x와 y에서 서로 다른
물리 길이로 반영될 수 있었다.

현재는 가장 가까운 반대 영역이 있는 방향을 찾아 x 경계에는 x 픽셀 크기, y 경계에는 y 픽셀 크기를
사용한다. x·y 픽셀 크기가 다른 합성 mask에 같은 물리 CD 값을 주고 실제 확장 길이를 비교하는 시험을
유지한다.

#### 4. Fab 이물 크기 구간의 경계

Fab 표의 크기 구간이 `[1, 3)`, `[3, 5)`라면 직경 3 µm 이물은 두 번째 구간에 한 번만 들어가야 한다.
이전에는 입력 행 순서에 따라 경계값이 다른 구간에 연결될 수 있었다.

현재는 구간을 크기순으로 정렬하고 마지막 끝점을 제외한 구간을 `이상·미만`으로 해석한다. Fab 표의
행 순서를 바꾸어도 같은 크기가 같은 구간에 연결되는지 확인한다. 실제 Fab 분포는 이물 시뮬레이션이
끝난 뒤 적용하므로 이 수정은 기하 접촉 판정이 아니라 사후 가중 결과를 보호한다.

#### 5. 잘못된 입력과 결과 파일

필수 열이 빠지거나 mask 파일이 잘못된 경우 계산 중간의 일반 traceback으로 끝나면 사용자는 어느
입력이 문제인지 알기 어렵다. 현재는 계산 전에 파일 형식, 필수 열, mask 관계와 결과 schema를 검사하고
입력 파일과 항목을 포함한 오류를 반환한다.

앞으로 전극 mask 합집합이 layer mask의 부분집합이 되도록 계약을 바꿀 예정이므로, 이 입력 검사는
새 규칙에 맞춰 함께 수정하고 회귀 테스트를 다시 실행해야 한다.

#### 6. 중복 제거 전체 CA의 수렴 기록

전극 조합별 CA가 안정돼도 여러 전극 조합을 합친 중복 제거 전체 CA가 같은 속도로 안정된다고 단정할
수 없다. 이전에는 전극 조합별 변화만 기록해 전체 위험도의 수렴 상태를 확인할 수 없었다.

현재는 조건 수가 증가할 때 전극 조합별 CA와 중복 제거 전체 CA 변화를 모두 기록한다. 다만 기록이
있다는 것만으로 수렴이 확정되는 것은 아니다. 64→128→256조건의 변화율과 여러 scramble seed 결과를
앞 페이지에서 정한 기준으로 판정해야 한다.

### 본문 표의 정리 방향

현재의 “대표 결함 / 발생할 수 있는 오판 / 현재 조치·근거” 표는 다음처럼 쉬운 표현으로 바꾼다.

| 확인 영역 | 잘못 계산될 수 있었던 내용 | 현재 확인 방법 |
|---|---|---|
| 좌표 이동 | x와 y 방향이 바뀐 hotspot | x만·y만 이동한 합성 입력 비교 |
| open 후보 | ㄱ자와 분기의 open 위치 누락 | 모든 이물 중심을 계산한 기준 결과와 픽셀 비교 |
| 비등방 CD | x·y 경계의 실제 확장 길이 오류 | 방향별 물리 길이 비교 |
| Fab 크기 구간 | 경계 크기가 행 순서에 따라 다른 구간에 연결 | 행 순서를 바꾼 경계값 시험 |
| 입력 계약 | 잘못된 mask·누락 열을 계산 중간에 발견 | 실행 전 입력 검사와 항목별 오류 |
| CA 수렴 | 전극 조합만 보고 전체 CA도 수렴했다고 오인 | 전극 조합별·중복 제거 전체 변화를 함께 기록 |

커밋 번호는 본문 표에서 제거하고 페이지 하단 근거 또는 부록에 둔다. 누가 검토했는지나 사용한 구현
도구는 보고 대상이 아니므로 표시하지 않는다.

### 발표 스크립트 초안

“열세 번째 페이지에서는 구현 과정에서 발견한 계산 오류와 재발 방지 방법을 설명드리겠습니다.

첫 번째는 좌표 순서 문제입니다. 이미지 배열은 y, x 순서이고 물리 좌표는 x, y 순서여서 이물 중심
이동 방향이 뒤바뀔 수 있었습니다. 현재는 x만 이동한 입력과 y만 이동한 입력을 별도로 계산해 hotspot이
의도한 방향으로 움직이는지 확인합니다.

두 번째는 open 후보 누락입니다. 계산량을 줄이기 위해 open 가능성이 있는 위치를 먼저 선택하는데,
기존 방식은 ㄱ자 모서리의 일부 위치를 놓칠 수 있었습니다. 후보 범위를 수정한 뒤 직선, 우회, 분기,
ㄱ자 배선의 모든 이물 중심을 기준 계산과 비교했고 차이 픽셀은 0이었습니다.

세 번째는 x와 y 픽셀 크기가 다를 때의 CD 처리입니다. 경계 방향에 맞는 픽셀 크기를 사용하도록
보정하고, 같은 물리 CD 입력이 방향별로 올바른 길이만큼 반영되는지 확인합니다.

네 번째는 Fab 이물 크기 구간입니다. 구간 경계에 있는 이물이 입력 행 순서에 따라 다른 구간으로
들어가지 않도록 구간 정렬과 이상·미만 규칙을 고정했습니다. 이 항목은 시뮬레이션 후 Fab 분포를
적용하는 단계의 오류를 막습니다.

입력 파일과 결과 파일도 계산 전에 검사해 잘못된 mask나 누락된 항목을 구체적인 오류로 알립니다.
전극 합집합과 layer mask 관계를 부분집합 규칙으로 변경할 때 이 검사와 시험도 함께 수정해야 합니다.

마지막으로 산포 수렴은 전극 조합별 CA뿐 아니라 중복 제거 전체 CA도 함께 기록합니다. 기록만으로
수렴이 확정되는 것은 아니며, 64·128·256조건과 여러 seed의 변화가 앞에서 정한 기준 안에 들어오는지
추가로 판정합니다.

이 회귀 시험은 코드가 정의한 규칙대로 계산되는지를 확인합니다. 실제 제품의 물리적 정확성은 기존
현장 sim과 동일 입력 비교, 실제 제품 pilot과 Fab 자료를 통해 별도로 검증해야 합니다.”

### 13페이지에서 확정할 해석

1. 작은 합성 반례와 전수 비교로 확인한 코드 계산 결함과 재발 방지 시험을 설명한다.
2. open 전수 비교의 차이 0은 시험한 합성 형상 범위의 결과다.
3. 산포 수렴값은 현재 기록되지만, 권장 조건 수와 seed 안정성 판정은 추가해야 한다.
4. 향후 layer mask 부분집합 허용, open 최적화와 산포 입력 변경 후 관련 회귀 시험을 다시 실행한다.
5. 이 페이지는 실제 제품의 물리 정확성이나 기존 현장 sim과의 동등성을 주장하지 않는다.

PDF의 표와 문구는 전체 첨삭 완료 후 수정한다.

## 14페이지 · 폐쇄망 설치와 재현

### 이 페이지가 전달하려는 핵심 메시지

> 소스와 의존성 잠금 정보는 준비돼 있지만, 폐쇄망 대상 장비에 맞는 설치 파일 묶음과 신규 환경 설치
> 시험은 아직 없다. 대상 OS·CPU·Python을 먼저 고정하고, 그 환경용 wheel을 반입해 네트워크 없이
> 설치·시험·대표 계산까지 완료해야 반입 가능 상태라고 판단할 수 있다.

현재 페이지는 `requirements.txt`가 없다는 점을 크게 표시하지만, 이것만으로 준비가 부족하다고 판단하면
안 된다. 저장소에는 직접 의존성을 정의한 `pyproject.toml`과 정확한 해석 버전·파일 hash를 기록한
`uv.lock`이 있다. 핵심 문제는 이 잠금 정보를 대상 플랫폼에서 설치할 실제 package 파일이 저장소에
없고, 깨끗한 환경에서 오프라인 설치를 재현하지 않았다는 점이다.

### 현재 준비된 것과 준비되지 않은 것

| 구분 | 현재 상태 | 해석 |
|---|---|---|
| 애플리케이션 의존성 | `pyproject.toml`에 정의 | 버전 범위가 있어 이것만으로 설치 결과를 고정할 수 없음 |
| 잠금 정보 | `uv.lock` 존재 | 정확한 버전·hash는 있지만 package 파일 자체는 아님 |
| 현재 검증 환경 | macOS Apple Silicon, Python 3.12.13 | 다른 OS·CPU에서의 실행을 보장하지 않음 |
| 폐쇄망 설치 파일 | 별도 wheel 묶음 없음 | 인터넷이나 사내 mirror 없이 새로 설치할 수 없음 |
| 신규 환경 검증 | 미실시 | 기존 `.venv`의 성공을 신규 설치 증빙으로 사용할 수 없음 |
| runtime 네트워크 | 계산 코드에서 명시적 호출 미발견 | 실제 실행 중 패킷 미발생을 계측한 결과는 아님 |

NumPy, SciPy, PyArrow와 같은 주요 의존성은 OS, CPU, Python 버전에 맞는 바이너리 wheel이 필요하다.
Mac에서 사용한 `.venv`나 wheel을 다른 Linux·Windows 장비에 그대로 복사해서 사용할 수 없다.

### 권장 반입 방식

설치 도구에 따라 두 방식 중 하나를 선택한다. 보고서에는 둘을 모두 필수 파일처럼 나열하지 않고,
폐쇄망 운영 환경에서 허용하는 방식을 확정한 뒤 하나만 공식 절차로 기록한다.

#### 방식 A · uv 사용이 허용되는 경우

- `pyproject.toml`과 `uv.lock`을 기준으로 한다.
- 인터넷이 가능한 동일 OS·CPU 환경에서 잠금 버전에 해당하는 wheel을 미리 수집한다.
- 폐쇄망에서는 `uv sync --frozen --offline`과 같은 고정·오프라인 방식으로 설치한다.
- 캐시에 우연히 남아 있는 package에 의존하지 않도록 빈 환경에서 시험한다.

#### 방식 B · 표준 venv와 pip만 허용되는 경우

- `uv.lock`에서 대상 Python과 platform에 맞는 고정 버전 requirements를 내보낸다.
- 실행용과 시험·개발용 의존성을 분리한다.
- 모든 package를 wheelhouse에 미리 내려받고 hash 목록을 보존한다.
- 폐쇄망에서는 `pip install --no-index --find-links wheelhouse ...` 방식으로 설치한다.

`requirements.txt`, `requirements.lock.txt`, `requirements-dev.txt`라는 세 이름을 반드시 사용할 필요는 없다.
필요한 것은 **직접 의존성, 잠긴 전체 의존성, 시험용 의존성을 구분할 수 있고 실제 반입 절차와 일치하는
것**이다.

### 반입 검증 순서

1. 폐쇄망 대상 OS, CPU, Python 버전을 고정한다.
2. 같은 platform에서 실행용·시험용 wheel을 수집하고 파일 hash를 기록한다.
3. 기존 `.venv`와 package cache를 사용하지 않는 새 환경을 만든다.
4. 네트워크를 차단한 상태에서 로컬 wheel만으로 설치한다.
5. 설치된 package 버전을 기록하고 잠금 목록과 비교한다.
6. 전체 회귀 테스트를 실행한다.
7. 단순 합성 입력과 복합 1000×1000 입력을 실행해 hotspot·CA hash와 TAT/RSS를 기록한다.
8. 쓰기 가능한 입력·출력·임시·matplotlib cache 경로를 확인한다.

반입 완료 근거에는 설치 명령, 설치 로그, 설치 시간, wheel·source hash, Python과 package 버전, 전체
시험 결과와 대표 계산 결과를 함께 보존한다.

### 계산 프로그램과 PDF 생성 환경의 구분

시뮬레이션 실행에 필요한 package와 이 보고서를 PDF로 만드는 package는 구분한다. 계산 프로그램의
의존성은 `pyproject.toml`에 들어 있지만, 현재 PDF 생성 스크립트가 사용하는 Playwright·PyMuPDF와
설치된 브라우저는 별도 보고서 작성 도구다. 폐쇄망에서 PDF까지 다시 만들어야 할 때만 별도 wheel과
브라우저 설치 파일을 반입한다.

matplotlib은 최초 실행 시 폰트 cache를 만들 수 있다. 폐쇄망 권한 정책에 맞는 쓰기 가능한 cache
경로를 지정하고, 입력과 Zarr·Parquet 출력 경로에도 충분한 용량과 쓰기 권한이 있는지 확인한다.

### 페이지 편집 방향

현재 페이지의 requirements 파일별 미제공 표와 아직 실행할 수 없는 명령 예시는 다음처럼 바꾼다.

1. `준비됨 / 미완료 / 완료 조건` 세 열의 표를 사용한다.
2. `pyproject.toml + uv.lock`을 현재 준비된 항목으로 표시한다.
3. 미완료 핵심은 대상 플랫폼 확정, wheelhouse, 깨끗한 오프라인 설치 시험으로 표시한다.
4. pip 또는 uv 명령 전체는 대상 환경 확정 후 입력·출력 가이드나 부록에 싣는다.
5. 계산 runtime과 PDF 생성 도구를 구분한다.
6. 폐쇄망 반입이 현재 보고서의 필수 목적이 아니라면 이 페이지 전체를 부록으로 이동한다.

### 발표 스크립트 초안

“열네 번째 페이지에서는 폐쇄망에서 같은 실행 환경을 다시 만들 수 있는지 설명드리겠습니다.

현재 저장소에는 프로그램 의존성을 정의한 pyproject.toml과 정확한 package 버전과 hash를 기록한
uv.lock이 있습니다. 따라서 의존성 목록 자체가 없는 상태는 아닙니다. 다만 잠금 파일에는 package
설치 파일이 들어 있지 않으며, 폐쇄망 대상 장비에 맞는 wheel 묶음도 아직 준비하지 않았습니다.

현재 시험은 Mac mini의 Apple Silicon과 Python 3.12.13에서 수행했습니다. NumPy, SciPy, PyArrow
같은 package는 OS와 CPU에 맞는 바이너리가 필요하므로 이 환경을 다른 장비에 그대로 복사할 수
없습니다. 대상 OS, CPU와 Python 버전을 먼저 고정해야 합니다.

uv 사용이 허용되면 현재 lock 파일과 오프라인 wheel 묶음을 사용하고, 표준 venv와 pip만 허용되면
lock에서 고정 requirements를 내보내 같은 wheel 묶음으로 설치합니다. 두 방식을 동시에 준비할 필요는
없으며 실제 폐쇄망 운영 절차와 맞는 하나를 선택합니다.

반입 완료 여부는 파일을 준비한 것만으로 판단하지 않습니다. 기존 환경과 cache가 없는 상태에서
네트워크 없이 설치하고, package 버전 확인, 전체 회귀 테스트와 대표 1000×1000 계산까지 완료해야
합니다. 설치 로그와 시간, 파일 hash, hotspot·CA 결과도 함께 보존합니다.

계산 프로그램과 PDF 생성 환경은 분리합니다. Playwright, PyMuPDF와 브라우저는 보고서 PDF를 폐쇄망
안에서 다시 만들어야 할 때만 별도로 반입합니다.

따라서 현재 상태는 소스와 잠금 정보가 준비된 단계이며, 폐쇄망 신규 설치가 검증된 단계는 아닙니다.”

### 14페이지에서 확정할 해석

1. `requirements.txt` 부재 자체를 핵심 문제로 표현하지 않는다.
2. `uv.lock`은 잠긴 버전과 hash를 제공하지만 오프라인 설치 파일을 포함하지 않는다.
3. 대상 OS·CPU·Python용 wheel 묶음과 깨끗한 환경 설치 시험이 현재 미완료다.
4. 기존 `.venv`에서 시험이 통과한 사실은 폐쇄망 신규 설치 완료 증빙이 아니다.
5. 계산 runtime과 PDF 생성 도구의 의존성을 구분한다.
6. 페이지 유지 여부는 폐쇄망 반입이 이번 개발 보고의 필수 범위인지에 따라 결정한다.

PDF는 전체 페이지의 내용과 배치가 확정된 뒤 생성한다.

## 15페이지 · 한계와 다음 작업의 우선순위

### 이 페이지가 전달하려는 핵심 메시지

> 현재 합성 형상 검증 다음 단계는 실제 입력에 필요한 필수 코드를 먼저 보완하는 것이다. 수정 버전과
> 출력 schema를 고정한 뒤 기존 `sim`과 동일 입력을 로컬에서 비교하고, 대체 여부를 판단한 다음
> `sim-compare`를 연결한다.

현재 페이지는 실제 제품, 산포, open, 대형 ROI와 `sim-compare` 항목이 한 표에 섞여 있어 무엇을 먼저
해야 하는지 알기 어렵다. 최종 페이지는 한계 목록보다 **대체 판단을 위한 단계와 통과 조건**을 중심으로
구성한다.

### 1단계 · 완료한 P0 코드 보완

기존 `sim` 비교 엔진을 구현하면서 `CODE-CHANGE-BACKLOG.md`의 다음 항목을 묶어서 반영했다.

1. 외부 기존 `sim` 결과를 읽고 같은 좌표로 정렬하는 비교기
2. 전극 mask 합집합이 layer mask의 부분집합인 실제 구조 허용과 남는 TR 영역 기록
3. 여러 전극이 있을 때 가능한 전극 조합의 선언 누락 검사
4. mask별 Fab 실측 overlay x·y와 CD 분포 입력
5. 기준 조건 CA와 산포 평균 중복 제거 전체 CA 열 분리
6. 이물 유입 공정과 Fab 측정 공정의 명시적 연결

TR의 전기적 신호 분리 기능은 이 변경에서 계산하지 않는다. 남는 영역을 허용하고 면적과 미반영 제한을
기록한다. `contact_margin_um`은 0으로 유지한다.

수정 후 기존 단위·계약·CLI 시험, 단순·복합 합성 형상, 산포 0조건, 중복 제거 전체 CA, Fab 공정
연결과 비교기 자체 시험을 모두 실행한다. 시험을 통과한 commit과 출력 schema를 이후 비교 기준으로
고정한다.

### 2단계 · 수정 버전 기준으로 기존 `sim` 비교 입력 고정

수정이 끝난 `particle-sim`과 기존 `sim`에 다음 입력을 동일하게 제공한다.

- 원본 mask와 이미지 크기, 픽셀 크기, 좌표 원점과 x·y 방향
- 전극 ID와 layer, stack 높이, 이물 유입 공정
- 이물 직경과 접촉 여유 0 µm
- 기존 `sim`이 실제로 계산하던 전극 조합
- 결과 hotspot의 축·단위와 CA 계산에 사용한 픽셀 면적

기존 `sim`도 높이를 반영한 2.5D 계산이므로 “2D와 2.5D 비교”라고 표현하지 않는다. 공통 계산
항목에서는 xy 거리, 높이 적용 방식, 경계 padding과 kernel 규칙을 대조한다. 기존 계산 대상이 아니었던
G–A 같은 대각 전극 조합은 기존 CA를 0으로 놓지 않고 `N/A`와 신규 전극 조합으로 분리한다.

### 3단계 · 기존 `sim`과 결과 비교

비교 결과는 공통 전극 조합과 신규 대각 전극 조합을 나누어 보고한다.

| 비교 대상 | 확인값 | 판정 방법 |
|---|---|---|
| 공통 전극 조합 | 기존 전용·현재 전용·공통 hotspot 픽셀 | 겹침 그림과 XOR 지도로 위치 확인 |
| 공통 전극 조합 CA | 기존 CA, 현재 CA, 절대·상대 차이 | 픽셀 면적·단위와 경계 규칙 확인 |
| 신규 대각 전극 조합 | 현재 hotspot·CA | 기존값은 `N/A/new_pair`로 분리 |
| 중복 제거 전체 결과 | 전극 조합별 합이 아닌 union hotspot·CA | 같은 이물 중심 위치를 한 번만 계산했는지 확인 |
| 실행 성능 | 같은 ROI의 TAT·최대 RSS·출력 크기 | 같은 장비에서 워밍업 후 5회 반복 |

차이는 좌표 변환, 직경/반경 해석, 경계 padding, kernel 모양·양자화, 대각거리 추가와 신규 전극 조합으로
분류한다. 설명되지 않는 차이가 남으면 대체 판정을 보류한다. 내부 `legacy_failure`는 이 비교를 대신하지
않는다.

### 4단계 · 실제 제품 pilot과 산포

기준 조건 short에서 입력과 기존 `sim` 비교를 통과한 뒤 실제 제품 산포 계산으로 진행한다.

- mask별 Fab 실측 overlay·CD만 입력한다.
- mask별 CD와 overlay는 서로 독립이고 overlay x·y도 독립으로 표본화한다.
- 근거가 없는 두께·이물 직경·이물 중심 offset은 0으로 고정한다.
- 같은 seed의 Sobol 64→128→256조건으로 중복 제거 전체 평균 CA의 수렴을 확인한다.
- 선택한 조건 수에서 여러 scramble seed로 결과 안정성과 TAT를 확인한다.

이물 크기별 Fab 발생 분포는 이 Sobol 입력에 섞지 않는다. 각 크기의 시뮬레이션이 완료된 뒤 공통
분포를 적용해 구조를 상대 비교하고, 실제 Fab 분포 연결이 확정되면 실제 분포 결과를 별도로 만든다.

### 5단계 · `sim-compare` 연결

`particle-sim` 대체 결과와 출력 schema가 확정된 뒤 `sim-compare`를 연결한다. 양쪽 계약에서 다음
값을 분리해야 한다.

- 이물 유입 공정
- Fab 이물 분포를 측정한 공정
- 하부·상부 전극 layer
- 전극 조합별 CA와 중복 제거 전체 CA

내보내기가 성공했다는 사실만으로 연결이 완료된 것은 아니다. 내보내기, `sim-compare` 읽기와 Fab
가중까지 실행한 결과가 수기 계산과 일치해야 한다.

### 우선순위에서 분리할 후속 항목

다음 항목은 기존 `sim` 대체 비교를 막지 않지만, 해당 기능을 운영하기 전에는 검증해야 한다.

- open 단독·전체 TAT 측정과 정확성 동등성을 유지하는 최적화
- 실제 최대 ROI에서 메모리 한계를 확인한 뒤 tile+halo 검토
- 폐쇄망 대상 플랫폼의 오프라인 신규 설치
- TR의 전기적 역할
- 전도성·비전도성 이물의 전기 접촉 차이
- 원형 외의 타원형·길쭉한·불규칙 이물 형상
- Fab 불량 위치 대조와 예상 불량·수율 변환

### 발표 스크립트 초안

“열다섯 번째 페이지에서는 현재 결과의 한계와 다음 실행 순서를 정리하겠습니다.

가장 먼저 실제 입력과 최종 비교에 필요한 코드를 보완합니다. layer mask 안에 남는 TR 영역 허용,
전극 조합 누락 검사, mask별 실측 overlay·CD 입력, 기준 조건과 산포 CA 열 분리, Fab 공정 연결과 기존
sim 결과 비교기를 한 묶음으로 수정합니다. 수정 후 전체 회귀 시험을 통과한 commit과 출력 schema를
비교 기준으로 고정합니다.

그 다음 기존 sim과 수정된 particle-sim에 같은 입력을 넣습니다. mask, 픽셀 크기, 좌표축, stack,
이물 유입 공정, 이물 크기와 전극 조합을 동일하게 맞춥니다. 기존 sim도 높이를 반영한 2.5D 방식이므로
2D와 2.5D의 비교가 아닙니다. 공통 계산 대상에서 대각거리 추가 전후와 경계·kernel 규칙의 차이를
확인하는 비교입니다.

G–A처럼 기존 sim이 계산하지 않았던 대각 전극 조합은 기존 결과를 0으로 처리하지 않고 신규 계산
항목으로 분리합니다. 공통 전극 조합에서는 hotspot 겹침과 XOR, CA 차이를 확인하고 모든 차이의 원인을
분류합니다. 설명되지 않는 차이가 남으면 대체 판단을 보류합니다.

TR은 현재 전기적 기능을 계산하지 않고 남는 영역과 제한만 기록합니다.

공통 항목 비교와 실행 성능이 확인되면 particle-sim의 대체 여부를 판단합니다. 그 다음 실제 제품
mask에서 기준 조건을 확인하고, mask별 Fab 실측 overlay와 CD만 사용해 산포 계산을 진행합니다.
근거가 없는 다른 산포는 0으로 고정합니다.

이물 크기별 Fab 분포는 시뮬레이션이 끝난 뒤 적용합니다. 우선 공통 분포로 구조를 상대 비교하고,
공정과 크기 구간의 연결이 확정되면 실제 분포 결과를 별도로 계산합니다.

sim-compare 연결은 이 과정 뒤에 진행합니다. particle-sim의 대체 결과와 출력 계약을 먼저 확정하고,
이물 유입 공정과 Fab 측정 공정을 분리한 계약으로 내보내기부터 최종 가중 결과까지 대조합니다.”

## 16페이지 · 입력 파일과 YAML 작성법

### 이 페이지가 전달하려는 핵심 메시지

> 기준 형상과 계산 대상은 제품 manifest에, mask overlay·CD 산포는 별도 산포 YAML에, 이물 크기별
> Fab 발생 분포는 시뮬레이션 후 사용하는 별도 표에 기록한다. 서로 목적이 다른 세 입력을 한 파일이나
> 하나의 확률 모델에 섞지 않는다.

이 페이지는 모든 필드를 나열하는 사용 설명서가 아니다. 입력 파일이 어떤 역할로 나뉘는지와 결과를
해석할 때 꼭 필요한 항목을 보여주는 요약 페이지다. 전체 필드, 허용값, 단위, 예제와 출력 설명은
`docs/second-test-and-io-guide.md`를 기준 문서로 사용한다.

YAML 자체에는 `#` 주석을 쓸 수 있지만, 프로그램은 주석을 읽거나 결과에 보존하지 않는다. 따라서
측정 근거, 단위 정의와 작성 규칙을 YAML 주석에만 남기지 않고 입출력 가이드와 실행 manifest에
구조화해 기록한다.

### 입력은 세 묶음으로 분리한다

| 입력 | 역할 | 주요 내용 | 적용 시점 |
|---|---|---|---|
| 제품 manifest + mask 이미지 | 기준 형상과 계산 대상 | 좌표·축척, stack, 전극, 전극 조합, open 단자, 이물 크기 | 모든 시뮬레이션 |
| 산포 YAML | mask 형상의 조건별 변화 | mask별 overlay x·y, CD와 측정 근거 | 기준 계산 확인 후 Sobol 실행 |
| Fab 이물 분포 표 | layer·크기별 평균 이물 개수 | Fab layer, 크기 구간, 평균 개수, 검사 단위 면적·기간 | 크기별 시뮬레이션 완료 후 |

Fab 이물 분포를 Sobol의 이물 크기 산포로 넣지 않는다. 작은 이물이 많고 큰 이물이 적은 현상은 크기별
CA가 계산된 다음 사후 가중으로 적용한다.

### 제품 manifest를 읽는 순서

#### 1. 좌표와 입력 크기

`coordinate_system`은 mask 한 픽셀의 실제 길이와 좌표 방향을 정의한다.

- 배열 shape는 고정되지 않는다. 200×200, 1000×1000 이상도 사용할 수 있다.
- 모든 layer·전극 mask는 같은 `(y, x)` shape여야 한다.
- `ROI 폭 = x 픽셀 수 × pixel_size_x_um`, `ROI 높이 = y 픽셀 수 × pixel_size_y_um`이 맞아야 한다.
- 배열 index는 `(y, x)`, 물리 좌표는 `(x, y, z)` 순서다.
- 이미지는 PNG 또는 TIFF의 2차원 이진 mask이며 resize·anti-alias된 중간값은 허용하지 않는다.

입력 크기의 코드상 고정 상한은 없지만 실제 한계는 메모리, TAT와 출력 용량으로 결정된다. 실제 최대
ROI는 수정 버전에서 별도 성능 측정한다.

#### 2. stack과 mask 이름

`stack`은 아래에서 위로 형성되는 순서, 재질과 두께를 정의한다. z 구간은 `process_order` 순서로 두께를
누적해 계산한다. 보고서와 새 예제에서는 도체 mask를 `mask1`, `mask2`, `mask3`으로 표기한다. 기존
합성 fixture의 `M1`, `M2`, `M3`은 저장된 실행 ID이므로 과거 근거 파일에서만 유지한다.

절연층과 평탄화층도 stack에 포함하지만 전극은 아니다. `planarization_factor`와 후속 layer의
`protrusion` 정책은 현재 합성 시험의 물리 가정이다. 실제 제품에 그대로 복사하지 않고 공정 근거를
확정하거나 해당 영향을 제외한 조건으로 시작한다.

#### 3. layer mask와 전극 mask

하나의 layer mask 안에 여러 전극 mask를 둘 수 있다. schema 2.0의 검증 관계는 다음과 같다.

- 각 전극 mask는 해당 layer mask 안에 있어야 한다.
- 같은 layer에 속한 서로 다른 전극 mask는 겹칠 수 없다.
- 전극 mask 합집합이 layer mask 전체를 채울 필요는 없다.
- layer mask에 남는 영역은 TR 또는 현재 평가하지 않는 패턴으로 허용하고 면적을 기록한다.
- 현재 short·open 계산은 전극 mask를 기준으로 하며 TR의 전기적 신호 분리 기능은 반영하지 않는다.

현재 HEAD는 전극 합집합을 layer mask의 부분집합으로 허용하고 잔여 영역 통계를 기록한다.

#### 4. 이물 유입 공정

YAML의 `particle_source_steps`는 보고서에서 말하는 이물 유입 공정 목록이다.

- `lands_after_layer`: 어느 layer 형성 직후 이물이 들어왔는지
- `surface_model`: 이물이 놓이는 표면 높이를 flat·conformal·partial 중 어떻게 계산할지
- `fab_distribution_layer`: 나중에 연결할 Fab 이물 측정 공정

이물 유입 공정, 전극 layer와 Fab 측정 공정은 서로 다른 의미이므로 이름이 우연히 같다고 자동 연결하지
않는다.

#### 5. 전극 조합과 open 경로

`electrode_pairs`에는 계산할 두 전극과 `lateral_short` 또는 `vertical_short`를 기록한다. 같은 layer의
서로 다른 net은 lateral short, 다른 layer의 서로 다른 net은 vertical short다. 가능한 모든 조합을 자동으로 계산 대상에 넣지는 않지만, schema 2.0은 선언·제외 목록을 전수 감사해 누락을 거부한다.

open을 계산하지 않으면 `open_paths: []`로 둔다. 실제 입력은 원본 배선 위에 시작 단자 영역과 도착 단자
영역을 작은 이진 mask로 표시하며, `(y, x)` 점 좌표는 이전 입력 호환용으로 유지한다. open은 이물이 배선 경로를 가려 두 단자 영역의 연결을 끊는 조건이다.

점 좌표는 합성 시험과 이전 manifest 호환용으로 유지하고, 실제 제품에서는 단자 영역 mask를 그림으로
겹쳐 확인한다. 단자 없이 ROI 경계에서 자동 선택한 결과는 `open proxy`로만 표시한다.

#### 6. 이물과 접촉 입력

- `particle_sizes_um`: 계산할 원형 이물의 직경 목록이며 작은 값부터 증가해야 한다.
- `embedding_depth_um`: 현재 첫 비교에서는 0으로 둔다.
- `contact_margin_um`: 확정대로 0으로 고정한다.
- `post_step_policy`: 이물 유입 후 생기는 layer와 접촉할 수 있는지 정하는 가정이다.
- `legacy_kernel`: 외부 기존 `sim` 결과 자체가 아니라 내부 xy kernel 참고 계산 설정이다.

현재는 원형 footprint와 구형 높이만 지원한다. 타원형, 길쭉한 형상과 불규칙 형상은 후속 물리 모델
검토 항목이다. 전도성·비전도성에 따른 유효 접촉 차이도 `contact_margin_um`에 임의로 넣지 않는다.

### 산포 YAML의 최종 입력 원칙

제품 manifest는 기준 형상을 정의하고 산포 YAML은 각 Sobol 조건에서 mask를 얼마나 이동·확장할지
정의한다. schema 2.0에는 다음 정보를 mask별로 입력한다.

- overlay x의 평균·표준편차와 기준 mask
- overlay y의 평균·표준편차와 기준 mask
- CD의 평균 bias와 표준편차
- 각 항목의 `measured` 근거, 원자료 ID, Fab 공정, 제품군, lot·기간, 단위와 변환 버전
- x·y와 mask별 CD·overlay가 독립이라는 현재 확인 사항

실제 첫 산포 입력에는 이 mask overlay·CD만 넣는다. 두께, 이물 직경과 이물 중심 offset은 근거가
없으므로 0으로 고정한다.

CD 값이 전체 선폭 변화인지 한쪽 경계 이동량인지 반드시 구분한다. 현재 변환 입력은 mask 경계 이동량을
사용하므로, 실측값이 전체 선폭 변화 `ΔCD`라면 대칭 직선에서는 일반적으로 `ΔCD/2`가 한쪽 경계 이동량이다.
측정값의 정의를 확인하지 않고 숫자를 그대로 입력하면 형상 변화가 두 배가 될 수 있다.

### 입력 크기와 여러 전극의 간단한 예

```yaml
coordinate_system:
  pixel_size_x_um: 0.5
  pixel_size_y_um: 0.5
  roi_width_um: 500.0
  roi_height_um: 500.0       # 1000×1000 mask

electrodes:
  - electrode_id: gate1
    layer_name: mask1
    net_id: gate_net1
    path: masks/gate1.png
  - electrode_id: gate2
    layer_name: mask1
    net_id: gate_net2
    path: masks/gate2.png
  - electrode_id: data1
    layer_name: mask2
    net_id: data_net1
    path: masks/data1.png

electrode_pairs:
  - pair_id: gate1__gate2
    electrode_a: gate1
    electrode_b: gate2
    failure_mode: lateral_short
  - pair_id: gate1__data1
    electrode_a: gate1
    electrode_b: data1
    failure_mode: vertical_short

open_paths: []
particle_sizes_um: [2, 4, 6, 8, 10]
embedding_depth_um: 0.0
contact_margin_um: 0.0
```

이 코드는 전체 실행 manifest가 아니라 크기, 여러 전극과 전극 조합의 관계를 보여주는 발췌다. 전체
검증된 실행 예제는 입출력 가이드와 `configs/legacy-sim-reference.example.yaml`에 둔다.

### 실행 결과에 남겨야 하는 추적 정보

`run_manifest.json`에는 다음 정보를 자동으로 기록한다.

- 제품·설계 ID와 실행 ID
- 제품 manifest, mask, 산포 입력과 Fab 원자료의 hash
- 계산 단위, 이물 크기, 이물 유입 공정과 적용한 물리 가정
- random seed, Sobol 조건 수와 수렴 상태
- simulator version, 출력 schema version, git commit과 working tree 변경 여부

현재 코드는 `git_commit`을 항상 `null`로 전달하므로 마지막 항목은 아직 충족하지 못한다. 수정 버전을
고정해 기존 `sim`과 비교하려면 commit과 dirty 상태 또는 배포 build ID가 반드시 기록돼야 한다. 이
항목을 기존 `sim` 비교기 코드 보완과 완료 기준에 추가했다.

### 페이지 편집 방향

1. 현재의 긴 YAML 두 칸은 입력 세 묶음 흐름도와 짧은 예제로 바꾼다.
2. `M1/M2/M3` 표시는 `mask1/mask2/mask3`으로 바꾼다.
3. 전극 합집합과 layer mask의 완전 일치 문구를 부분집합 관계로 수정한다.
4. 합성 fixture의 `protrusion`과 `coverage_break_factor=1.5`를 일반 기본값처럼 보이지 않게 한다.
5. 입력 크기 가변성과 한 layer의 여러 전극 예를 넣는다.
6. 제품 manifest, 산포 YAML과 Fab 이물 분포의 적용 시점을 분리한다.
7. 전체 필드 설명은 입출력 가이드로 연결하고 본문에는 핵심 관계만 남긴다.

### 발표 스크립트 초안

“열여섯 번째 페이지에서는 입력 파일을 어떻게 나누어 작성하는지 설명드리겠습니다.

입력은 세 묶음입니다. 제품 manifest와 mask 이미지는 기준 형상, stack, 전극과 계산 대상을 정의합니다.
산포 YAML은 mask별 overlay와 CD가 조건마다 어떻게 변하는지를 정의합니다. Fab 이물 분포 표는 Fab
layer별·이물 크기별 평균 이물 개수를 제공하며, 크기별 시뮬레이션이 끝난 뒤 적용합니다. 예상 건수로
계산하려면 평균을 구한 검사 단위의 면적도 함께 입력합니다.

mask 이미지 크기는 고정돼 있지 않습니다. 모든 mask가 같은 shape이고 픽셀 크기와 ROI가 일치하면
1000×1000 이상도 입력할 수 있습니다. 실제 사용 한계는 메모리와 TAT로 결정됩니다.

하나의 layer에는 여러 전극이 있을 수 있습니다. 각 전극은 layer mask 안에 있어야 하고 같은 layer의
서로 다른 전극끼리는 겹치면 안 됩니다. 전극 합집합이 layer mask 전체와 같을 필요는 없습니다. 남는
영역은 TR 또는 현재 평가하지 않는 패턴으로 기록하지만, TR의 전기적 기능은 아직 계산하지 않습니다.

전극 조합에는 lateral short와 vertical short를 명시합니다. open의 두 단자는 좌표 숫자 대신 연결을
유지해야 할 시작 영역과 도착 영역 mask로 입력하도록 보완합니다. 가능한 전극 조합의 누락 검사도
코드 보완 항목에 포함했습니다.

접촉 여유와 매립 깊이는 첫 비교에서 모두 0으로 사용합니다. 현재 이물은 원형으로 계산하며 재질별
전기 접촉 차이와 비원형 형상은 후속 검토 항목입니다.

실제 산포 계산에는 mask별 Fab 실측 overlay x·y와 CD만 입력합니다. 서로 독립으로 처리하고, 근거가
없는 두께·이물 크기·중심 이동 산포는 0으로 고정합니다. 이물 크기별 Fab 발생 분포는 Sobol 산포에
넣지 않고 계산 후 union CA에 적용합니다. 여기서 union CA는 전극 형상의 합집합이 아니라, 해당 Fab
layer에 연결된 이물 유입 공정에서 선언된 모든 불량 hotspot을 중복 제거한 결과입니다.

모든 실행은 입력 파일 hash와 계산 조건을 run_manifest에 남깁니다. 현재는 비교한 정확한
commit과 수정 파일 존재 여부도 함께 기록해 기존 sim 대조 결과를 재현할 수 있게 합니다.”

### 16페이지에서 확정할 해석

1. 제품 manifest, 산포 YAML과 Fab 이물 분포는 목적과 적용 시점이 다르다.
2. 입력 shape는 가변이며 1000×1000 이상도 가능하지만 자원 한계는 별도로 측정한다.
3. 한 layer에 여러 전극을 둘 수 있고, 전극 합집합은 layer mask의 부분집합이다.
4. 남는 TR 영역은 허용·기록하지만 전기적 역할은 현재 미반영이다.
5. 첫 실제 산포는 mask별 실측 overlay·CD만 사용하고 다른 산포는 0으로 고정한다.
6. `contact_margin_um`과 `embedding_depth_um`은 첫 비교에서 0이다.
7. 전체 YAML 필드와 출력 설명은 `second-test-and-io-guide.md`에서 확인한다.
8. 실제 open 입력은 단일 좌표 대신 두 단자 영역 mask를 기본으로 한다.
9. Fab 입력은 layer별·크기별 평균 이물 개수이며 검사 단위 면적을 함께 보존한다.

PDF는 코드 보완과 전체 페이지 첨삭이 끝난 뒤 최종 입력 schema에 맞춰 생성한다.

## 17페이지 · 출력 파일과 결과 확인 순서

### 이 페이지가 전달하려는 핵심 메시지

> 최종 출력은 **어느 Fab layer가 위험한지**, **어느 전극 조합과 개별 전극이 위험한지**,
> **어느 Fab layer에서 들어온 이물이 어느 전극 조합의 위험을 크게 만드는지**를 모두 확인할 수 있어야 한다.
> Zarr는 그 판단의 근거가 되는 위치별 지도이고, Parquet는 조건별 수치와 순위를 만드는 표다.
> `run_manifest.json`에는 어떤 입력과 코드로 계산했는지를 기록한다.

현재 페이지는 내부 파일과 보고서 근거 파일을 한 표에 섞어 나열해 핵심 출력이 잘 보이지 않는다.
최종 페이지에서는 사용자가 실제 결과를 읽는 순서와 개발자가 실행을 재현하는 정보를 분리한다.

### Zarr와 Parquet의 차이

#### Zarr · 위치를 보는 원본 지도

Zarr는 여러 차원을 가진 큰 배열을 작은 chunk로 나누어 압축 저장하는 형식이다. 이 프로젝트에서는
다음처럼 위치 `(y, x)`가 필요한 결과에 사용한다.

```text
이물 유입 공정 × 이물 크기 × 전극 조합 또는 union × y × x
```

- 특정 위치가 hotspot인지 확인할 수 있다.
- 산포 계산에서는 위치별 조건부 접촉확률을 확인할 수 있다.
- 필요한 공정·크기·전극 조합의 chunk만 읽을 수 있다.
- 하나의 파일처럼 보이지만 실제로는 디렉터리와 여러 chunk 파일로 구성된다.

쉽게 말하면 Zarr는 조건별 흑백 또는 회색 지도 여러 장을 이름표와 함께 쌓아 둔 **지도 묶음**이다.
예를 들어 1000×1000 hotspot 지도를 이물 크기 10개, 전극 조합 50개, 이물 유입 공정 3개에 대해
저장하면 지도 1,500장을 다루어야 한다. Zarr는 이 전체를 한 번에 메모리에 올리지 않고 필요한 전극
조합의 필요한 위치만 꺼내 읽게 해 준다.

Zarr는 Excel처럼 행 단위로 직접 읽는 표가 아니다. 프로그램으로 읽거나 필요한 지도를 PNG로 변환해
확인한다. 따라서 최종 결과에는 주요 전극 조합의 PNG 미리보기도 함께 만든다.

#### Parquet · 조건별 숫자를 보는 요약표

Parquet는 열 단위로 압축하는 표 형식이다. 한 행이 하나의 이물 유입 공정·이물 크기·전극 조합 또는
union 결과를 나타낸다.

- CA와 단위, 전극 조합, 불량 유형을 필터링하기 쉽다.
- Fab layer와 이물 크기별 평균 이물 개수·검사면적을 연결하기 쉽다.
- Python·데이터 분석 도구에서 필요한 열만 빠르게 읽을 수 있다.

쉽게 말하면 Parquet는 열이 많은 대형 Excel 표를 프로그램이 빠르게 읽도록 저장한 **분석용 표**다.
행과 열이 있으므로 전극 조합별 정렬·필터·합계에 적합하지만, 보통 Excel에서 바로 열어 검토하는
형식은 아니다. 사람이 바로 확인할 수 있도록 같은 결과의 핵심 열만 담은 `risk_summary.csv`도 함께
출력한다.

Parquet는 “조건별 CA와 가중 위험이 얼마인가”를 확인하는 표이고, 그 값이 나온 위치와 겹침은 Zarr에서
확인한다. 두 형식은 같은 결과의 숫자와 공간 근거를 각각 맡는다.

### 필요한 위험도 세 관점

#### 1. Fab layer별 위험도

각 Fab layer에 연결된 이물 유입 공정에서 모든 lateral short·vertical short·open hotspot을 먼저 OR해
중복을 제거한다. 이 `failure_mode=any` union CA에 해당 layer·이물 크기의 평균 이물 밀도를 적용한다.
이 결과는 “어느 공정 layer에서 유입된 이물이 구조 전체 위험에 크게 기여하는가”를 보여준다.

#### 2. 전극 조합별·개별 전극별 위험도

전극 조합별 원본 CA는 어떤 두 전극 사이가 이물에 민감한지를 보여준다. 다만 같은 이물 위치가 여러
전극 조합의 hotspot일 수 있으므로 원본 CA를 단순 합산한 값은 전체 위험이 아니다. 최종 출력에는
다음 두 값을 함께 둔다.

- `raw_pair_risk`: 해당 전극 조합의 hotspot 전체를 인정한 민감도. 전극 조합 순위를 보는 값이며
  전극 조합끼리 더하지 않는다.
- `allocated_pair_contribution`: 한 위치에서 동시에 `k`개 전극 조합이 hotspot이면 각 조합에 `1/k`씩
  나눈 기여도. 전극 조합별 값을 합하면 같은 조건의 union 위험과 정확히 같아진다.

개별 전극은 자신이 포함된 전극 조합의 `allocated_pair_contribution`을 모아 순위를 만든다. short는
전극 조합 기여를 두 전극에 절반씩 배분한 **합계 일치 기여도**와, 해당 전극이 관련된 전극 조합의
기여를 전부 보여주는 **관여 점수**를 함께 둔다. open은 해당 배선 전극에 전부 배분한다. 절반·`1/k`
배분은 전기적 원인을 단정하는 물리식이 아니라 중복 없이 합계를 맞추기 위한 보고 규칙이다.

#### 3. Fab layer와 전극을 함께 본 위험도

가장 중요한 분석 단위는 `Fab layer × 이물 크기 × pair_id`다. 여기에는 실제 `electrode_a_id`,
`electrode_b_id`, 두 전극의 layer, 불량 유형과 Fab 이물 밀도를 함께 저장한다. 이 표를 이물 크기에
대해 합산하면 “mask1 공정에서 들어온 이물이 gate1–data3 vertical short에 가장 크게 기여한다”처럼
공정 layer와 실제 전극 조합을 동시에 지정해 순위를 낼 수 있다.

현재 `particle-sim`의 `ca.parquet`에는 실제 전극 ID가 있으므로 기본 정보는 존재한다. 그러나 현재
`particle-sim-compare` 내보내기는 전극 ID를 구조화된 열로 넘기지 않고 전극 역할과 layer 중심으로
비교하며, 실측 평균 이물 개수의 가중 순위도 아직 지원하지 않는다. 따라서 현재 출력은 위치·CA 검증에는
맞지만 최종 전극 중요도 분석에는 불완전하다. 연동 단계에서 전극 ID, 전극 조합 ID, Fab layer와 배분
기여도를 계약에 추가한다.

### 사용자가 확인할 출력 순서

#### 1. 기준 조건 hotspot

`hotspots.zarr`에서 이물 유입 공정·이물 크기·전극 조합별 0/1 hotspot을 확인한다.

- `nominal_failure`: 기준 조건의 전극 조합 또는 open hotspot
- `pair_margin_um`: 해당 위치의 접촉 여유
- `union_failure`: 불량 유형별 또는 전체 hotspot OR
- `union_pair_count`: 같은 위치에서 동시에 hotspot이 된 전극 조합 수

`legacy_failure`는 외부 기존 `sim` 결과가 아니라 내부 xy kernel 참고값이다. 기존 `sim`과의 실제 비교
결과는 `compare-sim`의 별도 비교 출력으로 저장한다.

#### 2. 산포 반영 위험 지도

`probability.zarr`에서 mask별 실측 overlay·CD 조건을 반복했을 때의 위치별 결과를 확인한다.

- `probability`: 전극 조합 또는 open별 조건부 hotspot 비율
- `contact_margin_mean_um`: 조건별 접촉 여유의 평균
- `union_probability`: 각 조건에서 먼저 hotspot을 OR한 뒤 평균한 전체 확률 지도

이 확률은 입력한 overlay·CD 분포에 조건부인 기하 위험이며 실제 불량률이 아니다.

#### 3. 전극 조합별 CA

`ca.parquet`는 어떤 전극 조합이 결과에 기여하는지 분석할 때 사용한다.

- 기준 조건 CA
- 산포 평균 CA와 조건별 p05·p50·p95
- 이물 유입 공정, 이물 크기와 불량 유형
- 조건 수와 수렴 변화

전극 조합별 CA를 단순히 더한 값은 구조 전체 대표값으로 사용하지 않는다.

현재 `risk_by_pair.parquet`에는 Fab layer, 실제 두 전극 ID와 layer, 불량 유형, 이물 크기,
`raw_pair_risk`, `allocated_pair_contribution`과 union 대비 기여율을 저장한다. 산포 계산에서는 각 산포
조건에서 `1/k` 배분을 먼저 수행한 뒤 조건 평균을 내어 합계가 union 평균과 일치하게 한다.

#### 4. 중복 제거 전체 CA

`ca_union.parquet`는 구조 비교와 Fab 가중의 주 입력이다. 현재 기준 조건과 산포 결과를 다음처럼
서로 다른 열에 저장한다.

- `ca_union_nominal_um2`: 산포 미적용 기준 조건의 union CA
- `ca_union_mean_um2`: 산포 반영 평균 union CA
- `ca_union_p05/p50/p95_um2`: 산포 조건별 union CA 분포
- `failure_mode=any`: 해당 이물 유입 공정·크기의 모든 선언 불량 hotspot을 OR한 결과
- `ca_pair_sum_*`: 중복 효과를 확인하기 위한 전극 조합별 CA 단순합

여기서 union은 해당 layer 전극 mask의 기하 합집합이 아니다. Fab layer에 연결된 이물 유입 공정에서
lateral short·vertical short·open hotspot을 중복 제거한 결과다.

schema 2.0은 산포 평균 union CA를 `ca_union_mean_um2`에 기록하고 기준값과 분리한다. 기존 보존
결과를 읽을 때는 schema version을 확인하며, 최종 PDF는 새 schema 결과로 다시 만든다.

#### 5. Fab layer별 평균 이물 개수 적용 결과

기존 `fab_risk.parquet`는 전극 조합별 CA를 가중해 중복될 수 있으므로 최종 대표값으로 사용하지 않는다.
현재 Fab 가중 출력은 다음 값을 한 행에 보존한다.

| 구분 | 저장값 |
|---|---|
| Fab 측정 조건 | Fab layer, 이물 크기 구간, 대표 크기, 측정 기간 |
| 평균 이물 입력 | 평균 이물 개수, sample 수, sample당 검사면적 |
| 변환값 | 평균 이물 밀도 `개/mm²` |
| 시뮬레이션 연결 | 이물 유입 공정, `failure_mode=any`, union CA |
| 기여값 | `union CA(mm²) × 평균 이물 밀도(개/mm²)` |

검사면적을 알고 있으므로 layer·크기별 평균 이물 개수를 평균 이물 밀도로 변환할 수 있다. 전체 가중값은
Fab layer와 크기 구간별 기여를 합한다. 이 값은 기하 기반 기대 위험이며 실제 전기 불량 건수나 수율로
확정하려면 제품 대조가 추가로 필요하다.

최종 가중 출력은 한 합계만 만들지 않고 세 개의 Parquet 표와 검토용 CSV를 함께 만든다.

| 출력 | 답하는 질문 |
|---|---|
| `risk_by_layer.parquet` | 어느 Fab layer의 전체 중복 제거 위험이 큰가? |
| `risk_by_pair.parquet` | 어느 Fab layer에서 어느 실제 전극 조합의 기여가 큰가? |
| `risk_by_electrode.parquet` | 여러 전극 조합을 합쳐 보았을 때 어느 개별 전극의 관여·배분 기여가 큰가? |
| `risk_summary.csv` | 위 결과의 상위 항목을 사람이 바로 열어 확인할 수 있는가? |

#### 6. 수렴과 기존 `sim` 비교

- `convergence.csv`: 64→128→256조건에서 전극 조합별·union CA의 변화
- 신규 기존 `sim` 비교 표: 공통 전극 조합의 기존 전용·현재 전용·공통 픽셀과 CA 차이
- 신규 비교 지도: 두 결과의 겹침과 XOR 위치
- 신규 대각 전극 조합: 기존값 `N/A/new_pair`, 현재 hotspot·CA

저장소의 `legacy_vs_edt.csv`는 외부 기존 `sim` 비교 결과가 아니라 내부 kernel 차이 설명용이므로 사용자
대체 판정의 주 출력에서 분리한다.

### 실행 재현 정보

`run_manifest.json`은 결과 자체가 아니라 결과의 신분표다. 현재 다음 항목을 포함한다.

- run ID, 제품·설계 ID와 실행 시각
- 제품 manifest, 모든 mask, 산포 YAML과 Fab 입력의 hash
- simulator version, git commit, working tree 변경 여부 또는 build ID
- 출력 schema version과 비교기 version
- 이물 크기, 이물 유입 공정, seed와 Sobol 조건 수
- 단위와 적용한 물리 가정·경고
- 생성된 주요 출력 파일의 경로와 hash

현재 `git_commit=null`과 출력 hash 미기록은 재현성 보완 항목이다. 수정 후 기존 `sim` 비교를 실행할 때는
비교한 두 프로그램의 version과 입력·출력 hash를 같은 비교 manifest에 기록한다.

### 페이지에서 제거하거나 부록으로 옮길 내용

1. 로컬 iCloud 경로와 개인 PC 절대경로는 제거한다.
2. 전체 테스트 로그와 benchmark JSON 목록은 별도 근거 목록으로 이동한다.
3. `sim-compare` 상세 내보내기 파일 목록은 대체 판정 후 연동 계약이 확정된 버전만 부록에 싣는다.
4. 본문에는 결과 확인에 필요한 핵심 출력만 남긴다.

### 발표 스크립트 초안

“열일곱 번째 페이지에서는 계산 결과를 어떤 순서로 확인하는지 설명드리겠습니다.

먼저 Zarr와 Parquet의 역할을 설명드리겠습니다. Zarr는 조건별 지도 여러 장을 쌓아 둔 지도 묶음입니다.
큰 지도를 작은 조각으로 저장하므로 필요한 이물 유입 공정, 크기, 전극 조합과 위치만 읽을 수 있습니다.
Parquet는 대형 Excel 표를 프로그램이 빠르게 읽도록 저장한 분석용 표입니다. 조건별 숫자를 정렬하고
Fab 데이터를 연결하는 데 사용합니다. 사람이 바로 볼 수 있도록 주요 순위는 CSV로도 출력합니다.

기준 계산에서는 hotspots.zarr에서 전극 조합별 hotspot과 중복 제거 union 지도를 확인합니다. 산포
계산에서는 probability.zarr에서 위치별 조건부 확률과 조건별 OR 후 평균한 union 확률을 확인합니다.

결과는 세 관점으로 봅니다. 첫째, Fab layer별 전체 위험은 ca_union.parquet의 failure_mode=any를
사용합니다. 이 union은 한 layer의 전극 형상을 합친 면적이 아니라, 해당 이물 유입 공정에서 모든
lateral short, vertical short와 open hotspot을 OR한 CA입니다.

둘째, 전극 조합별 원본 CA로 어떤 조합이 민감한지 확인합니다. 같은 위치가 여러 조합의 hotspot이면
겹친 조합 수만큼 균등 배분한 기여도도 함께 계산합니다. 이 배분 기여도는 합계가 union과 일치합니다.
개별 전극 순위는 자신이 포함된 조합을 모아 관여 점수와 합계 일치 기여도로 보여줍니다.

셋째, Fab layer와 실제 전극 조합을 함께 묶어 어느 공정에서 들어온 이물이 어느 전극 사이의 위험을
크게 만드는지 순위를 냅니다. 이 결과를 이후 particle-sim-compare의 주요 입력으로 사용합니다.

Fab 적용 결과에는 layer별·크기별 평균 이물 개수와 검사면적을 함께 저장합니다. 평균 개수를 검사면적으로
나누어 평균 이물 밀도를 구하고, 해당 Fab layer에 연결된 이물 유입 공정의 union CA와 곱합니다.

마지막으로 run_manifest에는 입력 파일 hash, 적용 조건, 코드 version과 출력 schema를 남깁니다.
현재는 git commit과 수정 파일 존재 여부까지 기록하여 어떤 코드로 기존 sim과 비교했는지 재현할
수 있게 합니다.

기존 합성 결과는 기능 경로 근거로 보존합니다. 최종 대표 결과는 실제 기존 sim 대조 후 schema 2.0으로 다시 생성합니다.”

### 17페이지에서 확정할 해석

1. Zarr는 여러 조건의 위치별 지도를 저장하는 지도 묶음이고, Parquet는 조건별 수치를 저장하는 분석용 표다.
2. layer별 위험은 이물 유입 공정별 `failure_mode=any` union CA에 해당 Fab layer의 이물 밀도를 적용한다.
3. 전극 조합별로 원본 민감도와 중복을 배분한 기여도를 함께 저장한다.
4. 개별 전극별로 관여 점수와 합계 일치 기여도를 제공한다.
5. `Fab layer × 이물 크기 × 실제 전극 조합`을 이후 `particle-sim-compare`의 핵심 분석 단위로 사용한다.
6. Fab 입력은 layer별·크기별 평균 이물 개수와 검사면적이므로 평균 밀도까지 계산할 수 있다.
7. 외부 기존 `sim` 비교 결과와 내부 `legacy_failure`를 분리한다.
8. 최종 결과는 실제 기존 sim 대조 후 schema 2.0과 version 추적 정보를 포함해 다시 생성한다.

PDF는 실제 기존 sim 대조와 최종 결과 재실행이 끝난 뒤 한 번만 생성한다.
